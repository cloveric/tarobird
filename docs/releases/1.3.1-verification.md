## Build provenance correction

The initial mobile 1.3.1 build used installed npm package versions that did not
match the frozen lockfiles. Native UI validation passed, but that did not verify
the dependency installation. The corrected packages use a fresh `npm ci` tree;
all 787 installed root/client package versions match their locks. Dependency
resolutions and integrated-product pins were not upgraded.

At the owner's request, the corrected release remains 1.3.1. Android replaces
the original asset and increases versionCode from `2026110407` to `2026110408`.
iOS uses build **2**. Desktop installers are genuine rebuilt 1.3.1 packages,
including their embedded versions, rather than renamed 1.3.0 downloads.
Original 1.3.0 desktop releases remained available at publication; see the
November 12 reorganization below. The prepared 1.3.2 plan was
cancelled before publication.

## Fresh checks and inherited evidence

- Pre-freeze shipped-dependency security review, source builds, Source checks
  and Secret scanning passed for the frozen source. No dependency upgrade was
  added during release preparation.
- The affected checks passed: 16 viewport tests, 7 iOS plan tests and 10 browser
  keyboard/layout/queue cases. The queue geometry test now measures both
  controls in the same animation frame; its assertions are unchanged.
- Android: 50 JVM unit tests and release Lint passed (14 warnings, no errors).
  The production-signed corrected APK was installed over the initial 1.3.1 in
  an Android emulator. Existing draft retention, native Host connection,
  queued submission and keyboard close/reopen were exercised.
- iOS: the Release simulator App retained existing pairing/draft data and
  passed native Host connection, queued submission and keyboard close/reopen
  in XCTest. Simulator and signed device frontend assets match. Distribution
  signing, App/share-extension metadata, profiles and APNs entitlement passed.
- macOS: Developer ID signing, strict signature checks and Apple notarization
  passed. An isolated copy of the previous App was upgraded from the signed
  DMG; identity/signature continuity and retained synthetic state were checked.
- Windows: embedded version/source/UI, icons, runtime imports, official
  Electron runtime checksum and updater signature passed. Native installation,
  upgrade, custom-path and uninstall were **not rerun** for this scoped rebuild.
  There is no new Windows native-runtime acceptance claim.
- The standalone CLI passed clean installation and an existing-Host upgrade;
  the paired identity, network, workspace and conversation/attachment state
  were preserved. Packaged App hosts match the standalone source/version.
- Every newly uploaded signed package underwent a fresh unpacked privacy scan,
  including archive metadata, binary paths and ASAR content. Public upstream
  examples and JavaScript scanner false positives were reviewed against the
  exact candidate bytes and integrity-verified upstream files.
- All published GitHub assets were downloaded anonymously and matched their
  exact local digests/checksums. The manifest-selected installer API URLs also
  worked without GitHub login. The production updater policy/signature probe
  selected 1.3.1 from 1.3.0, verified the signed version and rejected a same-version
  update. This is download/signature evidence, not an owner-device GUI upgrade.

Unchanged Host, engine and integrated-skill behavior retains the explicitly
scoped 1.3.0 evidence; it is not presented as a new run. Mobile acceptance used
a real test Hub/native transport with a deterministic Codex fixture, not a new

acceptance, fresh push-delivery check or new Android in-app updater run is
claimed. The earlier Android 1.3.0 runtime gap remains in

The owner's installed Mac was not replaced or restarted. Public update-feed
and signature verification does not mean the owner's GUI upgrade was performed.

## November 12: unified download page

[TaroBird 1.3.1](https://github.com/cloveric/tarobird/releases/tag/v1.3.1)
collects macOS, Windows, Android and standalone CLI downloads, plus the existing
iOS TestFlight link. It uses the same immutable package bytes, source revision
and signatures listed above; later source fixes are not included. Desktop
manifests on the unified page point to that page's new asset IDs. This is a
publication reorganization, not a rebuild or installed-App update.

The three original 1.3.1 platform Releases and their asset IDs remain available
for installed updaters. The owner authorized deleting the twelve Release pages
for 1.1.1, 1.2.0, 1.2.1 and 1.3.0, including the Windows preview. Their Git tags
and source history are preserved; links to the removed installer assets no
longer work. The homepage download links point to the unified Latest page.

The next packaged updater transition is planned separately. Existing 1.3.1
clients do not recognize a `vX.Y.Z` release tag; retaining their platform
channels is required until a verified bridge build is available.

Reorganization checks: fresh scans covered the exact package bytes and
unpacked contents, with public upstream fixtures and scanner false positives
reviewed against their exact source evidence. All ten unified Release assets
were downloaded without authentication and matched their expected SHA-256
values. The unified desktop manifests reference their own installer asset IDs
and retain the original signatures. Original compatibility asset IDs, sizes and
digests were compared before and after the page edits and remain unchanged.
Production Mac, Windows and Android selection policies still discover 1.3.1
from the retained channels. These are publication, download and policy checks,
not a new installed-App or physical-device acceptance run.
