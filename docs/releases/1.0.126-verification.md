## Changes and source verification

Restores Chancellor ticket authorization/model-selection context, preserves confirmation and owner acceptance, adds generic quality/outcome guidance, and distinguishes unavailable preferences from explicit owner restrictions. The Host post-failure notice now follows those same boundaries and preserves progress. No production Bot persona or model configuration was rewritten. See [selection and Opus review](../client/dispatcher-quality-selection-2026-11-02.md) and [upstream inventory](../client/release-1.0.126-dependency-inventory.md).

Five isolated selection samples included Opus for a creative script, Luna for mechanical formatting, fallback when Claude was unavailable, and no substitution in two explicit-only cases. These are model-mediated samples, not proof of optimal routing, enforced natural-language restrictions, actual skill use or rendered-video quality.

Source/build/test evidence is captured in the adjacent JSON under `evidence.checks`. Initial failed checks are retained along with unchanged passing retakes; separate successful stages do not rewrite the first local hook exit.

Canonical CLI clean and extracted installations and prior-host upgrade passed. Ten real Codex/Claude journeys passed through paired protocol clients, isolated Hub/Gateway and the real CLIs: text/sync, byte-identical file return, synthetic local-ASR speech, question/resume, and stream/stop/context resume. This is not physical App acceptance.

The final signed bundled Node loaded the separate DeepSeek addon and returned the required real model marker.
