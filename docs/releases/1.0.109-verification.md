# App 1.0.109 / Host and standalone CLI 0.1.456

Frozen source: [`624476fc31302b8259a5539c44fcc93512abab52`](https://github.com/cloveric/tarobot/commit/624476fc31302b8259a5539c44fcc93512abab52). All packages use this revision, Android versionCode 2026102403 and iOS build 1. Wire protocol remains 1; Hub schema is 21, supporting 1–21. No external package registry is published.

## Changes and review

This release includes conversation multi-select on desktop and phone, recoverable batch deletion and folder moves, the visible Claude supplement/next-turn selector, coordinated main/side composer spacing, and the group/Agent Bus fixes from the independent human-behavior audits. Phone labels are “补充 / 排队”; choosing a mode does not send the draft. Existing queued-message editing, sorting and cancellation remain. Host/CLI capabilities use the same permission and transaction rules; older Hosts explain unsupported bulk operations rather than silently emulating them with partial writes.

The final release gate found a pre-existing desktop Bus reveal/wheel race. A queued second React reveal could reposition the board after the user had scrolled. The correction now commits inside the original cancellable animation frame, consumes that reveal intent and removes its listeners. Actual Opus 5.5 xhigh independently reproduced the original interleaving (offset 902), verified the candidate at offset 0 and reviewed focus, draft, missing/hidden targets, reduced-motion and reopening boundaries. The first candidate `b5470681` was never published; every platform was rebuilt after refreezing. This last correction is presentation-only and adds no CLI command or data/protocol change.

## Retained limits

Opus's stress probe still reproduces a viewport jump when a renderer stall spans the dock animation and the DOM wheel arrives only after the correction. This predates the release, affects viewport position rather than data/focus/drafts, and a subsequent scroll works. The original timing-sensitive test can still be stressed into that mode. Reducing layout work or handling delayed input timestamps is follow-up work; this release does not claim to eliminate all scroll stalls.

Native Windows installation/launch and Authenticode are unavailable/unverified. Physical iPhone/Android installation, production APNs/FCM, real tailnet/cellular routes and mobile IME behavior were not independently re-accepted for these release binaries. macOS is Apple Silicon. Simulator/browser checks are not physical-device acceptance. The local Mac has separate installed-runtime, real-model and visible-window acceptance receipts; this does not extend to the unverified platforms above.
