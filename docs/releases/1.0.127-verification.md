## Changes and checks

Adds worker assistance that yields and resumes the same parent session under bounded ticket permissions/allowance; adds capability metadata and routing help. Fixes a help/pause race that could misclassify a checkpoint as reviewable, exposes bounded helper-result and continuation-delivery readback, and states actual remaining allowance. Design is upgraded to 2.7.1 with refreshed source hashes and separate adapter. See [audit](../client/dispatcher-release-audit-2026-11-02.md), [preflight](../client/release-1.0.127-preflight-2026-11-02.md) and [upstream inventory](../client/release-1.0.127-dependency-inventory.md).

Source/native, browser, actual model, package and installed evidence remain separate. Initial failures are retained with any unchanged retakes; they are not relabeled as passing. Detailed current-run results are in the adjacent JSON.

The DeepSeek coordinator comparison proved cross-provider execution but missed a defect in its generated protocol answer. That proposal was not imported into production. This release does not claim optimal routing or error-free model review.

## Installed acceptance

Installed runtime, real model and native GUI verified; remote-screen first-connect functional finding remains unresolved.

The runtime checks preserve Host identity and baseline IDs, verify published/installed bytes and authenticated reconnection, and read back the terminal CLI. The installer records schema 23 → 24 migration. Passed installed runtime/model checks are not repeated for GUI acceptance.

CUA verified /Applications/TaroBot.app native window, Settings version 1.0.127 and the GUI device connected to macmini via the local direct route (6 ms observed). Screen service and all three native permissions were ready; this GUI device already had control authorization. First viewing attempt remained paused without an image; explicit disconnect/reconnect produced the real desktop and fresh viewing state for over 150 seconds, and final close removed the session. The initial pause is unresolved; no remote input, permission change or external-network acceptance is claimed.

Full functional acceptance is **not complete**. The first real screen-view session stayed paused without frames, then an explicit reconnect worked for over 150 seconds. Closing removed the session. The original visibility-event source was not logged (native stderr was `/dev/null`); no root-cause fix is claimed. Permission state was read from the GUI itself; CLI identity permissions were not substituted. No real remote input was posted.

Newer main commits for sidebar count alignment, extension installation help/settings/scope status, and remote-screen toolbar icons/spacing are **not included** in this frozen 1.0.127 package.
