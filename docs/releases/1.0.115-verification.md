# TaroBot 1.0.115 / Host 0.1.460

Status: Mac, Windows and Android published; iOS TestFlight available. Local Mac App, Host and terminal CLI updated; post-installation acceptance passed.

This release includes the October 26 changes and the independent daily audit through `e42515cd`.
App 1.0.115 and standalone Host/CLI 0.1.460 share frozen source `4fcfc997960f63b79a7a9111b669f1b5415eb86d`. Android versionCode 2026102701; iOS build 1; protocol 1; Hub schema 22 unchanged.

## Changes

- Strict time-limited invitations for first pairing; previously paired devices retain reconnect access. New devices need an updated App and a current invitation.
- Streaming and process-reader efficiency, projection-failure recovery and durable once-only input dispatch.
- Desktop side conversation window expansion, with the existing split when maximized or space is insufficient.
- Mobile image chrome/draft previews, pending-queue styling, list options, conversation actions, ADHD search/topics and theme/chart accents.
- Approved warm-gray fox launcher artwork, first-Bot avatar and avatar-library refinements.
- Audit fixes for independent-pane hover and white-violet disabled-label contrast.

See [daily audit](../client/day-audit-2026-10-27.md) for evidence and the distinction between confirmed defects and unverified risks.

## Release acceptance maintenance

The standalone live verifier now obtains short-lived invitations from an authenticated owner of its isolated test Host. Both simulated App devices still use the public pairing endpoint and require separate owner approval. Regression coverage confirms uninvited and invalid-invitation requests stay rejected; this changes acceptance scripts only, not the product authentication policy. The Rust TLS integration also passes the fixture-issued invitation and explicitly asserts that an uninvited request remains rejected.
