CLI **0.1.459**, Android versionCode **2026102602**, iOS build **1**,

without delegating build, publication or installation work to another Bot.

## Publication

- [macOS arm64](https://github.com/cloveric/tarobot/releases/tag/macos-v1.0.114): Developer ID signed, App and DMG notarized/stapled, Gatekeeper accepted. DMG and updater archive contain the same sealed App. Downloaded artifacts, updater signature and manifest were verified.

- [Android](https://github.com/cloveric/tarobot/releases/tag/android-v1.0.114): signed APK published and downloaded bytes/tag verified. The signing certificate is unchanged.
- iOS TestFlight **1.0.114 (1)**: Apple processing `VALID`, internal state `IN_BETA_TESTING`, internal group assignment and Chinese/English test notes read back. The tester membership state does not prove this version is installed on a physical phone. No App Store or external beta review was submitted.
- The same canonical `tarobot-0.1.459.tgz` is attached to the desktop/Android releases. No external npm publication occurred.

## Included changes

The release contains the reviewed UI changes after 1.0.113: coordinated chart
colors, approved warm-gray fox launcher artwork, first-host Bot avatar selection,
Monochrome light defaults and optional accents, restored ADHD avatars and topic
folding, wider side conversations, image-viewer input handling, message-action
consistency and the macOS overlay title bar. Saved themes and existing Bot
avatars are retained. The proposed warm-gray own-message bubble option was
reverted and is not claimed as a feature of this release.

CLI impact: first-Bot avatar selection and widget guidance are Host changes.
The canonical CLI and App-bundled Host therefore advance together from 0.1.458
to 0.1.459. Schema remains 22; no new database migration or manual compaction
is part of this release. Existing backup preferences are preserved.

## Native window and device boundaries

The [window-chrome audit](../client/macos-window-chrome-2026-10-26.md)
records the earlier browser and isolated native checks. Buttons, text input,
selection, double-click maximize/restore and fullscreen reservation were checked.
Actual mouse/trackpad window displacement remains **unverified**: in this release,
CUA moved neither the overlay fixture nor a separate standard-system-titlebar
control; the owner was unavailable for a physical drag check. That control result
is an automation limitation, not evidence that product dragging passed or failed.

Browser widths, Simulator builds and package readback do not establish physical
iPhone/Android acceptance. Native Windows startup, this release's real-phone
installation/gestures, APNs and FCM end-to-end delivery remain unverified.

## Local Mac activation

Local Mac update acceptance completed on October 26. The installed App is
**1.0.114**; the running Host and independent terminal CLI are **0.1.459**.
The installed executable and bundled Node match the published signed bytes.
The CLI wrapper/runtime are unchanged and the previous version remains available.

The Host completed its native drain on the first attempt, restarted normally,
and reconnected with the same identity. All previously recorded Bot,
conversation, message, device and attachment IDs remain present. All seven
managed Bots and the configured relay are online. Schema remains 22; the stored
backup policy and database storage mode are unchanged. No forced stop, database
rollback or production compaction occurred.

The installed signed Node loaded the external DeepSeek addon and produced the
real response `DEEPSEEK_INSTALLED_OK` in isolated test state, without using a
production conversation. The normally opened native window was raised and
visually inspected: General Settings opened, scrolled to the displayed
**TaroBot 1.0.114**, and closed back to the chat input. This verifies the installed
window and those basic interactions; physical mouse dragging remains unverified
as documented above.

The helper checks active work rather than merely counting resident processes.
A full page of 128 ended Claude tasks is accepted only with audited live-first
ordering, terminal/non-stoppable entries and the installed native-drain predicate;
unknown or active tasks still block. Policy/probe regressions passed. A historical
task page is not treated as proof of idle by itself.
