## Joint review and corrections

Codex and actual Claude Opus 5.5 (`claude-opus-5-5[1m]`, xhigh) reviewed the
unreleased changes and rendered phone/desktop interfaces. The
[audit disposition](../client/release-audit-1.0.107-2026-10-24.md) records
reproduced defects, fixes and retained limitations. The final production fix
binds deferred Claude launches to their exact background review; Opus separately
verified four probes and 212 related tests before the source freeze.

The integrated corrections cover stale Claude input receipts after worker
replacement, definite rejection versus uncertain delivery, draft retention
during preflight, native background work and final scoped-card delivery during
graceful updates, paused discussion context and resources, independent-answer
settlement, and forwarded group messages. Group addressing remains separate from
direct-chat native input. No alternate CLI backend or permission model is added.

UI corrections include user-message tables collapsing into a narrow scroller,
heading emphasis becoming doubly bold, task-list dialogs reopening after chat
navigation, failed background agents retaining an unknown state, and expanded
completed task groups losing their disclosure state after virtualization.
Phone and desktop geometry retain their separately accepted platform boundaries.

This release also includes the newly integrated
[Claude native input](../client/claude-native-input-2026-10-24.md),
[grouped background cards and task dock](../client/background-task-groups-2026-10-24.md),
[discussion recovery](../client/group-held-input-audit-2026-10-24.md),
and [open temporary side conversations](../client/side-conversations-2026-10-22.md).
Shared Host changes ship in the canonical CLI; native-input help uses actual
message/request IDs. Visual card grouping, typography and disclosure state are
App presentation and do not require a separate headless UI. Existing capability
gates, old-client fallbacks, message ownership and scoped read-only controls remain.

6,509 passing tests, five skips**, **77 Rust tests**, the 441-module standalone
graph, Host/client builds, fresh client installation, type checks, translations,
identity checks and secret/history scans. GitHub-hosted CI did not start because
of the account billing/spending limit; it is not a passing cloud check.

The final Chromium slice passed **35** tests. The WebKit slice passed **31**,
skipped one, and initially failed an offscreen-dock fixture because the card was
still visible with insufficient scroll extent. The corrected fixture passed
four consecutive runs on each engine, including appearance, card navigation and
disappearance. Production frontend code was unchanged between these runs.
Screenshots cover 390px and desktop widths, light/dark themes, running and
completed task groups, and the offscreen task dock. Browser evidence is not
physical-phone scrolling or animation performance acceptance.

Actual local Claude Code **2.1.309** passed the final native-input journey:
ordinary input does not interrupt a running tool; unconsumed input uses native
withdrawal; immediate input uses the native interrupt control with `send_now`
and its message UUID. Ordered per-message model receipts remain distinct from
CLI acceptance, and the background agent survives this exercised path. This does
not claim that every terminal keyboard interaction has a stream-json equivalent.

The canonical CLI passed clean installation, extraction and fresh installation,
dependency inspection without the retired SDK, and an isolated **0.1.453 →
0.1.454** Host upgrade preserving identity, controller, network and workspace.
Its ten real Codex/Claude checks passed: paired-client text/synchronization,
byte-verified file return, real local ASR, native question/answer, and streaming
stop/resume with context, five checks per engine. The small isolated ASR fixture
used internal temporary storage for the known external-volume service limit;
production ASR settings were unchanged and the fixture Host was closed.

The final signed Mac Node loaded a foreign native addon and the installed

bundled Node returned `DEEPSEEK_RECOVERED_OK`. This is package-runtime evidence;
the separate post-install check returned `DEEPSEEK_INSTALLED_OK` through the

## Local installation status and remaining acceptance

The terminal launcher now resolves to the verified **0.1.454** package and
reports that version. Its launcher and Node runtime are unchanged; the old
0.1.430 package remains available. The installed CLI tree matches the canonical
archive's verified tree, and its runtime loads the external DeepSeek addon.
This step did not change the desktop Host service or selected state directory.

The detached helper waited for work to settle before the existing graceful
Host handoff. Its final two observations, 12.6 seconds apart, each recorded no
busy work, no uncertain work and no native Claude processes. The old Host
predated the native-background drain fix, so foreground idle alone was not
treated as evidence that private native work had ended. No force-stop shortcut
was used. An offline database/configuration snapshot preceded the atomic App
replacement; the external previous-App backup remains available.

The actual Host PID changed from **43773 to 44098** during this handoff and
reports **0.1.454**, running and not draining. Authenticated reconnection and
schema 21 passed. Independent post-install checks matched the installed binary
to the published executable and identity bytes to the offline snapshot. All
prior IDs remain: nine Bots, 102 conversations, 4,462 messages, ten devices and
1,169 attachments. Later messages are additional rows, not replacements.

The installed signed Node loaded the external DeepSeek dependency and a real
isolated request returned `DEEPSEEK_INSTALLED_OK`. No production conversation
was used for that model probe. Finder's Applications folder opened the actual
installed TaroBot in the foreground. The existing chat history and composer
rendered; Settings displayed **1.0.107**, and the connection page showed the
existing Host connected directly. Settings were closed and the original
conversation restored without changing preferences or network routes. These
observations verify the inspected native window, not every UI path.

The final acceptance receipt records the independently checked versions, model
response, visible GUI and retained IDs. The helper's original receipt is retained
unchanged; its waiting-phase counters are superseded by the two actual final
idle observations. After model/GUI acceptance and checking that no files were
open in the retired local App, that redundant local copy was removed; the
byte-verified external backup remains.

Retained limits include the pre-existing 40–100ms initial reload scroll-restoration
window and the bounded one-second deferred-launch grace. Physical iPhone/Android
scrolling, push, real tailnet/cellular routes and native Windows execution have
not been independently re-accepted in this build. These remain separate from
the passing source, browser, package and model checks above.
