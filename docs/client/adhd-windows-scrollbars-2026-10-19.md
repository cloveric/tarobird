# Windows ADHD 外层滚动条排查

## 当前结论

Windows 用户截图中，ADHD 对话本身的细滚动条之外，窗口右侧和底部又有
两条粗滚动条。用户暂不记得触发步骤，后续确认受影响的 Windows App 是
**1.0.93**。该版本缺少已知的 Bus 返回定位修复；但尚未获得该次 Windows
原生 WebView 的布局数据，不能仅凭版本认定这次截图的根因，也不能把
浏览器测试通过称为该电脑已修复。

检查现有代码和保留的 1.0.94 Windows 发布源码，均已包含侧栏拖动把手的
相对定位，以及 Bus 协作方式 fieldset 的相对定位。这两处曾分别修复已确认的
外层溢出，但仅凭相似截图不能断定这次也是同一个原因。

## 1.0.93 与 1.0.94 安装包核对

收到版本号后，重新读取两版 Windows 安装包解出的主 EXE，核对其 SHA-256，
并从 EXE 内实际嵌入的位置解压界面 CSS；内容哈希与原发布校验记录一致：

- 1.0.93（源码 `35130bbb2cf91300f3e7f5d8f99bf81a5c88da64`）的
  `.agent-bus-mode-picker` 没有 `position:relative`，隐藏 legend 缺少定位容器。
- 1.0.94（源码 `e2f1cb6b0f821f7aa7cfaf26a163a84882820f4d`）已包含该属性，
  对应此前在 Mac 原生 WebView 复现并修正的 Bus 收起溢出问题。

对照证据保存在测试目录的 `version-comparison.json`。这确认了安装包之间的
修复差异，因此应先更新到包含修复的版本；仍未完成受影响 Windows 电脑的
更新后验收，本次不再叠加未经复现的样式补丁。

本次没有修改产品样式，没有用全局隐藏滚动条或锁定页面滚动来遮盖现象。
仅新增浏览器回归和排查记录，不增加主机能力，CLI 无需变更。

## 新增验证

`client/e2e/agent-bus-workspace.spec.ts` 补充三种设备像素比例（1、1.25、1.5）
的验证，每种均强制 17px 传统滚动条，并检查 1600、1360、1359、1100、820px
窗口宽度：

- 五个对话面板，长回复及 Markdown 表格。
- 单面板放大、恢复总览、向上和向下滚动阅读。
- 反复打开 Bus 配置并收起，跨过抽屉／覆盖面板布局断点。
- 每帧记录文档横纵溢出和整页滚动位置，包含过渡动画期间。
- 输入草稿保留、发送按钮可达，根节点仍保持正常的 `overflow: visible`。

当前客户端构建的新增三项 Chromium 测试通过；已有的 Bus 返回和 ADHD
工作台／最后一行输入框回归两项也通过。另外使用保留的 1.0.94 Windows
发布界面资源重跑 1.25 像素比例场景，一项通过；这仍是浏览器验证。
初版新增用例把虚拟列表的顶部位置
严格限定为 0px，遇到重新测量后的 4px 锚点修正；加入既有布局稳定等待并按
顶部阅读范围判断后通过。这不是外层滚动条复现，未因此修改产品阅读逻辑。

上述检查在 Mac 的 Chromium 中运行。设备像素比例参数不是 Windows 系统
缩放或 WebView2 真机验收，不能证明用户电脑已恢复。所有数据为隔离 Hub 和
合成对话，没有修改真实聊天、配对或主机配置。

测试输出位于外置盘 `taro-tmp/tarobot-windows-scrollbars-20261019`。
后续需要确认包含修复的版本在 Windows 原生环境的表现；若仍复现，再结合
原生触发场景定位新增原因。
