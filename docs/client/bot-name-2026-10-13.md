# Bot name editing — 2026-10-13

## Behavior

- Desktop: right-click the Bot in the sidebar → **Bot 设置** → **Bot 名称**.
  Conversation details → **Bot 设置** reaches the same editor.
- Phone: Bot tab → the Bot's settings button → **Bot 名称**.
- A focused dialog contains the name field, one scope sentence, Cancel and Save.
  New names are trimmed, nonempty and limited to 100 characters, matching Bot
  creation. Existing CLI-registered names remain readable even if they predate
  these limits.
- The Hub owner can rename a Bot even when its process is offline or it has no
  conversations. The Hub connection itself must be online.
- Changes update the Bot's display name on connected devices and survive
  restart. Bot ID, avatars, conversation titles, memberships, session bindings,
  history, persona and pending work are unchanged.

## Ownership and save semantics

`GET/PUT /api/bots/:id/name` uses authenticated Hub requests. The store checks
owner authority inside the write transaction, including the request's current
session guard. PUT compares `expectedName` against the stored name; stale writes
return 409, while retrying an already-saved target name is idempotent. The shared
creation specification remains unchanged so creation retries retain their
original identity.

`bot.status` distributes the authoritative name to existing clients. The UI
waits for the HTTP save receipt before closing, but never writes an older HTTP
response over a newer socket update. If another device changes the name during
editing, the input draft stays intact until the user chooses **读取最新名称**.
The endpoint and UI use the selected Bot's own Hub even when different hosts
contain the same Bot ID.

## Verification and delivery boundary

- Store and real-transport tests: all 34 tests in `tests/hub-bot-name.test.ts` and
  `tests/hub-server.test.ts` pass, covering persistence, offline Bots, unaffected data,
  concurrent writes, legacy names, authorization, validation and socket updates.
- Browser tests: `bot-name.spec.ts` covers desktop/390px phone editing, two-device
  synchronization, reload, avatar and conversation preservation, a Bot without
  chats, conflicts, delayed receipts, cross-host isolation and disconnected Hub
  controls. All three pass in both Chromium and WebKit. The four Chromium
  `persona-mobile-polish` and `conversation-details` regressions also pass.
- Root and client production builds pass; English translation keys are checked.
- Rendered desktop settings/editor and phone editor screenshots were inspected.

This is source and browser verification. The installed macOS app and Android
package were not replaced or tested on device in this change. Both the client
and the runtime Hub need this update; an older Hub receives a readable update
message rather than a false save confirmation.
