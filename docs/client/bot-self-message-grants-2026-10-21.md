# Bot 自身消息授权补充

## 问题与范围

此前 owner 的 CLI `messages allow` 已允许 `A → A`，但 App 接收方列表排除了自身，
界面写入 schema 拒绝相同 source/target，授权快照也过滤了已有自身记录。因此“在设置里
允许该 Bot 向自己的另一段对话发送消息”实际无法完成，已有命令行授权也看不到。

本次补齐现有直接消息授权的图形入口。授权仍是 owner 对稳定 Bot ID 的有向授权，
不代表 Bot 获得修改权限的能力；不改 Agent Bus、自动授权策略、模型适配器或任务调度。
未修改任何用户实际主机上的授权，也未发布或安装新版本。

## 界面与兼容

- 桌面/浏览器：设置 → Bot 消息授权；手机：我的 → 设置 → Bot 消息授权。
- 选择发起方，接收方列表第一项是该 Bot，并标注“自身其他对话”。即使主机只有一个
  Bot，仍可配置；离线与未授权分别显示。
- 勾选并保存开放 `A → A`，取消勾选并保存撤销；其他方向不受影响。
- 已通过 CLI 设置的自身授权自动显示。刷新、轮询、保存后的服务端回读沿用既有机制，
  不新建授权表，不自动新增授权。自身关系不重复显示为“其他 Bot”的反向授权。
- 使用稳定 ID；改名、重启后保留，同名新 Bot 不继承已删除 Bot 的授权。
- 快照增加可选 `selfTargetSupported` 字段，新主机返回 `true`，并将该能力纳入 revision。
  旧主机不返回此字段时，自身选项禁用并提示更新；其他 Bot 的授权仍可用。
  保存自身修改后的回读也必须确认该能力，不能将旧主机遗漏记录误判为撤销成功。
- 重复方向、一次超过 256 项、旧 revision、过期/错误设备签名仍拒绝；批量写入与审计
  保持同一事务。保存失败、结果未知不显示成功，也不自动重发。

## 消息与安全边界

只新增 UI 可选项，不改变已有 Bot 级直接消息通道：未指定对话时仍创建/复用专用协作
对话，显式指定对话时沿用现有成员和可见性校验。不是新增“按某个对话授权”的权限类型。
仍需要活动来源消息上下文，消息进入持久队列；原任务结果通过对应消息 ID 查询。
来源伪造、控制命令、超出转发层数和频率的请求继续拒绝。

撤销沿用[现有边界](bot-message-permissions-2026-10-19.md)：后续发送和结果查询受阻，
已经提交的任务不会被此设置停止。先取回结果再撤销；任务停止使用既有独立入口。
本次不增加并行执行能力，也不绕过同一 Bot 的执行容量限制。

## CLI

CLI 与 App 复用同一记录及权限检查，不新增命令。已有自身授权现在也会出现在
`messages grants` 的主机快照中。以下写操作由已认证的 owner controller 执行：

```sh
tarobot messages allow --from "HOST_ID/BOT_ID" --bot BOT_ID --json
tarobot messages grants --json
tarobot messages revoke --from "HOST_ID/BOT_ID" --bot BOT_ID --json
```
