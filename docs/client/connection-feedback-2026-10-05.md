# 原生安全连接反馈与 r26 开发包 · 2026-10-05

本轮继续原生 TLS 证书绑定与交付工作，不增加应用层端到端加密。旧 r25 不包含原生
固定证书网络栈；r26 将桌面实现封装为 Apple Silicon / Intel 通用开发包。
安装包不包含 Hub，必须配合支持 `/api/tls-identity` 的主机服务。部署仍按用户要求延期。

## 用户可见变化

- 配对失败分别说明主机暂时无法验证、身份不匹配、公钥无效；不再全部显示成
  泛化的连接失败。证明接口非 200 不必然是旧版，因此提示检查运行状态、版本和地址，
  不断言必须升级，也不自动修改信任。
- 已配对设备使用对应的恢复指引：先核对地址；只有确认主机重装或更换身份，才重新配对。
  已保存身份缺失或损坏也直接说明重新配对，而不是要求在没有公钥输入框的设置页粘贴。
- 线路列表和编辑页保留每条线路的验证原因，切换语言时标签同步更新。
  主线路失败仍允许通过验证的备用线路接替；认证失败没有浏览器或明文回退。
- 手工公钥允许粘贴时附带空白，规范化后用于请求与比较；输入长度留有余量，避免截断
  60 字符公钥。格式、SPKI 头和规范 base64 在联网前检查；这只是格式检查，不替代
  原生证书、签名和可信来源验证。配对响应身份发生变化时，拒绝配对并清理新建密钥。

## 实际 Opus 复核

通过 `claude --model claude-opus-5-5 --effort xhigh` 完成只读复核，返回的模型用量
确认是该模型，推理档位按 CLI 参数记录。采纳了中性的不可用文案、粘贴截断修复、
配对／已配对提示区别及身份标签统一。其反向代理终止 TLS 的场景不是本产品允许的
中转部署，但非 200 响应也可能暂时发生，因此仍采用中性文案。其错误码带前缀的担忧
未在已检查的原生生产路径复现；分别测试原生字符串拒绝和 Error 对象拒绝。

这是修改前的静态意见；修改后由父代理测试验收，没有声称后续又获得 Opus 签字。
报告与调用收据（本地材料：`evidence/connection-feedback-2026-10-05/opus-review.json`）。
