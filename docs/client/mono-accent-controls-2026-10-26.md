# 黑白主题的实心控件跟随点缀色

用户要求只有原本纯黑的按钮和开启的开关跟随点缀色。此改动限定在黑白主题
的浅色模式，以及跟随系统时的浅色外观。默认“不使用”仍保持黑白；深色模式
的浅色按钮、其他主题、关闭的开关和禁用按钮保持原样。

`porcelain-details.css` 给实心操作控件局部设置 `--primary-bg` 与
`--primary-hover`，不修改根节点的主色、正文或气泡变量。覆盖主／侧边发送、
主操作按钮、已开启的设置开关、空状态操作、录音状态按钮和工作表选中标签。
灰色／描边按钮、附件加号、输入框、徽标和消息气泡不会因为此设置被染色。
原有回复标记与运行提示仍使用已有点缀逻辑。

六种柔和点缀色不直接用作白字背景，实心填充采用同色系较深一档，保持白色
文字和箭头的对比度；悬停再略加深。开关的白色滑块和既有键盘焦点保留。
设置说明同步解释这一范围。无新偏好、迁移、Host API、协议或 CLI 行为。

这是 App 显示调整，本次不发版、不安装、不重启生产主机。

验证：客户端翻译／类型检查／构建及 Host 构建通过。Chromium、WebKit 的
4 项点缀色回归各通过（共 8 项），覆盖未知值回退、保存／重载、六种颜色、
白字对比度至少 4.5:1、开关开／关、发送按钮禁用、灰色控件保持、显式和
系统浅深色、390px 手机与桌面、原有运行提示和强制色模式。扩展既有测试时
纠正了两处基线取值：输入框聚焦与失焦不能直接比较边框，禁用发送按钮应
与禁用基线比较。实际产品样式没有为这些测试误差改动。

已查看 WebKit 的桌面／手机发送与开关截图；浏览器验证不代替已安装 App
或物理手机验收。

## 字号滑块补齐

用户补图确认后，已核对“保存修改”通过 `.primary` 覆盖，两个设置开关也
已覆盖；字号圆点此前漏掉。字号组件自绘滑块直接读取 `--accent`，现在以
独立的 `--font-size-thumb` 接入相同点缀填充，轨道和外圈仍使用原来的灰色
边框变量，不改尺寸、触摸方向判断或键盘操作。原生 range 的实心部分也使用
局部主操作色；深色、无点缀和禁用状态继续保留原样。

补齐验证：客户端与 Host 构建通过；Chromium 4 项、WebKit 3 项既有用例
通过，覆盖点缀选择、队列保存（普通／ADHD）及 Chromium 的滑块触摸与
主题切换。WebKit 的 CDP 触摸用例按原设计跳过 1 项，不能当作通过。
已查看 WebKit 的手机字号滑块和“保存修改”截图，圆点／按钮有色，滑块
轨道仍为灰色；无原生安装或真机验收。

## 鼠尾草绿浅色化（2026-10-27）

按用户反馈，黑白主题的鼠尾草绿点缀采用浅灰绿 `#dce4d6`，悬停为
`#cbd7c4`，文字／图标用深灰绿 `#43513d`。色样、启用的实心控件和手机
消息页的汇总数字使用这组浅底深字；浅色、深色、跟随系统的外观一致。
保留 `sage` 偏好 ID，无需重新选择。原来为白字而压深按钮的规则不再应用
于此选项；不把浅底色直接用到需要对比度的正文标记、运行提示或图表线上。

此节覆盖前文关于鼠尾草绿“白字、仅浅色模式”的旧规则。配对／设置页按
此前要求继续使用固定浅暖灰；普通聊天背景、禁用与关闭状态、红色未读头像、
其他点缀色和独立的松绿主题不变。纯 App 配色调整，CLI 不适用；无 Host
能力、同步、配置格式或默认值变更。不包含发版、安装或生产主机重启。

验证：客户端翻译、类型检查和生产构建通过；既有 Chromium／WebKit 点缀色、
状态文字、手机汇总、桌面红色未读及两种宽度录音回归共 14 项通过。
独立浏览器通过设置选择鼠尾草绿、刷新确认保留，并核对浅／深／系统模式的
实际填充和文字颜色；390px 与 1360px 截图无横向溢出。未新增测试文件；
没有原生 App 安装或真机验收。
