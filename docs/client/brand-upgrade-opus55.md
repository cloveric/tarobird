## 2. 设计方向

**“温暖的小狮子工作室”**。

| 维度 | 决定 |
| --- | --- |
| 底色 | 侧栏、设置导轨、配对页用奶油 `--canvas`；阅读区用近白暖纸 `--bg`；卡片、输入框、选中行用 `--raised` 白，形成“纸张叠放”的层次，不用玻璃模糊。 |
| 品牌色 | **金色识别，陶土色行动**。暖金只做识别与点缀（狮子、Bot 默认头像底、空状态图标底、运行中胶囊、工作中光环起点）；所有可操作、焦点、选中反馈统一用更深、更偏红的**陶土色（clay）**。绿 / 琥珀 / 红仍是成功 / 警告 / 错误语义色；群组保留薰衣草紫作身份色。详见 §2.1。 |
| 伙伴 | 小狮子 = TaroCub 自身（侧栏品牌标、欢迎、配对、加载、favicon）。其余 8 只动物只作为**没有自定义头像的 Bot** 的稳定默认头像（按 Bot id 哈希，不随机）。自定义头像始终优先。素材原画颜色不改。 |
| 状态 | 第二轮新增：Bot 头像本身表达**真实的回复状态**（见 §3.2）；“在线”不等于“在工作”。 |
| 排版 | 系统字体；标题 650–750 字重、轻微负字距；正文/元信息 11–14px 分层；手机主要触控目标 ≥44px。 |
| 圆角 | 6 / 8 / 12 / 16 / 22 五级；行与按钮 10px，卡片 12–14px，对话框 18–20px，药丸 999px。 |
| 动效 | 只服务于“出现 / 反馈 / 真实状态”，120–360ms；`prefers-reduced-motion` 下全部关闭；不做常驻漂浮、粒子、JS 动画循环。 |
| 不变量 | 虚拟列表 `.message` 的 inline `translateY` 不被任何 animation/transform 覆盖；用户消息是浅陶土色气泡，Bot 消息留白无气泡；不改头像鉴权/加载逻辑、连接/存储/协议代码。 |

### 2.1 配色（第三轮，最终方案）

为什么是陶土色：奶油纸底和金色小狮子都在暖色区，冷蓝按钮会“浮”在纸面上。陶土色和金色同属暖色，但**色相更红（约 16° 对金色约 33°）、明度更低、饱和度更高**，所以按钮、选中项与狮子 / 运行状态仍能分开，不会变成整屏橘黄。没有选整套深棕：那样稳重但太暗，失去小狮子的亲和感。

全部定义在 `client/src/brand-theme.css` 顶部三组 token（浅色、显式深色、跟随系统深色）。styles.css 及各功能样式里的 `--blue` / `--selected` 是旧名，现在是 `--accent` / `--accent-soft` 的**兼容别名**，因此没有全项目重命名。深色两组必须重申别名，因为 styles.css 的 `:root[data-theme=dark]` 选择器优先级高于 `:root`。

| --- | --- | --- | --- |

| `--accent-soft` / `--selected` | `#fbeae2` | `#3d2820` | 柔和按钮底、选中底色 |
| `--accent-soft-hover` | `#f8dfd2` | `#4a3026` | 柔和按钮 hover |
| `--primary-bg` / `--primary-hover` | `#b9532c` / `#a3461f` | `#ec8f66` / `#f3a17b` | 实心主按钮、发送、未读数、欢迎主卡片、品牌气泡 |
| `--on-primary` | `#fff` | `#2a1710` | 实心主色上的文字与图标（深色主题为浅陶土 + 深墨字，而不是暗底白字） |
| `--focus` | `#a3461f` | `#ec8f66` | 2px 焦点轮廓 |

## 3. 第二轮复审

### 3.1 结论：还像不像“换了暖色的普通后台”？

看 `round1-*` 截图：配对页双栏构图清楚，侧栏的 Bot → 对话层级、空会话卡、设置导轨已经有自己的语言，不推翻。剩下的“后台感”主要来自三处：

1. **界面是静的**。Bot 正在回复时，除了消息里的金色运行胶囊，整个界面没有任何“它在干活”的感觉；头像只是身份证照片。
2. **状态点到处都是**。侧栏每个 Bot、每个对话、每个话题都挂一个绿点，信息重复，看起来像监控面板。
3. **手机 header 被次要信息挤占**，标题只剩约 4 个字（集成审查发现）。

### 3.2 从 Grok Bot 吸收什么、不吸收什么

| Grok 的做法 | 本次决定 |
| --- | --- |
| Bot 而不是对话是主对象，侧栏是 Bot 名册 | 我们的侧栏本来就是 Bot → 独立对话、群 → 独立话题。保持；把“可用”状态点只留在 Bot 行和群行（嵌套的对话、话题行不再重复），身份和状态集中在 Bot 上。 |
| 头像即状态（idle / thinking / working / waiting / blocked / done） | **只映射我们有明确数据的两态**：Bot 消息 `pending` = 已接到任务，头像外一圈柔和的金色呼吸环；`streaming` = 工作中，金→陶土的弧线绕头像旋转；回复结束时旋转原地停下、光环淡出，即“安定下来”。会话 header 头像跟随会话末尾，消息里正在回复的那条消息头像同步显示。离线时一律不显示（缓存里的状态不代表正在进行）。 |
| idle 时“平静而略带好奇”的待机动画 | **不做**。那是没有状态支撑的常驻装饰循环。 |
| waiting / blocked / done 独立表现 | **不做**。客户端没有可靠的显式字段，靠扫描卡片内容推断会伪造生命周期，也会造成逐 token 重算。“完成后有新内容”已由未读胶囊表达。 |
| 过程按需展开 | 工具过程、思考已是折叠小卡，保持。 |
| 黑色圆形角色、单色界面 | 不照搬。我们用自己的手绘动物和奶油 / 暖金 / 陶土。 |

另外一处与之配套：输入框里的“停止当前轮次”按钮一直存在（原行为），只在有回复正在 `pending/streaming` 时变成红色，让“正在跑、可以停”一眼可见。没有新增控件。

### 3.4 第三轮：配色统一

用户反馈“背景暖色，我们按钮是冷色，不太搭”，并明确浅蓝用户气泡也可以换。此前“所有动作统一蓝色”“保留浅蓝气泡”两条决定作废，由 §2.1 的陶土方案取代。具体处理：

- 在 `brand-theme.css` 定义 `--accent*`、`--on-primary-soft`、`--primary-shadow`、`--selection`、`--accent-line`；本文件内所有动作色引用改用 `--accent*`，删除 `--blue-soft*`。
- 旧名 `--blue`、`--selected` 映射到陶土 token，styles.css、preferences.css、question-form.css、file-center.css、bot-dashboard.css 中的链接、焦点、选中、复选框 `accent-color` 等随之变暖，无需改这些文件。
- 清理了 brand-theme.css 中写死的冷蓝 RGB：文本选区、主按钮 / 发送 / 品牌气泡 / 欢迎主卡片阴影，以及主卡片图标和气泡圆点的写死白色（改为 `--on-primary(-soft)`，深色主题才正确）。styles.css 里仍有若干写死的旧蓝（如 `#245bdb` hover、`#8ab0ff` 聚焦边框、`#3370ff` 头像色），均已被 brand-theme.css 同优先级规则覆盖；`.message-avatar` 遗留的蓝色文字色也已覆盖为中性。代码高亮（`.hljs-*`）属于内容配色，未改。
- 只改了 `BrandScenes.tsx` 中一个 class 名（`blue` → `accent`）；其余 TSX、翻译、`index.html` 未改。

## 5. 动效规则

| 场景 | 动效 | 时长 |
| --- | --- | --- |
| 按钮 hover / 状态色 | `background-color / border-color / color / box-shadow` 过渡 | 120ms |
| 紧凑按钮按下 | `scale(.97)`（欢迎卡 `.985`） | 120ms |
| 欢迎页入场 | 四块依次上浮淡入，错开 40ms | 220ms，一次 |
| 品牌气泡 | 狮子之后从尾巴一角弹出（欢迎页、配对页） | 280ms，延迟 240ms，一次 |
| 空会话卡 | 上浮淡入，**延迟 120ms**：缓存消息通常在此之前到达，有消息的会话不会闪出空状态 | 220ms，一次 |
| 对话框 / 面板 | 遮罩淡入；面板 `translateY(10px) scale(.985)` → 原位 | 160 / 220ms |
| 手机设置 | 底部上滑 sheet | 220ms |
| 手机侧栏 | 原有 `translateX` 抽屉，改用统一缓动；遮罩淡入 | 220 / 160ms |
| 命令菜单、回到最新 | 小幅弹出 | 160ms，挂载时一次 |
| Bot 已接任务（`pending`） | 头像外金色环透明度呼吸 | 1.6s 循环，仅在该状态 |
| Bot 回复中（`streaming`） | 头像外金→陶土弧线旋转（伪元素 `rotate`） | 1.1s/圈，仅在该状态；结束时原地暂停并 360ms 淡出 |
| 停止按钮 | 有回复进行中时图标变红 | 120ms 颜色过渡 |
| 录音中圆点 | 透明度呼吸（仅录音期间存在） | 1.2s 循环 |

第三轮只改颜色，没有新增或修改任何动画、过渡或 transform。

硬约束：

- `.message`（虚拟列表行）没有任何新规则；列表内部没有入场动画。光环是消息头像槽 `.message-avatar` 的 `::after`，`position:absolute`，不参与布局、不改变行高，不碰行的 transform。状态 class 在流式过程中保持不变，React 不会重写它，因此 token 到达不会重启动画。
- 状态只来自 `message.status` 的 `pending / streaming`（且 `authorType === "bot"`、已连接）；header 只看会话最后 8 条，每次渲染常数开销，不做全历史扫描，不新增 effect/定时器。8 条之外仍在流式的消息（例如用户在流式期间连发多条）header 不再显示，但该消息自己的头像仍显示。
- 不用 `transition: all`；不对 width/height 做动画；不设置 `scroll-behavior`。
- `prefers-reduced-motion: reduce` 下所有 animation/transition（含 `::before/::after/::backdrop`）关闭，按压缩放改为 1。光环仍以**静态**形式显示（pending 实心金环、streaming 静止的弧），状态信息不丢。
- 无 JS 动画、无新依赖、无常驻漂浮吉祥物或粒子。
