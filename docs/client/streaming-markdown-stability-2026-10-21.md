# 长回复的流式排版与绘制稳定性

本次继续处理 [客户端稳定性修订](stability-repair-2026-10-21.md) 中实测失败的超长回复渲染，不改变正文、消息顺序、模型输出或队列协议。

## 原因与修订

1. **解析完成的前缀被后续流式更新反复作废。** 原调度器只接受最新 revision；流式到达快于解析时，中间结果一直不能显示，定稿才一次性插入大量节点。`markdown-jobs.ts` 现在允许同一追加世代中已完成的前缀推进显示，仍只排队最新请求。替换内容、失败、重试和卸载保持原有生命周期检查；“替换后又变成旧文本的前缀”不能绕过世代检查。
2. **逐段隔离造成大量绘制分组。** `.markdown > p` 的隔离改为 `.markdown-chunk` 分组隔离。包裹层的主题、首尾间距、阅读宽度、CLI、引用、转发和附件说明选择器同步迁移。已显示且指纹未变的分组继续复用原 DOM。
3. **定稿时的表格和公式仍会集中插入较多节点。** `markdown-parser.ts` 按最多 100 个顶层节点和约 250 个树节点分组；一个语义块不会拆开。`MarkdownText.tsx` 每帧最多增加两个新分组，避免把新增内容集中在一次布局中。每次绘制来自同一次解析的结果；新结果、失败、重试或卸载均撤销旧帧，即使被取消的回调再次运行，也不能覆盖新文档。

不是正文虚拟化或内容截断：最终所有节点都显示，复制、引用和转发仍读取消息数据。首次打开超长消息时内容从上至下逐步出现；后台标签页暂停动画帧，回到前台继续。单个巨大表格、代码块或其他顶层节点保持完整，约 250 节点是分组预算，并非所有文档的硬性 DOM/内存上限。替换大量已显示内容也不保证恒定开销。

保留原有解析 Worker、1 MiB 输入边界、依赖按需加载、失败原文回退与“恢复排版”机制，不引入新的依赖。CLI 不适用：本次改变客户端排版和绘制，主机协议、数据库、工具输出及 CLI 正文均不变。

## Codex 自测结果

### 性能与完整性

原有 `performance.spec.ts` 门槛未放宽：帧间隔 P95 小于 35 ms、最长任务小于 80 ms。仍断言全部 5,000 段正文、10 个表格、10 个公式、草稿保留及已显示首段 DOM 不重建。

| 验证 | 结果 | 范围 |
| --- | --- | --- |
| 最终代码，5,000 段流式回复，三次串行 | 三次均通过；帧间隔 P95 均约 16.8 ms；均未记录到 ≥50 ms 的长任务；自动化输入往返均 10 ms | 本机 Chromium，真实隔离 Hub、模拟引擎流式输出；不是手机硬件指标 |
| 300 个 TypeScript 高亮代码块，每块 25 行 | 完整内容和高亮断言通过；最后一段约 5.23 秒出现；未记录到 ≥50 ms 长任务 | 手机视口、真实 Worker；一次容量表征，包含冷加载/解析/绘制 |
| 20,000 段正文、4 倍 CPU 降速 | 全部内容和顺序通过；最后一段约 3.89 秒出现；未记录到 ≥50 ms 长任务 | Chromium 降速模拟，一次容量表征，不能替代低端手机验收 |

性能测试期间关闭自动 DOM trace 快照，因为快照自身会遍历整篇文档；完整正文断言在测量后执行。保留原有可选 CPU/timeline 采样，不将采样运行与无采样结果当作严格 A/B。

失败证据仍保留：最初三次 P95 约 217–283 ms、最长任务 790–831 ms；未修改基线也复现。中间版本三次有一次最长任务 154 ms 失败，增量分析定位到定稿时新增表格/公式的样式计算；并未以一次通过就宣布修复。最终增加绘制预算后才取得上表三次串行通过。

## Opus 审阅发现及处理

实际使用 Opus 5.5 / xhigh，独立复核调度器、主题选择器迁移和浏览器 timeline。指出不能只移动表格测量来转移停顿，也不能用估计高度、正文裁剪或放宽门槛掩盖问题。本次保留表格测量、完整正文和原性能门槛。

增量复审确认追加世代/旧帧生命周期和分组正确性，没有发现阻塞缺陷；提出三项补充：检查首次渐进显示的阅读行为、大量代码块的隔离成本、降速环境下完整显示时间。已补绘制生命周期和容量测试，并回归相关界面。其建议的测试与 Codex 实测结果分开记录；Opus 本轮为只读代码/证据审阅，没有独立执行上述性能测试。

最终复审确认将旧分组快照展平后对比完整节点不削弱语义断言；未修改基准样本。提醒容量测试是在独立 Markdown 组件页面，不能代替真实 App 气泡/虚拟列表中大量代码块的测量；已明确列为边界。双方无未决分歧。

Opus 收尾意见以最后 68 项及节点等价测试完成为交付条件；随后 Codex 执行结果分别为 68 项通过、1 项通过。以上是 Codex 验证，没有冒称 Opus 另跑了一遍。
