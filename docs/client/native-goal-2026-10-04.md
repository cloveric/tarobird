# 原生目标任务：停止、最终正文与会话隔离

2026-10-04。范围是本地隔离 Hub、真实 Codex / DeepSeek CLI，以及桌面和手机布局的配对浏览器。不是实体手机、原生安装包或生产部署验收。

## 本轮发现与修复

- 原生 `goal clear` 只撤销后续自动轮次，不能据此宣称正在生成的轮次已经停止。初次 Codex 验收缺少中断终态；DeepSeek 在清除后约 14 秒仍以 `completed` 结束。现在 Codex 先清除目标，再中断准确的目标轮次；DeepSeek 在没有已接入普通请求时，清除目标并取消该会话的目标工作，新普通请求在取消回执到达前等待。
- 原生“目标完成”可能早于最后一段正文。两家引擎都保持目标输出通道直到所属轮次结束；完成后的正文不再被目标状态摘要替换。Codex 使用原生终态正文纠正流式遗漏，避免再次拼接造成重复；DeepSeek 同样发布最终结果事件。
- 最后一轮采用 60 秒无活动超时；持续生成会续期，超过一分钟的活跃输出不会被固定计时截断。缺失终态仍明确报错，不把不完整回答宣布为完成。
- Opus 复核后补齐 Codex 轮次隔离：被停止的轮次不能被后来的普通请求接管；未知轮次 ID 的通知暂存，在原生响应证明归属后回放；停止发生在 ID 返回之前也不会把普通回复当作目标输出。每个新目标轮次清除上轮最终文本。
- 成功卡片保留目标标题和实际答案，取消重复的完整目标摘要。非终态的目标退出显示中断，避免出现“已完成 / 状态 active”。

## 真实验收方法

`client/e2e/live-goal.spec.ts` 默认关闭，只有 `TAROCUB_LIVE_GOAL=1` 才启动原生 CLI。

停止流程：手机与桌面配对 → 原生目标 API 自主开始写作（没有替身 `turn/start` / `session.prompt`）→ 实际答案出现后由手机停止 → 核对原生 `interrupted` / `aborted` 终态 → 同一原生会话回答原作品编号 → `/goal status` 确认无目标 → 两端刷新后仍可见，已中断消息没有被迟到输出改写。

完成流程：模型计算随机两数之和，结果并未写在用户提示词中 → 目标和原生轮次完成 → 实际结果只显示一次 → 两端刷新、查询状态仍保持同一会话。计算结果容许模型添加空格；续聊容许标题带引号，但必须保留完整随机编号。截图等待 Markdown worker 完成解析，不把短暂的原文占位当作最终 UI。

观察器只记录本次隔离 worker 的协议边界与合成答案，不替换请求、结果、权限或原生行为。Codex 临时会话通过原生归档 API 清理；DeepSeek 使用隔离实例目录，测试结束后关闭 Hub / worker 并移除目录。

## Opus 5.5 复核

实际调用 `claude-opus-5-5 --effort xhigh`，只读检查；成功返回，73 个 turn，约 10 分 28 秒。它指出迟到目标事件、缓冲通知丢失、未知 ID 的普通停止、最终正文重复和固定超时等问题。对应修复增加了可控协议回归，再用真实 CLI 检查。

复核期间代码仍在迭代，因此这不是 Opus 对最终提交的逐行批准。其 DeepSeek 建议包含一个明确未闭合的网络竞态：仅凭本地“普通消息尚未开始”就取消整个会话，仍可能误停已经在原生端开始的普通消息。本轮保留更保守的已接入请求保护，没有采用这种扩大取消范围的做法。

## 最终结果

Codex 0.160.0、DeepSeek 0.2.0-rc.2，Chromium / WebKit 各自完成停止和自然完成两条流程，共 8 项通过，保存 16 张解析完成后的双端截图。手机点击停止到原生中断边界为 Codex 64 / 65 ms、DeepSeek 49 / 84 ms，仅为本机样本。8 个原生 CLI 进程均确认已退出，目标测试目录无残留；Codex 测试会话已原生归档。

必需仓库检查通过：233 个文件，3,688 项通过、1 项跳过，构建通过。两种浏览器默认关闭检查各跳过 2 项，未启动真实模型。初次原生缺陷、测试误认静态目标条、过小预算、空格／引号断言及重复正文的失败均在回执保留；最终通过不抹去这些记录。

## 保留的限制

- DeepSeek 0.2.0-rc.2 的 `session.cancel` 没有 expected-turn 参数。已有普通请求接入时，清除目标只撤销自动继续，当前原生目标轮次可能自然结束。不能承诺该组合即时中断。其普通排队消息的取消、目标预算与普通轮次用量的严格分离、并行 steering 的归属仍需下一步专项验收。
- Codex / DeepSeek 目标后台的 App 工具授权限制保持不变；本轮没有验证后台文件发布、交互审批的全矩阵。
- Claude / Antigravity 的原生 slash-goal 与 Kimi 的不支持路径不是本轮真实模型验收范围。
- 手机布局浏览器不代表实体手机的键盘、锁屏、权限或通知；此轮未更新安装包、替换已安装 App、部署 Hub 或重启生产 Bot。

最终结果、停止边界计时、截图索引和保留的初次失败见 机器回执（本地材料：`evidence/native-goal-2026-10-04.json`）。精确停止计时是同机本地验收，不代表公网或移动网络时延。
