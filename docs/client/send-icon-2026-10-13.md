# Icon-only composer send button

Mac 1.0.53 removes the visible Send/Queue words from the composer button. The
up arrow stays, using a fixed 32px desktop control and the existing 44px phone
hit target. Normal, CLI and pixel themes share this behavior. Obsolete
label-driven pill widths are removed. The accessible name remains “发送消息”;
the tooltip distinguishes normal sending from queueing during a running task.
The separate steering and stop controls, queue behavior and keyboard send
semantics are unchanged.

Verification uses isolated Hubs: WebKit passed both Latin/Chinese IME cases,
compact-message layouts in three themes at 1360px/800px, and desktop/phone
send/queue/steering acceptance. Chromium passed IME and send/queue/steering;
the opt-in native-engine live-steering case was skipped. Root and client
builds passed. Rendered screenshots confirm the single-arrow control.

The local Apple Silicon installer includes earlier conversation-search and
message-alignment updates. No installed App or live host is replaced, and
these browser-engine checks do not claim physical-phone or native IME testing.

## CLI Return glyph (2026-10-16)

The CLI palette now renders the composer Send action with a small Return (↵)
glyph. The icon stays centred on hover, follows the existing button foreground,
and uses the same 18px size as the previous arrow. Other palettes retain their
up arrow. The accessible name, disabled state, queueing and keyboard behavior
stay the same. This is App presentation only, with no host or headless CLI
change.

Verification: the client production build and the existing CLI/pixel palette
journey passed (light/dark/system, reload persistence, 1360px desktop and
320px/390px phone layouts). Rendered desktop/phone screenshots confirm the
Return glyph in CLI and the original arrow in Pixel. This change is source-only;
the installed Mac app and published Android 1.0.72 asset have not been replaced.
