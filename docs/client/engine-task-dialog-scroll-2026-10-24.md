# 子代理与后台任务弹窗滚动修复

用户在 Android 的「子代理与后台任务」弹窗看到多条任务，但无法继续下滚。
复现基线：`c2e73c5`。实际组件是 `EngineTasks.tsx`，使用原生 `CreationDialog`。

## 原因与修复

外层弹窗允许滚动，内层 `.engine-tasks-list` 同时设置了 `overflow-y:auto`
和 `overscroll-behavior:contain`，却没有受限高度。内层随内容撑高、没有可滚动
距离，并拦住了向外层传递的触摸滚动。测试中在 12 条任务上发送真实 Chromium
触摸事件后，第一条任务的纵坐标保持不变。仅用 `scrollIntoView()` 会掩盖问题，
还会把关闭按钮一起卷出屏幕。

仅修改此弹窗：使用纵向 flex 布局和一个可收缩的 `.engine-tasks-body` 滚动区。
提示、恢复操作和任务列表都在该滚动区内；标题、关闭按钮和底部批量操作固定在外。
移除任务列表自身的嵌套滚动设置，沿用现有字体、主题与任务操作。

任务查询、归属、停止回执、后台进程和只读任务卡未修改。CLI 不适用：这是 App
滚动布局修复，`tasks` 命令和共享任务 API 保持原有行为。

## 验证范围

- 浏览器使用与 App 相同的全局样式；任务夹具包含运行主机标签和 12 条任务。
- 390×844 竖屏、844×390 横屏、1360×900 桌面；检查真实滑动/滚轮能移动内容、
  最后一项及其停止按钮完整可见、标题/关闭/批量操作完整可见、无页面滚动和横向溢出。
- Chromium 手机布局使用 CDP 触摸事件。WebKit 的移动输入模拟不支持滚轮/滑动注入，
  因此验证同尺寸及粗指针布局的滚轮行为；不作为 iPhone 真机手势验收。
- 既有任务列表回归覆盖单独停止、未知/拒绝回执、离线、父子任务与强制恢复确认；
  App 导航回归覆盖 `/tasks`、菜单打开和切换对话后不会意外重开。
- 浅色/深色底部截图与测试记录位于
  `/Volumes/gdrive/taro-tmp/engine-tasks-scroll-20261024/`。

结果：Chromium 13 项、WebKit 11 项浏览器用例通过；共享任务 API/CLI 的 21 项
测试通过；Host/CLI 和 App 构建通过。没有执行手机原生安装或真机触摸验收。

本次没有安装或发布新版本，也没有停止生产会话里的任务。
