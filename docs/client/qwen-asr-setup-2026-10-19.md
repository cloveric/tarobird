# Qwen3-ASR 标准安装与运维完善（2026-10-19）

## 行为与边界

App 的集成建议页、`tarobot integrations asr` 和直接 Bash 入口共用安装器。
默认脚本行为不变；下载模型、注册监督器均需显式选项或 App 确认。
标准运行目录属于当前操作系统用户；不按 Bot 或 Hub 数据目录创建多份模型。
同机多个 Hub 共用安装锁和任务回执。旧服务占用端口时不接管；向用户说明迁移入口。

协议新增 `integrations.asr.v1`：owner-only GET `/api/integrations/asr`，POST
`/api/integrations/asr/install`（严格 requestId/model/service）。保存入场审计，执行前
重新验证 owner 会话；业务冲突返回409，平台不支持返回400。只执行随包固定安装器，
不接受客户端路径或命令。状态不含模型路径、用户目录或转写文本。
同 OS 用户的完全访问 Bot 仍属于本机信任边界；不能宣称 API 认证隔离这种 Bot 的系统操作。

安装任务回执持久化，保留最多64项，使用实际子进程PID与跨进程文件锁。
状态读取单飞、3秒缓存；前端仅可见时轮询。未知提交结果保留请求编号，明确重试不重复安装。
已确认启用时不把以前的失败当作当前错误。旧主机没有能力时显示更新提示。

内存回收保留定时/请求结束两种检查；自动判断核对监督器PID和退出后重启策略，
显式 ASR_RECYCLE_IDLE 优先。macOS footprint；其他平台 RSS 加 CUDA reserved。
不可读明确报告 unavailable。修复与模型冷启动/所有接受请求共享文件锁；有任务不强杀。
保留回环监听、8请求上限、音频校验、通用错误、无 shutdown 接口。

- B2 继承监督器变量/孤儿进程误判：核对真实监督器PID、KeepAlive/Restart及InvocationID。
- B3 旧服务的必败安装按钮：隐藏并显示可继续使用、可由Bot协助迁移。
- B4 历史失败覆盖当前成功：以当前服务确认状态为准，隐藏过时失败提示。
- B5 macOS临时目录别名导致测试失败：测试使用规范路径；产品仍拒绝符号链接祖先，明确限制。
- B6 业务错误变500：添加400/409映射及真实Hub响应测试。
- 同步改善：实际安装器PID、跨进程单飞、固定服务PATH、状态stdout隔离、状态单飞缓存、
  旧模型自动发现、请求回执保留、失败配置回滚、确认文案和私有配置就绪顺序。

方案阶段 Opus 建议删除若干功能以缩小实现；本次按 Owner 明确范围保留自动判断、周期检查、
跨平台内存、模型下载与服务管理。代码复审已认可可在这些功能内部修复，没有不可兼顾的矛盾。
保留的设计取舍：不强杀持有请求锁的卡死推理；不自动覆盖已注册服务；不重排整个 Skills 设置页。
如要改变这些取舍，需另行明确任务超时/升级及设置页范围。

收尾复审结论为“可交付，没有剩余阻塞项”。随后提出的N1服务加载窗口误显未安装、N2

计数，helper不因健康服务的400/422而重启；Opus确认未引入恢复漏洞。网络文件系统限制已补入README。
模型质量退化/无异常的空文本不自动修复；可通过时长校验但解码失败的坏文件可能触发一次空闲修复，
受互斥锁和共享冷却约束。复审无待Owner裁定的阻塞分歧。

## 已知限制

- Linux/systemd服务模板、Windows内存路径有自动测试，尚无这两平台真实服务/GPU验收。
- 原生Windows一键服务注册未实现；Linux用户服务默认登录启动，不自动启用linger。
- 本次Mac复用模型，未执行新的HF模型下载；使用官方CLI的恢复机制，模型完整性在下载后验证。
- 不自动修复符号链接HOME或覆写已有服务；人工升级/回滚见集成README。
- 推理卡死且仍持锁时需人工判断，避免误杀有效长任务。
- 源码提交不等于已安装桌面App升级；本次不发布新版App/CLI安装包。
- GitHub Actions因私有仓库账单限制不作为验收依据，本地检查结果单独记录。
