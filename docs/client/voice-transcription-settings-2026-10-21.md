# 语音转写设置

## 入口与三种模式

桌面、手机和浏览器共用「设置 → 语音转写」，配置当前主机的全部 Bot。

| 模式 | 实际路线 | 失败处理 |
| --- | --- | --- |
| 全部本地 `local` | 短语音、长录音都用本地 Qwen；长录音沿用现有分段机制 | 本地失败报告错误，不上传云端 |
| 全部云端 `cloud` | 所有录音用通义听悟，包括短录音与无法读取时长的录音 | 云端失败报告错误，不切回本地 |
| 按时长自动选择 `auto` | 短于阈值用本地，达到或超过阈值用云端；时长未知先本地 | 云端失败沿用本地回退；取消不回退 |

仅自动模式显示「长语音起点」，范围 1–120 分钟，默认 15 分钟；恰好达到阈值算长语音。
切换到固定模式隐藏该输入并保留已设置的有效阈值，切回自动时恢复。
自动模式保留录音同消息/同批正文中的原有强制路线关键词；固定模式以主机选择为准。
录音路线在本次时长探测前固定，保存不打断正在转写的任务，也不重复排队。
模式选择不启停已有 Qwen 服务。新视频的自动提取音轨范围没有扩大。

本地模式与自动模式显示 Qwen 状态、安装/修复入口，复用现有 LocalAsrSetup。
云端模式与自动模式显示已有通义配置检测和上传同意；选取新模式或适配器后重新确认。
上传前明确说明阿里云 OSS、通义听悟及可能的费用。页面读取与保存不发起付费云任务。
「Skills 与 MCP → 语音与搜索建议」中的可选通义引导仍仅准备独立配置对话草稿。
不在客户端或聊天里输入/读取密钥，不把文件存在描述为实际 API 验证成功。

## 保存与归属

保存必须收到服务端响应并再次 GET 核对版本、参数和原请求回执。
失败不显示成功，不自动重发；客户端按主机公钥保存非秘密请求，显式重试沿用编号。
多设备版本冲突要求重新载入。草稿在设置分类之间保留，关闭前提示放弃。

- 首次保存前沿用现有环境；页面读取主机公共配置，不枚举各 Bot 的旧覆盖文件。
- 首次保存后，当前主机启动的新版 Worker 按 `TAROBOT_HOST_DIR` 读取统一策略，
  优先于每 Bot 的历史云端目录、模式和时长。其他主机不受影响。
- 策略写入 `<Host-state>/voice-settings.json`：格式 2，含 `mode`、目录、阈值、版本，
  以及最近 32 个请求的操作者、时间、参数摘要和回执。POSIX 权限 0600。
- 读取旧格式 1 时，`enabled=false` 映射为 local，true 映射为 auto；仅查看不重写文件，
  保存时写格式 2。不会把旧配置迁移为全部云端。
- Hub 能力为 `integrations.voice.v2`，Worker 为 `integrations.voice-policy.v2`。
  v1 客户端/CLI 与 v1 Worker 不能正确表达全部云端，需更新。在线未支持的 Worker
  显示提示，任务结束后通过当前主机更新并启动。手动 Worker 未绑定 Host 不宣称接入。
  不接受缺少 `mode` 的旧 API 写请求，避免猜测；v1 Worker 读取格式 2 会禁用云端，
  因此必须完成后台更新才能使用新设置，不能将其提示当作已生效。
- 文件损坏、非普通文件、链接、权限过宽或超过 32 KiB 时报告不可读；Worker
  禁用云端并保留本地路线，不回退旧环境配置而意外上传。

## 接口与权限

| 接口 | 行为 |
| --- | --- |
| `GET /api/integrations/voice[?requestId=ID]` | mode、目录就绪度、阈值、待更新 Worker、回执 |
| `PUT /api/integrations/voice` | 严格校验 requestId、revision、mode、adapterId、thresholdSeconds、cloudConsent；最多 4096 字节 |

`cloudVerified` 恒为 false：本接口不进行付费 API 验证。
仅已认证 owner 可读写，Bot 实例凭据不可调用；提交阶段重新核对撤销/权限。
文件锁等待上限 10 秒、版本检查、请求幂等、独占临时文件+fsync+原子替换保持不变。
提交与权限撤销在同一 Hub 数据库串行队列排序；不在该队列扫描适配器目录。
审计 `voice.settings-updated` 记录 mode、阈值、目录 ID、请求 ID，不记录密钥。
落盘后审计/响应失败属于结果待核对，通过持久回执恢复；超过 32 个回执仍受版本保护。

目录仅能选择主机检测结果，不接受任意路径或命令。检测公共 TINGWU_ASR_DIR、标准目录
`~/.tarobot/integrations/tingwu-asr`、兼容目录 `~/.tarocub-secrets/tingwu_asr` 及已保存目录。
兼容目录不表示需要旧聊天平台。凭据由适配器读取 `.env.local`；设置仅查元信息。
拒绝标准 Bot 工作区及指向其内的链接；自定义工作区仍需配置人员核对。
POSIX 验证所有者/权限；Windows 页面明确文件与位置检测不等于 ACL 已验证。

## CLI

同一正在运行的 Hub、同一 owner 身份与接口，不另起 Hub：

```sh
tarobot integrations voice status --json
# 从 status 取得 revision 与 adapterId；所有设置都需确认主机范围。
tarobot integrations voice set --mode auto --adapter ADAPTER_ID \
  --threshold-seconds 300 --revision REVISION --yes --request-id voice_setup_1 --json
tarobot integrations voice status --request-id voice_setup_1 --json
```

将 `--mode` 改为 `local` 或 `cloud` 选择固定路线；仍需保留有效阈值以供切回自动模式。
旧 CLI 参数 `--enabled on/off` 在新版 CLI 中分别映射 auto/local，不能与 `--mode` 混用。
旧 API 的 enabled 写协议不复用为新模式写协议。新请求带预期版本并读回确认。
原 `integrations asr status/install` 仍是系统用户级安装，不能携带云端模式参数。
未托管 Worker 可用公共配置 `ASR_CLOUD_MODE=local|cloud|auto`，缺省 auto；Host 策略优先。

## 验证与边界

本次使用隔离 Host、虚构凭据、模拟本地服务与可执行的假通义适配器验证实际路由。
没有真实付费云端调用，没有更改生产语音设置、重启生产服务或替换 App。
验证重点：三模式短/长/未知时长、阈值等号边界、云端失败不回退、取消、旧策略迁移、
同编号重试、权限/CAS、真实编译后 CLI、手机/桌面保存刷新与阈值保留。

本轮结果（2026-10-21）：

- 完整本地回归：367 个文件通过，5,160 项通过、5 项按条件跳过。
- 三模式与 CLI 定向检查：38 项通过；包含编译后的 CLI 连接隔离 Hub，
  三种模式各保存一次并以同编号重试，共 7 次 CLI 调用、3 次审计写入。
- 共享媒体提示兼容检查：12 项通过。
- Chromium 手机/桌面：10 项通过，覆盖三种模式、保存重开、阈值保留、
  同编号重试、读回失败、版本冲突、旧主机和离开未保存草稿。
  首轮发现测试夹具的本地看门狗字段误改；恢复其 `enabled` 后重跑全部通过。
- 主机构建与客户端构建通过；客户端构建包含翻译检查。提交前身份与历史密钥扫描通过。

上一轮未改动的原生 Rust 检查已通过 76 项；本轮没有重复下载/构建原生依赖。
WebKit 上轮已确认在空白页创建阶段阻塞，Safari/iOS 与实体手机验收仍未完成，
不以 Chromium 手机视口代替。GitHub CI 的账单限制另报告实际状态。
