# 网络与连接：入口、操作范围与返回路径

## 问题

设置中的正常组网入口藏在“设备与安全 → 危险操作 → 移除此主机连接”，实际却打开组网概览。连接线路、网络成员关系、此设备保存的连接记录混在一起；从一个主机详情配置线路还需要回到全局列表重新寻找。

## 设计

设置增加“网络与连接”一级分类，工作台和手机“我的”原有快捷入口保留。分类明确当前主机及连接状态，提供：

- **连接设置**：当前主机的线路。桌面本机显示局域网、Tailscale 和本机 VPS 入口；远程主机编辑的是此设备访问它的线路。本机回环地址不被中转覆盖。
- **我的网络**：主机之间的组网关系、网络成员名称与共享线路。
- **此设备的连接**：保存到当前设备的连接记录；从列表打开另一主机的线路也不切换当前工作台。

“设备与安全”继续作为独立设置分类，管理配对和授权。正常组网入口不放在危险操作中。设置底部不再以“移除连接”命名一个打开组网概览的按钮。历史单连接模式的真正“断开并重新配对”操作保留确认。

当前主机只是作用域行，不作装饰性大卡片。保存的连接列表先显示名称、状态和操作，改名时才打开输入框。帮助默认折叠，强调操作方向和填写 VPS 地址不等于部署隧道。

## 导航和草稿

- 设置进入连接页或网络概览时保持原页面挂载，关闭子页回到原入口，保留设置草稿。
- 从网络概览去配对新主机，或离开当前设置上下文，经过 `OpenNetwork` 导航守卫。有未保存内容时让用户选择继续编辑或放弃；不是每次打开只读页面都要求放弃。
- 从保存的连接列表进入线路页，使用选中记录的 `registrationId` 定位并绑定 ConnectionPanel；不发送工作台切换命令，不改变当前会话。
- 本机 VPS、连接编辑和主机改名的未保存输入各自保留确认；保存期间阻止离开。嵌套连接页的 Escape 不向父对话框冒泡。
- “添加主机”明确区分把新电脑加入当前网络和此设备连接另一主机。已有多主机网络不因一次配对而引导迁往另一网络；独立主机仍保留明确的加入确认。
- “确认新设备”打开所选网络的协调主机，显示其名称；没有网络时使用当前主机或唯一可管理主机，不在多个目标之间猜测。离线和权限不足会说明原因。
- 返回未保存的主机改名时可继续编辑或放弃；其他设备同步过来的改名不会被误判为本地草稿。
- 从设备设置修改主机名称会直接打开对应主机详情；创建网络优先使用打开页面时选中的主机，不默认落到列表第一台。
- 嵌套的设备审批页只显示当前主机的设备操作，不重复嵌入整套设置导航。“确认新设备”和“添加新设备”位于设备列表上方；返回仍回到添加主机页。
- 移除连接确认同时提供取消和确认按钮，标题标明目标主机。共享线路的返回标签跟随实际父页，避免返回层级不明确。

## 加载失败恢复

“我的网络”的按需加载模块由 `PageLoadBoundary` 单独包裹。升级后旧页面引用的模块不可用时，保留聊天工作区和设置草稿，显示可关闭的错误页；用户可以在保存输入后主动重新加载，不自动刷新或清空页面。本次边界仅覆盖网络页，不表示所有按需加载页面均已覆盖。

## 范围

不改变网络签名、配对、批准、撤销或持久化协议；不自动部署 VPS、不为真实主机修改线路、不自动批准组网。CLI 已有组网和线路 API 不变，本次新增部分是客户端发现入口与导航，CLI-not-applicable。

- 设置、工作台与 ADHD 的集成检查覆盖嵌套返回、焦点、目标主机和未保存输入。初轮发现的旧入口断言已按新导航修订并单独复验；不是未运行的全仓回归结果。

- 实际复现旧模块加载失败，并通过请求故障注入检查关闭错误页、保留聊天草稿及主动重新加载。主机名称同步、未支持改名时的错误显示、移除取消和 ADHD 返回路径均已定向复验。
- 最终桌面和手机设置流程、按钮文字可见性检查通过，并逐张复核截图；修正审批按钮受快捷操作样式覆盖而出现白底白字的问题。客户端类型检查、构建和翻译键/占位符校验通过。
