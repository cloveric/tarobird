## 已确认并修复

1. **新消息意外关闭预览**：在打开图片或文件后连续投递 35 条消息，虚拟列表
   卸载原消息，使其 portal 阅读器一起消失。修复前两个桌面用例均失败。
   图片、文件及其准备/保存过程现在保留所属消息行；关闭后继续恢复原触发按钮
   的键盘焦点。复用已有按 Workspace 计数的保留机制，不把整段历史常驻内存。
2. **断连破坏已加载原图**：连接状态变化使 `useAttachment` 撤销 object URL
   并重新下载；大图不在持久缓存时，断连会让正在看的图片变成加载失败。
   现在保留已成功取得的原始 Blob，URL 跟随 Blob 的生命周期；主机、附件 ID
   和 enabled 状态仍隔离。失败图片继续支持重连恢复和单次手动重试。
   最后还复现了 WIP 停用消费者后仍持有原图的问题（`before-disabled.log`）；
   显式停用现在清空 Blob 与 URL 引用，重新启用时重新取得附件。
3. **后台通知混淆更新、失败和交付**：后台 `partial` 同时用于未确认终态、
   例行更新和交付未确认，不能整体判为失败或成功。新增可选 `status` 与
   `delivery: unconfirmed` 标记区分这三类；明确失败、中断以及交付未确认
   保持 error 提醒，例行更新保持中性。静态报告和 scoped 报告均覆盖附件
   投递失败；旧报告仅对带结构化后台标记的固定中英文标题做兼容判断。
   推送省去重复的完成/更新标题和来源说明，保留失败标题，避免丢失告警依据。
   仍在运行的静态回报也归为更新；新增结构化状态与历史标题两种先红后绿用例，
   防止“后台任务执行中”的正文前仍出现“回复完成”。
4. **同一状态在两处含义不同**：scoped 卡片与过程详情统一为“最终状态未确认”。
   `done` 也作为完成状态处理，不再让已完成的后台子代理仍显示“后台任务更新”。
5. **个人删除未应用到过程附件**：运行详情查询现过滤当前用户已删除的附件
   消息，也在串行读取中再次核验原运行消息是否被该用户删除。其他成员仍保有
   自己的记录，删除范围没有扩大。
6. **并行运行的文件归属混淆**：旧文件消息只有原请求 ID，没有可靠的 run ID；
   时间重叠不足以证明某后台任务生成了文件。后台/子代理不再从时间窗口猜文件
   归属，前台也只有在同请求下没有其他 run 时才使用旧关联规则。回报本身明确
   携带的附件照常显示；无法归属的文件仍在原消息和文件中心，不删除、不改存储。
7. **后台复审等待被显示成思考**：Claude 等待同一会话的原生任务回报结束时，
   现在由适配器发出真实 admission 事件，显示“等待后台回报结束”。事件属于
   等待中的新消息，不计入工具动作数，也不借用上一轮回调。取消等待的模拟
   进程验证确认：新 prompt 未写入 stdin，原 worker 未被终止。
8. **停止影响范围和确认生命周期不清楚**：Claude 共享会话进程，活动回复的
   进程级停止可能中断同 Bot 的后台工作。对已知并行 scope 或后台复审等待，
   所有界面停止入口使用统一说明；等待态也保守确认，因为服务器可能已进入
   下一阶段。未添加“只在等待阶段生效”的协议能力，不承诺客户端状态就是
   收到停止时的状态。后台 streaming 消息本身不被当作前台回复。
   确认绑定主机、对话和原消息/run 身份；切换、隐藏、卸载、新轮次及确认后的
   异步缓存查询均有失效保护，重复点击不会并发发送。停止回执基线在真正发送
   时采集，避免思考是否停止期间的重连被误算成此次停止失败。
   Context 的停止回调保持稳定，输入草稿不因这个新入口触发所有运行卡片重新渲染。

Opus 的首轮 WIP 复审确实阻止了两个错误修法：把所有 scoped partial 中性化，
以及直接去掉所有后台标题。修正后独立探针复核卡片生成、Gateway 转换、推送
分类和等待取消；发现并修正静态附件交付、回执取样及确认异步生命周期问题。

## CLI 与兼容性

阅读器保留和原图生命周期属于客户端展示，无需新增 CLI 命令。通知、运行详情
和状态标题使用共享 Hub/Core 实现，桌面内置主机与 headless CLI 自动共用；
未引入新端点、数据库迁移、权限或队列规则。后台卡片新增两个可选元数据字段，
旧客户端按原非 strict schema 忽略新增字段，原有严格 run summary 形状不变。
等待事件在共享 Core 内记录，停止协议语义不变。下一次发版必须同步构建 App
和独立 CLI，源码提交本身不表示本机已升级。

历史附件没有 run ID 的边界采用保守显示，没有靠正文、文件名或时间猜测归属。
终态未知没有被升级成成功，后台卡片也没有接上前台停止按钮。显式 `/stop`
命令保留既有命令语义。未上报/未加载的后台 scope 不能依靠客户端推断；没有
引入独立子进程取消。执行阶段结束和后续复审结束是不同回报，本轮未合并通知。
停止请求依旧按对话/Bot 寻址，没有新增服务端 run-ID 条件取消，因此发送后到
服务器接收前的状态变化仍受旧协议限制；本轮的确认失效保护覆盖客户端决定与
缓存重读阶段，没有把它描述为服务端原子取消。
