# 设备与安全：身份、名称与授权层级

2026-10-14。落实此前两轮 Opus 5.5 xhigh 讨论，桌面和手机共用同一设备管理逻辑。

## 页面与操作

- 页头显示一次当前管理的主机名称，沿用共享主机资料。
- 按当前设备 ID 置顶「你正在使用」，其余有效授权单独分组，已撤销记录默认折叠。设备列表先于一般配对说明；待确认请求仍优先展示。
- 每行一个「管理」入口，详情提供明确的「修改设备名称」、身份尾号、系统、配对和上次连接时间；撤销记录只读。
- 只有当前设备依据实际连接状态显示已连接。其他设备的上次连接时间不表示实时在线；缺失时间不伪造为刚刚连接。
- 手机详情占满可用视口并保留安全区。返回和 Escape 遵循页面层级，未保存名称需要明确放弃；写入期间防止重复提交。
- 新配对默认使用 Mac 电脑、Windows 电脑、Android 手机等中性名称，提示确认稳定名称。旧名称不自动修改、合并或推断机型，模糊旧名称提示可永久关闭。
- 无可靠客户端类型字段时，`web` 标记显示「浏览器或其他客户端」，不把 CLI 误称为浏览器，不臆测本地控制器角色。

## 授权与名称范围

设备名称修改使用原有 `/api/devices/rename`，只更新所选主机的设备记录，不改变主机名称或设备身份；不会承诺同步修改整个网络的设备别名。

撤销确认说明已入网设备的授权将同步撤销到整个网络，以及同步可能有延迟。没有可靠网络目录时使用条件说明，不承诺仅影响单个主机。撤销设备访问不会让承载 Bot 的主机退出网络，也不删除 Bot；已缓存消息和完整文件保留。当前设备仍不提供自撤销入口。

原有签名证明、权限边界、一次性配对码、丢失回执后的读取核对均保留。增加 `tarobot devices rename ID --name NAME`，与 App 使用同一 API；CLI 帮助和操作指南同时更新。没有新建一套身份、数据库或精简主机。

## 验证边界

测试使用隔离的真实 Hub 和浏览器设备，不修改用户生产设备授权。包含重名设备、旧默认名、撤销记录、改名持久化、断线、过期读取、丢失回执、返回草稿保护、窄屏与安全区、手机确认新电脑、桌面带 Bot 加入网络等场景。

本次交付为源码与本地构建；没有生成、发布或安装新的 App / CLI 安装包，不代表真实手机或原生权限弹窗验收。安装版本不变。

### 本地结果

- 主程序 `npm run build`、客户端 `npm run build --prefix client` 通过；构建后的 CLI 帮助包含设备改名入口。
- 六个单元／集成测试文件共 111 项通过：`device-presentation`、`host-cli-management`、`host-cli-network-command`、`hub-device-actions`、`hub-request-revocation`、`hub-private-network`。
- 首轮较广浏览器回归：Chromium 85 项通过；WebKit 83 项通过，2 项发现撤销按钮移除后焦点落在嵌套对话框的问题。已修复后，设备／设置／语言／远程配对重点回归 Chromium 和 WebKit 各 26 项全部通过。
- 手机 320/390 像素、横屏、47 像素顶部安全区、桌面布局均覆盖；截图为隔离验收环境，不是用户设备实况。
- 打开另一条设备记录时清除上一条的操作提示，防止把之前的改名结果显示在别的设备详情中；该路径纳入最终设备体验回归，Chromium 和 WebKit 各 6 项全部通过。
