# 系统推送令牌更新与多主机同步

2026-10-11，本轮属于程序实现和本地验收。没有部署 Hub、重启服务、安装手机包或替换已有 Mac 安装包。

## 修复的行为

- 每个已配对主机独立维护 APNs/FCM 订阅；一台主机响应慢不会阻塞其他主机。首次连接、重新连接、App 回到前台，以及系统注册事件，都会重新检查对应主机。
- 维护只更新已经启用且选用了对应系统推送的主机。没有订阅、用户已删除/关闭、改用 UnifiedPush/Web Push、设备已撤销时，不会自动创建或重新启用。
- Hub 将“用户选择的推送方式”与“当前可投递的令牌”分开保存。服务商报令牌失效时保留订阅选择，之后可恢复；用户 DELETE 则同时移除选择。
- 每次显式注册、删除和通知偏好变更都隔离旧更新请求。后台更新必须提供读取时的订阅版本；发生冲突后最多重读一次，并重新读取系统令牌。
- APNs 事件仅作为更新提示。真正的令牌来自 AppDelegate 先写入的内存快照；保留的旧 JS 广播不能直接充当本轮注册结果。提示触发快照读取，不触发重复注册循环。
- FCM 使用上一轮加入的原生 Firebase Task 返回值。后台维护不申请通知权限，也不保存令牌到 IndexedDB。
- 本机清理会同步取消维护及设备令牌读取。权限弹窗、原生快照和监听器迟到返回后都不能重启 APNs 注册。

## 数据与兼容

Hub schema 12 新增 `push_bindings` 表；schema 11 的有效现存订阅迁移一次并保留原令牌。重启和备份恢复保留订阅版本。升级前已经被服务商清空的旧订阅无法从空值恢复，需用户重新启用。

新增 `GET /api/push` 只返回 provider、revision、enabled，不暴露令牌；`PATCH /api/push` 只允许 APNs/FCM 的版本匹配更新。旧 Hub 不支持时停止自动维护，不退回无条件 PUT。

iOS 快照接口与新的 App 原生代码一起交付。旧 iOS 壳没有该接口，不能宣称已支持本轮自动更新。Android 依赖上一轮的原生 `registerFirebase` 接口。
