# iOS 原生 TLS 接入 · 2026-10-05

iOS 源码已将 Hub HTTP、文件和 WebSocket 接入原生 URLSession/Security，
并由 Capacitor 插件连接到共享前端。按用户决定，本阶段不增加应用层端到端加密。
独立中转只转发 App 与 Hub 的 TLS 字节，不需要持有 Hub TLS 私钥；若 VPS 同时
运行 Hub，它就是能够读取业务内容的运行主机。

**这是源码和隔离 Apple Foundation 验证，不是 iPhone、iOS 安装包或正式发布验收。**
本机只有 Command Line Tools，没有完整 Xcode。没有替换已安装 App、r25 安装包、
在线 Hub 或 VPS；原计划第 14 项仍开放。

## 实现范围

- `client/ios/App/App/HubTLS.swift` 先保留系统 CA、主机名及证书策略校验，再验证
  Hub 身份对随机数和实际 TLS 叶证书摘要的 Ed25519 签名。证明请求不带设备身份
  或业务凭证。只有证明成功，才允许同一 URLSession 发送后续请求；每次新的
  信任回调还要符合固定的叶证书。生产插件没有测试 CA、替换公钥或跳过校验参数。
- 系统信任采用异步验证，避免证书链获取阻塞其他主机、取消和超时。信任失败会
  取消整个对应会话并作废缓存；普通认证挑战不能污染后续请求的错误原因。
  HTTPS 是硬性要求，含 loopback；不跟随重定向，不使用 Cookie、凭证缓存或
  WebView 回退。同源路径只允许 `/health` 和公开 `/api/`，拒绝内部实例入口变体。
- `HubTransport.swift` 管理页面凭证、32 个 HTTP / 8 个 Socket 名额、5 分钟
  证书缓存、请求取消与期限。HTTP 期限 300 秒，Socket 兜底期限 1,200 秒；现有
  15 分钟令牌续期仍提前更新连接。正常缓存轮换让已开始的有期限任务完成。
- 上传上限 8 MiB，整个传输器同时持有的已解码上传体不超过 32 MiB，只传单次
  使用的 InputStream，不接受可直接重放的 `httpBody`。
  丢失响应的写操作仍可能已经在 Hub 执行，不能把网络失败解释为“没有执行”。
  测试中的“服务端读完 POST 后断开”只收到一次上传，不能据此保证所有 CFNetwork
  版本、HTTP/2/3 和移动网络故障下绝无内部重试。
- HTTP 使用原生 AsyncBytes 按需取数据，每次桥接至多 256 KiB，复用同尺寸的
  读取缓冲。首版暂停 dataTask 的方式在真实测试中仍累计超过 8 MiB 回调数据，
  已替换。新路径通过 512 MiB 哈希和未消费响应测试。该测试记录的是应用读取块
  和受控响应行为，不能声称整个 App 或所有 Foundation 内部缓冲只有 256 KiB。
- WebSocket 原生 `maximumMessageSize` 为 1 MiB，整个传输器的待完成发送最多
  16 MiB。每个连接最多交付 8 个或总共 1 MiB 未确认消息；另容纳一个已接收但
  等待字节额度的消息，收到确认后继续，停滞有期限。它们是准入和应用队列限制，
  不是整个 WebKit/JSON/系统网络栈的总内存上限。
- `HubTransportPlugin.swift` 在主线程管理监听器和页面代际；利用 Capacitor
  `reset()` 实际调用的 `removeAllListeners(nil)`，在页面导航与 WebKit 进程终止
  时取消旧工作。代际在原生入口处采样；iOS 每次调用还携带页面随机标识，新页面
  的凭证申请要与当前 WebView 的实际标识一致，避免桥队列里迟到的旧申请冒领。
  事件名也按页面分开。同一页面主动重置不会丢掉旧请求的失败回执；真正导航
  后的回执不会注入新页面。插件销毁清理网络资源。
  `ShareInboxPlugin.swift` 的容器同时注册此插件，Xcode 工程包含三份生产 Swift
  文件；共享 `native-network.ts` 识别 iOS 和 Android，插件失败不回退普通网页请求。

## 关闭回执的实际修正

Apple 的原生关闭回调不能简单解释为服务端确认：测试让服务端收到客户端关闭帧
后完全不回复，URLSession 仍以客户端指定的状态码和原因触发 `didCloseWith`。
初版因此误标 `clean: true`，已保留失败收据并修正。

现在本地主动关闭仍完成资源清理，但保守地返回 `clean: false`，不虚构服务端
确认。未主动关闭时收到服务器发起的关闭，才保留服务器状态码和清洁关闭标记；
异常断线、消息过大、取消和超时不标为清洁关闭。队列已满时的关闭也有专项测试。

## 验证与证据

运行：`TMPDIR=/tmp/t node client/scripts/ios-transport-audit.mjs <输出目录>`。
脚本编译生产 Swift 核心和管理器，在 Mac 的真实 Foundation/Security 上连接
隔离 Hub、临时 CA 和两张同 CA 的有效证书，不安装系统 CA，不读取用户聊天。
脚本清理自己的进程、密钥和状态目录。

验证包括普通 CA/主机名拒绝、真实配对和设备认证、冒用代理拒绝、认证 HTTP/WS、
8 MiB 上传、512 MiB 下载哈希、256 KiB 分块、慢响应与上传取消、页面凭证作废、
迟到请求拒绝、配额回收、事件确认、关闭回执、过大消息及证书轮换。认证代理的
敏感请求计数为零。文件耗时是本机隔离测试，不能用于 VPS 或飞书速度比较。

插件另做了 Swift 类型检查：直接导入已安装 Capacitor 的真实 Objective-C 头文件，
只用编译覆盖文件声明三个 Swift 便捷方法。这能检查覆写与空值签名，但**不是
完整 iOS SDK 编译，也没有运行 Capacitor 容器**。测试文件不进入 App 构建目标。
前端的真实 Capacitor JS SDK 配替身原生桥，在 Chromium/WebKit 验证两种手机平台
检测、分块、订阅顺序、实际关闭事件、取消与失败不回退；这也是独立的合同测试。

准确结果、失败复现、Opus 报告和生产源文件哈希见
本轮收据（本地材料：`evidence/ios-native-transport-2026-10-05/summary.json`）。

## Opus 5.5 复审处理

两轮实际 `claude-opus-5-5 --effort xhigh` 分别检查 TLS 核心与传输器/插件，
用时 327 秒和 507.58 秒，均未报告高等级别问题。报告是修正前的静态意见，
不能视为修正后的批准或真机验收。

- 已处理异步信任验证、单次上传体、信任失败会话作废、具体错误码传递，以及
  旧任务不能删除同线路新建的缓存。实际 AsyncBytes 路径验证了换证书时返回
  `tls_identity_mismatch`，随后重新证明能够恢复。
- 已处理主线程调度前后的代际窗口、迟到页面凭证申请、同页面重置的回执，以及
  多连接的上传/发送预算和按字节确认。插件生命周期部分仍待真实 iOS 容器运行。
- “256 KiB 或 EOF 才返回”确实不适合 SSE/NDJSON 增量 HTTP。本产品的聊天、
  thinking 和进度事件走 WebSocket，HTTP 用于有限 JSON 和文件；本轮保留文件
  分块聚合，不将此接口标为通用的低延迟 HTTP 事件流。未来新增这类端点时必须
  增加有界缓冲和及时刷出的读取模式，不能直接复用现有聚合语义。
- 1,200 秒 Socket 期限是已有产品策略的兜底，令牌提前续期；缓存退役让已准入
  的有期限任务结束，属于预期行为。系统恢复票据、WS 底层接收缓冲和网络迁移
  等未由当前实验证明的条件继续留在原生验收范围。

   原生产品流程继续保留为独立验收项。
