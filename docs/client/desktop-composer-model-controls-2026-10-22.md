# Desktop composer model and effort controls

Ordinary desktop conversations display the current Bot model and effort at the
right end of the composer toolbar, immediately before Send. Each compact button opens the existing
model or effort dialog, including supported choices, custom model IDs, explicit
Bot-wide scope, save feedback and revision-conflict handling. Closing the dialog
returns focus to its button and preserves the message draft.

The displayed values follow live Bot metadata. A direct conversation targets its
Bot; a group or topic exposes the buttons only when exactly one reply recipient
is selected. This avoids choosing an arbitrary Bot for a multi-recipient message.
ADHD panes omit these composer controls, including expanded panes; Bot settings
remain available through their existing entry. Model names truncate with the
complete value available in the tooltip.

Only an owner with an online Bot can open the composer controls. The existing
settings page remains available for offline diagnostics. Phone composer layout
is unchanged; its Bot settings continue to expose the same selectors. Existing
model/effort validators cover Codex, Claude, Antigravity, Kimi and DeepSeek as
supported by their adapters; this adds no separate catalog or save path.

Changes remain Bot-wide: other conversations using that Bot receive the updated
metadata, and subsequent tasks read the new settings at the adapter's existing
safe boundary. Current work is not interrupted and no chat message, new session
or context reset is generated by the controls.

CLI impact: presentation only. The existing `tarobot bots model` and
`tarobot bots effort` commands continue to use the same Host/Gateway APIs,
authorization, shared config mutex and revisions. No protocol, schema or CLI
behavior changes are needed.

## Placement correction

The owner requested these shortcuts only in ordinary mode and beside the send
arrow. The ADHD row and its CSS have been removed. Ordinary mode places the
controls after any live task actions and immediately before Send. Browser
checks now assert adjacency/alignment at 1360px, 900px and 761px, while idle and
running, and absence across six ADHD panes. Returning to ordinary chat restores
the controls and retains the pane draft.

The client translation/type/Vite build and three focused scenarios in each of
Chromium and WebKit passed after the correction. Desktop and ADHD screenshots
were inspected. Correction evidence: `/Volumes/gdrive/taro-tmp/tarobot-composer-placement-20261022`.

This remains a presentation-only change; Host APIs and CLI behavior are unchanged.

This is a source change. It has not yet been packaged into a new desktop installer
or installed over App 1.0.97. Browser evidence does not establish native WebView,
physical-device or real-provider acceptance.
