# TaroCub 对话界面：对齐 Grok Bot 的日常交互质感（Opus 5.5）

> 后续主流程已完成浏览器验收，并补上深色用户代码高亮及导航摘要中的粗体标记修正。
> 当前证据、检查结果和适用边界以 [design-qa.md](../../design-qa.md) 为准；下面保留设计交接时的观察与风险。

在 [professional-ui-opus55.md](professional-ui-opus55.md) 的中性主题之上做一轮**有边界的精修**，不是重写。
数据模型与范围不变：Bot → 独立对话，群组 → 独立话题；创建、自定义头像、消息操作、原生问题卡、文字/文件/语音输入、响应式和深浅色都保留。
本文件只记录设计依据和代码改动。**我没有构建、运行测试或截图**，构建和视觉验收由上级流程完成。这里也不声称已达到与 Grok 同等的产品水准。

## 依据（两张截图）

`screenshots/grok-alignment/01-reference.png`（x.ai/bot 官方交互演示，不含顶部站点导航）：

- 对话关系一眼能看出：自己的消息是靠右的近黑气泡（白字、全圆角）；Bot 的消息是靠左的浅灰软气泡，短回复的气泡只包住内容。
- 没有给每条输出套描边面板，工具结果的清单也放在同一种软气泡里。
- 头部只有一行（小头像 + 名称 + 一个图标）。
- 输入框是一条圆角输入面：左边 `+`，右边圆形黑色语音按钮。
- 侧栏近白底，只有一行选中（浅灰圆角填充）；行内是名称加一行预览，没有系统日志式的元数据。

`02-before.png`（当前 TaroCub 群组）：

- 顶部叠了三层：头部、`群名 › 群内讨论 … 全部话题` 面包屑行、话题标签行。
- 所有消息都靠左。“我”的消息只是浅灰小框；Bot 回复是带边框的卡片，里面还有深色描边的“过程 · 1 步”。
- 输入框约 130px 高，聚焦时整圈紫色边框加光晕，在画面里最抢眼。
- 侧栏每个子对话都重复“演示引擎”，每个话题都重复“独立话题”。
- 群组头部副标题显示的是第一个成员 Bot 的引擎（`codex · 演示引擎 · high`），放在群组语境下有误导。

## 实际改动

| 优先级 | 参考观察 | 改动 |
|---|---|---|
| 1 对话 | 自己靠右、深色；Bot 靠左、软灰 | 自己的消息：隐藏头像；“我”字只在视觉上隐藏，读屏仍会读出；整体靠右，只保留时间。文字气泡为 18px 圆角，最宽 600px（手机 88%）。浅色模式用炭灰 `#2b2a27` 配 `#f7f6f2` 字；深色模式用抬升中性灰 `#3b3a37` 配 `#f2f1ed` 字，与 Bot 的 `#262624` 明显区分。气泡内的链接、行内代码、代码块、引用、表格、分隔线、Bot 提及、选区、焦点框都单独改了颜色（对比度手算：正文 10–13:1，链接 ≥7:1，次要文字 ≥7:1）。气泡里的卡片、文件和链接预览（如转发）恢复页面配色。 |
| 1 对话 | 不套面板 | Bot 文字消息是软灰气泡，按内容收缩，最宽到阅读宽度。代码块、行内代码改为 `--raised` 底，在气泡上仍能分辨。卡片（运行/完成/审批/问题卡）直接作为软底表面：去掉描边、标题下的分隔线，圆角 18px。短卡片按内容收缩（最小 280px）；表单、问题卡、图片批次、分栏和表格占满阅读宽度。卡片布局里映射为 `var(--grey)` 的灰色描边，在卡片内统一改为发丝线 `--border-strong`，红、蓝、绿、橙这些有语义的颜色不动。只有图片、文件或运行状态的消息不加气泡。引用/转发条改为透明底、宽度随文字的左侧细线。 |
| 2 输入框 | 一条紧凑的圆角输入面 | 18px 圆角的单一表面，默认发丝边框加极淡阴影。聚焦时边框加深为中性 `--composer-focus`（与白底 ≥3:1）并抬高阴影，不再用紫色光晕；强调色只留给发送按钮。文本区用 em 固定为两行高（`calc(3.2em + 16px)`，手机 `+14px`），原来 `rows=3` 约 83px / 90px，现在约 61px / 65px。没有加入脚本或 `field-sizing` 自动增高，超出的内容在框内滚动。工具按钮和发送按钮为圆形：桌面 32px，手机 44px。“让谁回复”改为圆角开关条。功能按钮一个都没少。 |
| 3 顶部 | 单行头部 | 群组的面包屑行与话题行合并成一行：返回/群组图标按钮（文字只在视觉上隐藏，可访问名称仍是“返回群组「…」”）、话题条、`全部话题 n`、`新建话题`。头部与话题行之间不再画分隔线。当前话题从紫色下划线改为中性填充，和侧栏选中行一致。群组语义移到头部副标题：默认讨论显示“群内讨论”，话题显示“群名 · 独立话题”，不再显示第一个 Bot 的引擎。没有加任何“正在回复”之类的进度文字。手机上 `全部话题`/`新建话题` 只显示图标（加计数），点击区域 44px，文字保留在可访问名称里。 |
| 4 侧栏 | 选中仅一行、预览可读 | 嵌套的子对话和子话题只在有预览时显示第二行，不再重复引擎名或“独立话题”；Bot 行仍显示一次 model/engine，群组行仍显示话题数和 Bot 数，置顶行的回退文字不变。行圆角改为 8px，Bot 名 14px，子行 13px。“新建 Bot / 新建群组”改为无边框软底按钮；搜索框聚焦用中性边框。嵌套树、引导线上的选中段和自定义头像都不变。 |
| 5 动效 | 克制 | 没有新增动画。只有输入框 hover/focus 的边框和阴影过渡（120ms，沿用现有过渡），其余沿用原有 120–180ms 规则；减少动态效果设置下仍全部关闭。`.message` 没有新增 transform、transition 或 animation，只改了内边距和 flex 对齐，行高仍由 react-virtual 测量。 |

没有新增 UI 文案：副标题和标题提示复用已有的 `独立话题`、`群内讨论`、`全部话题`、`新建话题`，`en.json` 中都有对应英文。没有新增依赖、图标或插画。

## 改动文件

- `client/src/brand-theme.css`：在原有分区内修改，没有追加一层覆盖。新增 token `--self-message-fg/-muted/-link/-line`、`--bot-message-bg`、`--composer-focus`（浅色、深色、跟随系统三处都写了）；改了侧栏、头部/话题、消息、卡片、输入框、宽屏和手机分区。文件头的设计规则同步更新（新增 18px 圆角档，以及对话规则）。
- `client/src/GroupTopics.tsx`：上下文行与话题行合并成一行 `.topic-bar`，`新建话题` 的文字包进 `<span>`。可访问名称、`aria-current` 和话题目录对话框都不变。
- `client/src/App.tsx`：只改了头部副标题的取值（群组/话题语境）。
- `client/src/ConversationList.tsx`：嵌套行在没有预览时不渲染 `<small>`。

## 上级 QA 需重点检查的风险

1. **`:has()` 依赖**：气泡、卡片脱离气泡、嵌套行图标居中都依赖 `:has()`。不支持的引擎（Firefox 121 以前）会退化为：消息靠右/靠左但没有气泡底色。请在 Chromium 和 WebKit 上确认。
2. **灰色描边覆盖**：选择器 `.rich-card [style*="solid var(--grey)"]` 依赖浏览器把内联 `border` 简写序列化成原样。如果不匹配，会回到原来的深色边框，不会更糟。`card-layout` 夹具只加载 `styles.css`，不受影响。
3. **自己气泡里的代码高亮**：`hljs` 的紫/绿/蓝色在炭灰底上对比度偏低（约 3:1），只调整了注释颜色。用户消息里很少有高亮代码，请确认是否可以接受。
4. **头像测试**：自己消息的头像用 `display:none` 隐藏，DOM 仍在。`avatars.spec` 要求所有 `user:owner` 头像图片的 `naturalWidth === 256`；这些图片没有懒加载，理论上仍会加载，请实际运行一次确认。
5. **话题导航测试**：`topics.spec` 要求手机上“返回群组「…」”和“新建话题”都在视口内（现在都是 44px 图标按钮），还要求 390px 下没有横向溢出。话题很多时，话题条可以横向滚动，但滚动条是隐藏的。
6. **输入框高度**：固定两行，长草稿在框内滚动，不会自动增高。若希望自动增高，需要另行评估对贴底滚动的影响。
7. **卡片宽度**：短卡片按内容收缩（≥280px）。流式更新的运行卡宽度会随内容变化（无动画）。请检查审批卡和运行卡在桌面和手机上是否过窄或抖动。
8. **侧栏预览中的 Markdown 原文**（如 `**已完成**`）是预览数据本身的问题，本轮没有处理。
9. **深色模式**：卡片内按钮/选项（`--raised #222220`）和卡片底（`#262624`）差异很小，主要靠 `--border-strong` 描边区分，请目测确认。
10. `docs/entrypoint-map.md` 的主题条目仍指向 `professional-ui-opus55.md`。本轮权限不包括修改该文件，是否追加本文件的链接由维护者决定。
