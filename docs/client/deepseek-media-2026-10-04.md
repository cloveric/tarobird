# DeepSeek 十图与 PDF 原生交付验收

2026-10-04。覆盖原计划第 12.5 项的软件与真实引擎路径，不代替实体手机验收。
使用本机 DeepSeek Harness `0.2.0-rc.2`、已配置的默认模型与 low effort；没有更改
用户的模型供应商、全局 MCP 或生产实例配置。

## 修正

适配器原先只保留非图片附件的文件路径，图片只有内联像素与文件名。模型能看图，
但编辑或原样回传时缺少原始路径，容易猜测工作目录中的同名文件。
`buildPromptContent` 现在保留所有输入附件的路径，并继续传递原有图片字节、
真实媒体类型与规范化名称。没有更改 App 外发路径许可或上传／发布检查。

定向回归在修改前因缺少图片路径失败，修改后通过。首次真实流程也记录到缺失
路径导致的 `not-found`；工具明确返回 `published:false`，模型修正后只发布了一套
图集。不能仅凭这一次模型行为证明所有失败都由缺少路径导致，但适配器缺失本身
已由原生请求的定向断言复现。

## 最终通过范围

- 手机布局一次发送文字、十张 PNG 与一个 PDF；Hub 接受为一条用户消息。
- 每张图内含新生成的八位编号，PDF 有另一编号；编号未出现在提示或文件名中。
  模型生成的报告与十一份附件中的编号全部一致。
- 用户请求没有指定原生工具名称或旧文件标记。模型自行选择 `app_send_batch`。
- 十图分别带标题；原 PDF 和报告与图集在同一条消息发布。原生成功回执与持久化
  交付回执对应到同一个消息 ID，最终两轮各一次调用、一次发布。
- Chromium 与 WebKit 各使用独立的桌面和手机浏览器上下文。全部图片成功解码，
  浏览器附件缓存 SHA-256 与原图一致，实际下载的 PDF 和报告字节一致。
- 检查了桌面网格、手机单列图集的开头与末尾截图，页面没有横向溢出。
- 真实观察器只转发、记录原生 App RPC，不注入模型答案或工具结果。关闭 Hub 后
  观察器和原生子进程均退出，测试私有目录和 DSH 历史已清理。

最终回执、失败记录和源文件摘要（本地材料：`evidence/deepseek-media-2026-10-04.json`）。

## 保留的失败与测试修正

1. 初次脚本把“只发布一次”写成“模型只尝试调用一次”。已改为要求唯一成功发布，
   并逐一核验其他尝试必须有明确的 `published:false`。重复图集与附件仍会失败。
2. 一次 WebKit 流程把报告写入合法的 `workspace/output` 并成功交付；脚本却去
   工作区根目录读取。现在通过 Hub 登记的附件 ID 读取已交付报告，并与两端实际
   下载结果比较，不猜模型使用的输出子目录。
3. 一轮 Chromium 收到原生 Harness 错误 `tool input is invalid JSON`，发生在
   批次工具调用之前。App 显示部分完成，没有报告附件已交付。该轮保持失败记录；
   单独复测成功，没有添加自动重放、吞错或无限重试。此供应商／模型层失败仍可能发生。

## 运行与边界

在 `client/` 中执行：

```sh
TAROCUB_LIVE_DEEPSEEK_MEDIA=1 TMPDIR=/tmp/t npx playwright test e2e/live-deepseek-media.spec.ts
TAROCUB_LIVE_DEEPSEEK_MEDIA=1 TMPDIR=/tmp/t npx playwright test --config playwright.webkit.config.ts e2e/live-deepseek-media.spec.ts
```

未设置开关时，两种浏览器均在启动 Hub／CLI 和生成图片之前跳过。定向回归
104 项通过；最终仓库检查 233 个测试文件、3676 项通过、1 项既有跳过，构建通过。
这是已配置默认模型的有限样本，不是所有模型、全部媒体或无失败保证，也不是
iOS/Android 原生容器、Windows/Linux 或公网中转验收。Kimi、Antigravity 的文件
交付仍有各自的兼容路径。修改需要运行主机使用更新的适配器代码；未重启生产机群，
未更换已安装客户端。前端未修改，r10 开发包仍适用于这项服务端修正。
