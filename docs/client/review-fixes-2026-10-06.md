# 双模型审查后的修复与体验改进

本轮承接 [新 Opus 5.5 xhigh 与新 Astra 独立审查](fresh-model-review-2026-10-06.md)。用户授权全部推进。本轮保持既有主机/中转拓扑和 TLS 设计，不加入应用层端到端加密，不重启业务 Bot 或服务。

## 对话与草稿

- 已确认的免打扰写入立即更新共享状态；旧读取不能覆盖新回执，刷新失败单独提示。结果不确定时只补读，不自动重发写入。
- 名称保存统一 trim，更新成功基线；请求期间继续输入的新版本保持不动。
- 命令和元数据操作同步防重复提交；命令结果不确定时复用消息 ID，已入队命令在同一面板内禁止重复发送。绑定、归档与重命名等待对应缓存回执。
- 已归档对话及其话题禁止重发，操作入口和执行逻辑均检查；转发到可用会话保持可用。
- 每个会话分别保留文字、附件、完成的录音、引用、链接预览选择和回复 Bot。发送只清理来源会话中没有继续编辑的内容，迟到的回执不会清空另一段会话或新文字。
- 附件与引用目前为工作区内存草稿，支持切换会话、切换已挂载主机；不承诺 App 退出、进程被系统终止或重载后恢复。附件区明确提示退出前发送，浏览器关闭时有未发送内容提示。文字仍保存在本地数据库。
- 对话管理采用 App 对话框和退出保护；手机开关恢复左右排列，整行可点，快捷操作保留触控高度。
- 手机消息“…”移到发送者/时间行，保持 44px 触控入口和长按操作。

## 设备与配对

- Opus 5.5 xhigh 实际实现设备与配对组件；Astra 实现对话管理并补设备边界测试；主线程核对调用链、整合、翻译、修正样式并验收。
- 「添加新设备」打开独立三步向导：分享已保存的主机连接信息 → 在已授权设备批准配对码 → 回新设备连接。向导显示当前主机身份，Escape/原生返回逐级返回，外层未保存的设备名保留。
- 批准/撤销明确显示进行中状态、目标与主机，同步锁阻止重复写入。响应丢失只重读并说明结果不确定，不自动重复一次性批准；不把连接按钮存在误当成成功。
- 列表展示最近连接、未知时间与同名设备 ID 短尾；撤销前展示配对时间和身份。新批准设备按服务端返回 deviceId 高亮并适当聚焦；用户开始其他操作后不抢焦点。
- 已确认授权与后续列表刷新失败分别显示；新增的中英文界面文案经过键与占位符检查。
- 手机向导采用整宽底部面板，底部操作保持可达；修复实际实拍发现的负边距横向溢出，深色步骤标记使用主题文字色。

## 开发预览

实际验收发现 Fast Refresh 复用已关闭的主机注册表/连接池，会短暂返回配对页；完整重载可恢复，持久数据未丢失。开发期通过模块 URL key 重建资源所有者，生产使用稳定 key，保留生命周期清理。独立回归覆盖直接模块与非刷新边界依赖更新，确认配对设备 ID、文字草稿与页面实例均保留；普通偏好更新不重挂载。不把浏览器模拟视为原生 App 验收。
