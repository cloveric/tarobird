# 2026-10-04 双重自审与修复记录

本轮由主代理独立检查，并实际调用 **Claude Opus 5.5 / xhigh** 进行源码审查；随后由 Opus 实现系统分享收件箱的定向修复，主代理检查改动并执行验证。不是把同一份结论换一个署名。

Opus 的首轮使用 Read / Glob / Grep，只读、不保留 CLI session、未接 MCP；第二轮仅对指定分享文件开放编辑。首轮读取的是共同工作目录，期间主代理有修复提交到文件，因此它不是不可变快照审查。初始与最终源码哈希、实际模型回执及测试记录一并保存。现有工作目录的大量历史改动保持原状，本轮未发布、部署或重启 Bot 服务。

后续 Android 多主机推送又进行了两轮实际 Opus 5.5 xhigh 审查，修复注册/删除顺序、升级迁移、失败注册恢复和推送方式切换。最终本地验证与仍开放事项见[多主机推送自审](unifiedpush-multiple-hosts.md)。这份后续记录不代替下面的连接、会话和系统分享验收。

| Opus 6 / P3 | 系统分享到群/话题没有明确选回复 Bot；已归档会话也可被选择；失败重试与收件箱异步刷新有歧义 | 过滤归档目标及归档群内话题，要求群组明确选择 Bot，持久化锁定目标、正文和 mentions；发送前再检查归档。旧版无 mentions 的锁定项保持原样并说明；慢旧列表不能恢复已丢弃项。浏览器与 Swift 存储检查通过，Android 真机仍待验。 |

| Opus 8 / P3 | 回到前台拆掉健康连接、打断 HTTP；网络恢复继续等待最长退避 | 健康连接先 ping；断线的前台恢复与 online 事件立即重连。上传/下载遇到 401 仍可强制重新认证。慢 HTTP 前台恢复及深度退避后的 online 回归通过。 |

- 全量根目录测试：232 个文件、3,646 通过、1 个既有跳过。随后构建发现新增测试的 `this` 缺类型标注；补上类型后单独重跑根构建，不改产品逻辑。原先失败日志保留，不把第一次 hook 记为整体成功。
- 针对性 Hub / 权限撤销 / 推送 / Gateway / capabilities：133 项通过，包含在更大全量覆盖中，不重复累计。
- 最终 Chromium / WebKit 连接与同步集合：各 50 项通过。
- 交互集合：Chromium 19 项通过，WebKit 17 项通过，覆盖分享、停止、引导、effort、命令和流式。Chromium 还包含 5,000 行渲染与空闲读取；之后空闲读取移入两浏览器的同步集合，不能据此把重复执行当成新功能覆盖。
- 根构建、客户端翻译检查 / TypeScript / Vite 构建通过。Swift 分享存储独立编译和执行通过。
- Android Gradle 编译尝试被当前环境无法定位 Java Runtime 阻断，未到源码编译阶段。本轮没有接受 SDK 许可，也没有生成 APK。

## 仍开放的审查项与产品缺口

1. Opus 提到的慢数据库或后台节流可能引发心跳误判，以及 Gateway 离线 journal 可能有写放大：目前只是低置信疑点，未复现，不列为已确认缺陷或已修复项。
2. 路由探测频率、流式事件触发的历史重读还有优化空间；需要持续负载、长会话与手机功耗测量，不能由本次短时空闲结果推断。
3. 后续多主机里程碑已接入正常 App 的统一主机导航、通知深链与分享目标，见正常界面验收（本地材料：`evidence/multiple-hosts-ui-2026-10-04.md`）。原生后台推送、安装包及两台实体电脑验收仍未完成，浏览器双 Hub 测试不能替代这些结果。
4. 此轮不是完整渗透测试或逐文件穷尽审查。Opus 实际读过和未覆盖的模块在其原始结论末尾逐项列出；原生安装包、生产部署等原计划验收门槛继续保留。
