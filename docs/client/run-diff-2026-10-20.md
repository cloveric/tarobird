# 本轮改动：按回复查看已保存的编辑记录

## 产品修正

普通 Bot 回复卡片的入口改为「本轮改动」；新主机在前台运行结束且记录持久化
成功后，把文件数与增删统计写入卡片。打开后先取文件列表，选择文件才返回代码。
不再以 Bot 默认工作区是不是 Git 仓库决定这条回复能否显示改动。

数据来自该消息、该 run 的已保存工具编辑回执，不读取当前文件，不执行 Git。
文件后来被修改、移动或删除，也不会改变已经保存的记录。没有保存的旧内容无法
补造：界面分别说明未记录、仍在执行、记录过期和部分记录；不会回退到磁盘当前值。

同一绝对路径可有多个修改步骤，每步单独查看。`+x −y` 是已捕获步骤的累计值，
不是文件最后的净变化；修改同一行两次会计两次。无法可靠计算时显示未知。
相对路径缺少当时 cwd，按步骤保留独立条目，避免把不同目录下的同名文件合并。
子任务的修改仍在运行过程里，不混入前台本轮统计；界面明确提示。

仍保留「当前工作区（实时）」作为独立次级入口及原 CLI 行为，便于查看当前
未提交修改和继续处理原有工作区批注。它的 Git 安全检查未放宽，也不自动初始化仓库。

## 引擎与格式

- Codex：原生 `fileChange` 的 update 是补丁，add/delete 是整侧文件内容；按
  原生 kind 转成带真实边界的 unified patch，空文件和无末尾换行正确计数。
- Claude：保留 structuredPatch 的 `@@` 坐标；已完成的 create 回执可保存整文件
  新增内容。缺少坐标的旧回执只展示现有片段，不编造行号。
- Kimi / DeepSeek：已有 diff 回执沿用；`oldText === null` 的新建文件转为新增
  补丁，避免旧实现制造一条空白删除。片段替换没有可靠起始位置时不允许行内批注。
- Antigravity 或任意引擎通过 shell/外部程序改文件但没提供结构化编辑回执时，
  本功能不能承诺完整捕获；明确显示未保存差异。未增加自动磁盘扫描或整仓快照。
- 历史裸文本保留为原始记录；只有行首增删符号的旧记录仅用于区分旧/新内容，统计为未知，避免整段替换夸大行数。
  不完整或重叠 hunk 不提供可信行号；凭据类路径和二进制只给元数据。

## 接口与权限

能力：`runs.changes.v1`。

```text
GET /api/messages/:messageId/changes?conversationId=...&botId=...[&runId=...]
GET /api/messages/:messageId/changes/file?conversationId=...&botId=...&runId=...&key=...&revision=...[&operation=SEQ-INDEX][&preview=1]
```

返回 `scope: recorded_run`，包含消息/对话/Bot/run 标识、修订令牌与完整性状态。
列表不返回代码；文件接口按不透明文件 key 和修改步骤读取。令牌变化返回 409，
要求刷新，不使用旧令牌读取悄悄变化的数据。

沿用已认证 owner、对话成员、消息可见性与设备撤销检查；校验消息确属该 Bot
及对话。读取完成后在同一个 DB 串行槽内再次检查身份/成员/删除状态并发送响应。
删除 Bot 的对话成员关系不抹掉仍可见的历史回复；读取不要求 Bot 正在线或仍有工作区。
路径仅是证据标签，可以是绝对路径；从不用于打开文件，因此不会引入路径穿越或
符号链接读取。凭据路径过滤不等于内容秘密扫描，普通源码中夹带的秘密不自动识别。

严格的 native-run v1 和 change v1 协议未扩展；卡片统计放在独立 extra 字段。
旧主机没有新能力时明确要求更新，不伪装为可用的实时工作区视图。

## 上限与性能

- 延用运行记录保留期 30 天、最多 2000 条前台记录、每条最多 20 个文件/32768
  字符的上游捕获上限。新界面不能恢复已经截掉的内容。
- 同时最多 2 个读取请求，整体 10 秒；超时/断连立即返回，底层排队工作结束前
  不释放配额，防止取消后反复堆积工作。每次读取最多 64 条后释放 DB 队列并让出事件循环，初尾修订清单不同则要求刷新。
  客户端只对幂等读取的 429/504 最多退避重试三次，取消时立即停止。
- 最多展示 200 个文件、每文件最多列出 200 步；超出明确提示。列表不预取客户端代码。
- 单步超过 1000 个差异行/段落或 200 KiB 时默认只给元数据，可显式看前 200 行。
- 单行最多 4096 字符；截断行不可批注。仅对小片段使用现有高亮，长代码虚拟化。
- 无新生产依赖，无编辑器。查看器和现有高亮懒加载；首屏仅增加入口与协议支持。
  此构建查看器独立 JS 为 40.70 kB（gzip 12.54 kB），CSS 8.10 kB（gzip 1.99 kB）。

## 桌面批注与可靠发送

桌面判定沿用 ADHD：宽度大于 760 且不是原生 Android/iOS。手机只读，桌面支持
单栏/左右对比、单行/Shift 连续多行批注。批注绑定消息、run、文件 key、具体步骤
和当时的旧/新行号，不跨步骤借用标记，不随代码后续移动重新定位。

原 v1 草稿、待发快照和 outbox 格式保留；另存与草稿同事务的来源索引。来源索引
固定绑定批注的路径、侧、行号和引用片段；缺失或被篡改时拒绝发送，不误认作工作区
批注。批注文字可以编辑，来源不可换绑。新旧草稿都能通过实时工作区入口访问。

「发送批注给 Bot」汇总当前对话/Bot 的所有待发批注为一条普通用户消息，附原消息、
run 和步骤，以及最多五行引用，提醒行号属于当时记录。使用既有持久队列和去重，
只有主机确认接受消息才清理该快照中未再编辑的批注；不是调用 send 就清空。
可选来源索引损坏不能让已收到的 ACK 事务回滚；剩余损坏草稿仍提示错误而非猜测。

旧客户端仍能读 v1 草稿并处理既有 ACK，但不了解新来源索引；不支持降级客户端
重新编辑/发送本轮批注。应先更新客户端。并发修改继续使用原有 CAS 和复制/重读
冲突处理，不宣称自动合并所有窗口里的修改。

## CLI

```sh
tarobot changes list CONVERSATION_ID --bot BOT_ID --message MESSAGE_ID --json
tarobot changes show CONVERSATION_ID --bot BOT_ID --message MESSAGE_ID --path FILE_KEY --json
tarobot changes show CONVERSATION_ID --bot BOT_ID --message MESSAGE_ID --path FILE_KEY --operation 3-0 --preview --json
```

一次性连接已运行的本机 Hub，不启动第二个 Hub，与 App 共用接口和鉴权。
不传 `--message` 时保留实时工作区语义。路径重名必须使用列表返回的 key。

## Opus 审阅发现及处理

开工前使用实际 Claude Code Opus 5.5、effort xhigh 独立审阅。已吸收：仅展示
结束后的证据、与当前工作区分开、保留 v1 协议、同文件分步骤、来源索引不可变、
ACK 独立于来源索引损坏、凭据路径过滤及旧草稿入口。按原需求保留大文件前 200 行
预览；相对路径按步骤区分，以免缺少 cwd 时错误合并。

代码审阅同样由实际 Opus 5.5 / xhigh 完成，原始请求和结果保存在私有任务目录。

| 发现 | 核实与处理 |
| --- | --- |
| ACP 整段 old/new 被误当作净行差异 | 确认；signed 旧片段计数改为未知，已知 whole-file 新建与 unified 补丁保留准确计数 |

| 文件数超过 200 无后续入口 | 原需求允许截断并提示；v1 保留上限，不宣称全部可访问，未扩大为分页功能 |

**保留的显示取舍：** Opus 建议总计显示已知部分的和（加“≥”或“部分”），并对
受保护路径仍算行数。Codex 保留未知 `—`，避免看起来像完整统计，也不为了计数
解析凭据内容。这不是权限缺陷；如 Owner 更偏好部分合计，可另改显示语义。
其余修订没有通过放宽授权、取消配额或隐瞒截断来解决问题。

交付前同一实际模型复审认为上述 12 项已修正或可以作为已披露边界接受，未发现
新的阻塞项，也接受未知总计采用 `—` 的保守取舍。额外的低优先级反馈随后修正：
ACP 新回执不再人为加一格前导空白；片段提示不再误称“旧记录”；超过 200 项的
引用不再反复要求无效刷新；草稿读取失败提示与保存失败区分。

三轮调用均在 Claude Code 参数中明确传入 `--model opus --effort xhigh`，完成结果
的 `modelUsage.canonicalModel` 为 `claude-opus-5-5`。最后一轮模型文字称不能确认
自身 effort；本地 CLI help 确认支持 xhigh，调用参数与退出成功是请求配置的证据，
不把模型自述或 token 数当成服务端强度证明。审阅只读，测试由 Codex 执行，不能用
审阅意见代替测试记录。

## Follow-up: return from file detail to the file list

The file-toolbar arrow already cleared the selected file, but native Back and
Escape went through `CreationDialog.close`, which closed the entire viewer.
This skipped the file list in both recorded-run and live-workspace views.

`CreationDialog` now accepts an optional `onBack` action for native Back and
Escape. Existing dialogs keep `close` as the default; busy-state checks, modal
precedence, focus handling, explicit close and backdrop behavior are unchanged.
Both diff viewers consume one Back step by clearing their selected file. From
the list, Back uses the existing close/flush path. Explicit X and backdrop clicks
still use that close path directly. Returning from live workspace restores its
parent recorded view before navigating further. File-read cancellation and
stale-response guards remain in their existing effects; returning to the list
does not discard review notes or send them.

This is client navigation only: CLI commands, Hub APIs, permissions, queue
semantics and stored review schemas are unchanged. No user-facing string or
translation key is added. Ordinary chat and ADHD use the same viewer components.

Validation at draft-PR preparation:

- Installed 1.0.96 assets reproduced the skipped-list defect for native Back and
  Escape in both viewers (four baseline checks).
- An isolated Chromium probe uses those assets with a small in-memory overlay
  equivalent to the three source changes, plus fake HTTP/cache data. It covers
  phone/desktop widths, native Back, Escape, explicit X, the file arrow, loading
  and failed reads, aborted late responses, nested live/recorded navigation,
  unsaved comments and the discard-confirmation modal: all 19 corrected-behavior
  checks passed. One initial assertion was corrected to wait for React to remove
  the confirmation dialog; the final full probe passed all 23 checks. No installed files,
  production conversations, host state or credentials are modified.
- Added 15 source Playwright cases across `run-diff-viewer.spec.ts` and
  `diff-viewer.spec.ts`; the existing unsaved-review test now covers Back through
  confirmation, detail and list without losing the draft. Both test files pass
  TypeScript syntax parsing.
- Full source Playwright execution (Chromium/WebKit), native-back/dialog/ADHD
  regressions, translation checks and client/root builds are pending external
  volume authorization. The isolated bundle probe is not a fresh source build or
  physical Android/iOS acceptance. This PR remains a draft, and no release or
  installed App has been updated. GitHub Actions has a separate known billing
  restriction and is not counted as passed.
