# ADHD 工作台入口与窗口边界

## 改动

- ADHD 侧栏底部原先只有一行勾选提示，缺少普通聊天的工作台和设置。现由两种模式共用 `WorkspaceFooter`：个人头像、工作台、设置，以及工作台内的文件中心、Skills 与 MCP、定时任务、运行状态、已归档对话、连接、我的网络和添加主机。
- `AdhdWorkspaceTools` 直接复用已有工具面板与连接，不创建隐藏聊天实例。关闭工具后保留原面板、草稿及正在运行的对话。需要离开面板的操作继续经过发送／上传／草稿保存检查。
- 工作台显示当前操作所属主机。有焦点面板时采用该面板的主机；尚未选择面板时采用进入 ADHD 前的活动主机。工具按主机注册身份隔离，双主机同名、同 ID 对话也不能互串。
- 工具弹层和菜单位于公共浮层，不被侧栏或面板的裁切区域挡住。“我的网络 → 此设备的连接 → 设置连接”也能在 ADHD 上方打开正确主机的连接设置。
- 面板网格隐藏可见滚动条，但保留滚轮、触控板及焦点导航带来的滚动。短窗口或多行面板仍能到达最后一行；侧栏底部设置固定保留。
- 删除底部“勾选加入，取消勾选移除”“面板组合仅保存在此设备”“草稿与任务沿用原对话”三处常驻说明及其空白占位。进行中的上传／发送操作入口移入顶部工具栏；底部空间交还给对话面板。布局保存失败仍有原来的错误提示。
- 截图中整个窗口右边和底部的粗滚动条，仍对应安装版 1.0.87 的整页溢出；此前侧栏相对定位修复已消除该溢出，详见 [阅读与滚动验证](adhd-reading-2026-10-17.md)。本次没有以全局 `overflow:hidden` 掩盖内容尺寸问题。

这是已有客户端工具的入口与布局调整，不增加主机能力、协议或权限；CLI 不需要新增命令。

## 验证范围

- 修复前新增浏览器用例在寻找 ADHD 设置入口时失败；修复后设置、全部工作台工具、关闭返回、嵌套网络连接设置都通过。
- 双主机相同对话 ID 场景，分别聚焦两边面板并打开文件中心，核对实际 HTTP 请求所属主机和界面主机名称。
- 强制 16px 常驻滚动条，缩到 1120×560，并打开五个面板、设为两列：整页横纵溢出不超过 1px，底部设置始终可见，网格仍可用滚轮滚到最后一个发送按钮。
- 最终测量结果：横纵溢出均为 0px；网格滚动条不可见；侧栏底部位于窗口内的 560px。Chromium 的 ADHD 全套 28 项通过；WebKit 的 ADHD、普通设置、侧栏调整、多主机工作台和新建回归共 46 项通过。
- 客户端翻译检查、类型检查、构建通过；完整源测试为 323 个文件、4,253 项通过，1 项已有跳过。
- 随后的底部文案精简通过客户端构建及 Chromium／WebKit 各 3 项既有回归（窗口边界与工具入口、流式阅读和输入位置、上传期间导航）；未为纯文案删除新增重复实现的测试。
- 浏览器验证和数据都使用隔离 Hub、临时 Bot 与临时目录；没有向真实对话发消息或修改生产主机状态。

测试输出保存在外置盘 `taro-tmp/tarobot-adhd-workspace-tools-20261017`。本次不是发版或本机 App 替换，也不能将浏览器结果称为已安装 Mac App 的验收。
