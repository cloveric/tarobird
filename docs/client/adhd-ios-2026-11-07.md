# ADHD board on iPad and an unfolded iPhone (2026-11-07)

Native iOS previously never showed the ADHD board. It now opens on iOS whenever
the window is desktop-wide (more than 760 CSS px). iPhone windows additionally
need a shorter side of at least 600 CSS px, so rotating an ordinary phone does
not expose the Duo board. iPad retains its width rule. See the
[scope follow-up](iphone-duo-scope-2026-11-10.md).

## What changes, and where

| | Desktop (Mac/Windows/web) | Android | iPad | Unfolded iPhone |
|---|---|---|---|---|
| ADHD entry | unchanged | unchanged (none) | shown | shown |
| Agent Bus | unchanged | unchanged (none) | hidden | hidden |
| Board layout | unchanged | — | same as desktop | see below |

- `adhdSupported` is unchanged and still gates Agent Bus and the diff viewers.
  The board uses the new `adhdBoardSupported`, which differs only for iOS.
- iPhone-only rules key off `adhdPhoneBoard` (iOS and an `iPhone` user agent;
  the iOS WebView runs in mobile content mode, so an iPad reports `iPad`) and
  the `data-adhd-device="phone"` attribute on the board shell:
  - the conversation list keeps its full width; panels may shrink to 260 px so
    two tall panels sit side by side; columns are capped at two and the
    「每行」 menu offers only 自动 / 2 列;
  - the Bot name and model mark are hidden in the list and panel headers;
    avatars and each reply's author still identify the Bot.
- Folding shut (the window becomes narrow or its shorter side drops below the expanded boundary) shows a short "two panels
  become one" animation for 450 ms. Unfolding again within that time keeps the
  board. Otherwise the board exits to 按对话 and opens the focused panel's
  conversation. While an upload, recording, layout save or draft write is in
  progress, the board stays mounted and shows the compact-layout notice. It
  exits automatically after those operations and draft writes settle; failed
  draft saves retain the normal explicit discard guard. Unfolding later does not re-enter the board;
  its panels are remembered for the next entry. iPad keeps the existing
  widen-window screen when Split View narrows it.

## Verification

- `tests/adhd-board-state.test.ts`: every platform × width answer for desktop
  and Android equals the previous rule; iPhone/iPad/Mac/Android user agents;
  column cap and the 260 px minimum.
- `client/e2e/adhd-ios-phone.spec.ts`: the real App and Hub with only the
  board-state platform checks answered as iOS: two tall panels at 880 and
  1000 px, no horizontal overflow, two-column menu, hidden marks, no Agent Bus;
  folding with an upload in flight keeps its panes mounted, then opens the
  focused conversation and stores 按对话 after upload completes; unfolding
  in time keeps the board.
- Existing ADHD, Agent Bus and diff-viewer browser suites unchanged.
- These are browser runs, not an installed App on an iPad or iPhone Duo.
