# 手机设置导航与启动精修 · 2026-10-04

本轮由实际 **Claude Opus 5.5、xhigh** 查看修改前截图、设计并编辑设置导航；父代理审查实现、修复回归问题并完成实际渲染和交互验证。Opus 调用正常完成（756,049 ms、92 turns）；其[原始交接报告](settings-nav-opus55-2026-10-04.md)保留了当时“尚未验证”的范围，以下为后续验收。

## 用户可见变化

- 手机设置采用与聊天一致的返回导航：当前页名称在顶栏。从“我的”进入的分类逐级返回；从聊天直接打开连接页，返回聊天。桌面仍是分类侧栏和右上角关闭。
- 返回、Escape、Android Back 共用层级规则。线路草稿跨分类保留；最终退出才询问放弃。扫码和确认框优先关闭。忙碌请求继续保护退出。
- 手机顶栏、语言选择、字号滑块和危险操作至少 44px；英文 320px 下字号数值与滑块同行。触屏宽屏另保留 44px 控件规则。
- 手机空间足够且空闲时，协作入口带可见“协作”标签；小于等于 360px 或回复中保持图标，原可访问名称和行为不变。
- 设置打开沿用 240ms 过渡；减少动效模式为 `none / 0s`，没有新增装饰动画。

## 父代理修复与真实失败记录

1. **即时返回丢失线路草稿保护**：编辑后的 dirty/busy 原来通过被动 effect 告知设置页。Chromium 的快速 Back 和 Escape 两个用例实际退出而没有确认。改为 layout effect，与编辑一起提交退出守卫，保留不加等待的快速返回检查。
2. **横竖屏焦点**：保留同一个顶栏按钮，避免跨 760px 重挂载。手机首页在桌面布局会卸载，因此设置退出时还需在同一 workspace 找回重新挂载的入口。采用稳定标记，独立于语言，不跳到其他主机。
3. **英文 320px 字号数值换行**：实际截图发现 14px 仍另起一行；修正该行 flex 收缩和间距后，截图与几何断言均通过。
4. **WebKit 加载失败不能重试**：动态聊天包在 modulepreload 失败后，即使刷新也没有再次发出脚本请求；HTTP 503 与 abort 都重现。禁用预加载、交由单次 import 拉取后，两种内核的 HTTP 故障→重试→保留设备身份和历史路径通过。没有掩盖失败或重新配对。
5. 初次新增旋转用例证明手机首页入口卸载后无法归还焦点；上述稳定入口恢复后通过。另一个测试在设置视口之后、界面尚未响应断点时立即发 Back，现先等桌面入口实际可见再验证桌面不拦截原生 Back。

## 启动拆分

新增 `Bootstrap.tsx` 和 `Pairing.tsx`，首次配对不加载聊天、卡片、设置及 Markdown 解析器。连接后才加载 `App.tsx` 的 Workspace，多个主机复用模块但各自保持状态。离线 worker 仍缓存完整资源，原生壳仍打包全部文件。

五个空缓存浏览器上下文实测：首屏 JavaScript 从上一版 **899,834 B** 降为 **614,387 B**，约 **31.7%**。Chromium 中位 105ms、最大 106.5ms；WebKit 中位 101ms、最大 104ms。该测量禁用 service worker 后台预缓存，只代表本机浏览器首屏工作量，不代表下载总量、原生冷启动、移动网络或常驻内存。
