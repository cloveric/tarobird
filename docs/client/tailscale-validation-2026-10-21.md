## 已实现

- 手机、桌面和网页的「连接 → 编辑线路」独立呈现局域网、Tailscale、中转，保存时保留其他线路和每个地址自己的 CA。
- 每主机最多 4 个并行健康探测，最多保存 4 条直连/Tailscale 与 8 条中转。首次 200 ms 比较窗口；后续结合延迟、失败、握手与已观测文件吞吐，使用稳定观察和驻留时间，在空闲时切换。只保留一条业务连接。
- 主机既有 LAN/Tailscale 加密入口开启后，通过 `host-routes.v1` 向已认证 owner 设备同步地址。采用按来源的三方合并、手工线路保留、身份事务与并发配置检查。
- 自动 LAN 更新需要同一网卡来源；出现过多网卡歧义时，重启或 Wi-Fi 断开也不能让虚拟网卡自动成为原局域网的替代。歧义需主机所有者明确选择。
- 保持旧签名目录、QR v1 和主机持久化格式的单直连限制。QR 优先当前在线直连；额外直连在配对后同步。旧主机不具备新能力时不尝试新接口。
- CLI 增加 `tarobot network local --json`；可选 `--tailscale` 只读检查本机 Tailscale 状态，固定参数、3 秒超时、256 KiB 输出上限，不列出其他设备。

## 实现取舍与剩余验收

1. **候选预认证取舍**：Issue 曾要求候选先全部完成设备授权再排序；本实现只将健康探测用于候选顺序，备用线路显示“可达 · 待连接验证”，新线路在完整主机验证与设备认证通过后才成为业务线路。没有每轮对所有候选提前登录，避免多次系统密钥读取。此差异供 Owner 在 PR 中审阅，未将其写成原验收已满足。
2. **物理设备未验收**：本机 Tailscale 为 Stopped，没有连接真实手机。手机蜂窝网、Wi-Fi 切换、锁屏、睡眠唤醒、真实 P2P/DERP、ACL 拒绝与长期持续连接尚待真实验收；测试没有开启 VPN 或改变网络配置。
3. **WebKit 阻塞**：未修改的基线页面就在 `page.goto`、发出页面请求前卡住，当前环境无法完成 WebKit 验收。Chromium 结果不能替代 iOS/WebKit。
4. **原生边界**：未运行 macOS WebView、Rust/Android/iOS 原生传输审计或安装包升级。原生取消探测、同 CA 证书更新、关闭帧经中转改写仍需验收；主动优选目前有逻辑单测，浏览器场景主要验证故障回退及稳定驻留。
5. **兼容与保守行为**：member 设备不自动读取 owner 线路；所有旧线路失效时需要同主机二维码恢复；多标签页配置冲突可能需要整页刷新；旧 App 不应编辑新的多直连本地配置；双来源保守保留的旧手工线路可能需要在上限提示后整理。
6. **CI**：GitHub Actions 未作为通过依据；仓库此前受账单/额度限制，以本地结果为准，PR 上的实际检查状态另行核对。

这些限制没有通过放宽 TLS/身份验证、重建主机或重复发送请求解决。没有将 Issue #53 关闭为已完成，也没有据模拟结果宣称实际手机网络可靠性已经达标。
