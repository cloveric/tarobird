# 手机原生连接监听恢复

本轮继续 TLS 原生连接完善，不增加应用层端到端加密，也不改变 Hub 公钥、证书、
设备配对或中转信任策略。Mac 当前锁屏，Android SDK／许可和完整 Xcode 尚未就绪；
没有安装 App、部署 Hub 或修改系统证书。

## 复现与修复

`client/src/native-network.ts` 的 `mobileNetwork` 原先永久缓存
`addListener` 的 Promise。如果注册拒绝，后续每次连接都会拿到同一个失败结果，
即使桥接已恢复也不会再尝试注册。受控测试在两个主机同时连接、首次注册失败后，
再次连接仍全部失败，且只发生过一次注册。

修复仅清除失败的注册缓存。当前请求照常拒绝；之后的重连重新注册，两个主机
并发时仍共享一次注册。成功注册继续复用，iOS 的页面 token 和消息通道隔离不变。
持续失败时不会打开 socket，也没有 WebView 网络回退或自动重放聊天请求。

实际 Opus 5.5 xhigh 静态复核提出：注册可能先留下回调再报错。父代理据此增加
回调失效标记，覆盖同步抛错和异步拒绝；旧回调不能重复投递消息，也不能通过
迟到的 close 删除新连接的通道。最终补丁由父代理完成回归，没有声称再经 Opus
二次签署。

这是桥接适配器的异常恢复，不表示手机上已经观察到瞬时注册失败。
现有 Capacitor SDK 的内部回调注册行为还需要真机验证；此改动只处理返回 Promise
明确拒绝的情况，不把一直不返回或原生静默丢失监听当作已修复。
