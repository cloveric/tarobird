## 实现范围

- `client/src-tauri/src/transport/core.rs`：先由平台验证器检查普通 CA、有效期和
  主机名，再验证 Hub 身份对本端实际 TLS 叶证书、此次随机数的签名。后续连接
  固定叶证书 DER SHA-256。TLS 会话恢复关闭；rustls 不接受重新协商。
- 证明请求不携带设备身份、访问令牌或用户内容。验证结果按线路和 Hub 公钥
  隔离，缓存最长五分钟；证书切换失败后清除缓存，下一次连接取得新证明。
  敏感 POST 不自动重放。普通 HTTP 和 WebSocket 升级使用同一固定证书的客户端。
- `transport/mod.rs`：原生分配操作 ID 后才允许开始请求；按窗口绑定、取消和
  页面重载清理。入口模块启动时只领取一次页面凭证；新页面领取会作废同窗口
  旧凭证并取消旧请求。分配与作废共用锁序，旧凭证不能在重载后重新分配。
  pagehide 取消前端工作，历史缓存恢复时重载，窗口销毁时清理原生操作。
  HTTP 拉取按 256 KiB IPC 块交付，上传每次最多 8 MiB；WebSocket
  限制帧大小、输出队列及未确认事件数量。请求禁止跨源路径和重定向。
- `client/src/transport.ts`：配对、健康探测、聊天、普通 API、头像和附件都走
  原生 IPC。失败不回退 WebView。每个源最多四个数据请求，整体十二个；健康
  探测另有名额，Rust 的 HTTP 与 Socket 配额分开。取消排队不会启动迟到的 POST。
  关闭消息与命令拒绝之间的竞态不会直接覆盖真实关闭码。未读取的响应在
  30 秒后释放队列；Channel 回调异常不阻塞后续事件。接收方未确认消息时仍能
  发送关闭帧；只有实际对端关闭回执才能标记 clean，入队成功不冒充关闭成功。
- 原生首次连接与重连在健康备用线路验证完成后给优先线路 200 ms 余量，不再
  等待黑洞主线路的全部六秒探测超时；背景选路仍等待完整结果。
- macOS 14+ 桌面使用 `backgroundThrottling: disabled`，避免隐藏窗口后暂停
  读取与事件回执。真实隐藏 WebView 对照出现大文件停滞；禁用暂停后完成。
  该配置在 macOS 13、Windows/Linux 上不能据此保证相同行为，仍需对应验收。
- 桌面首次 HTTPS 配对要求可信二维码或手动主机公钥；已信任设备可展示和复制
  公钥。桌面内嵌主机的 loopback 路径也使用 HTTP，不限于调试：依赖同一
  本机用户环境、主机身份及已认证的签名协议，不提供该段 TLS 加密；不能把此
  路径扩展到远程地址或当作不可信本地进程隔离。历史配对不被静默删除，但不能据此
  证明旧版首次配对时未遭替换。桌面 CSP 禁止 WebView 任意 HTTPS/WSS 外连。

## 复核与验证

实际 `claude-opus-5-5 --effort xhigh` 完成静态复核。其发现的
`net_socket_send` 参数名 `data` / Rust `text` 不一致已修正；补充了按 Rust 合约
检查参数的 IPC 测试。还修正晚到的 send/ack 拒绝、请求配额、Channel 分配前取消、
Ping 超时、Close 回送和默认 Content-Type。原生读取和取消仍保留严格生命周期。

复核中“20 分钟 Socket 上限必然打断长会话”是有条件担忧：当前 Hub 令牌为
15 分钟，客户端提前 30 秒续期；保留原生上限作为兜底。移动端是 Capacitor，
不是 Tauri。当前 Tauri Channel SDK 自带索引排序；页面重载已接入 `reset()`。
以上不能把条件建议记成已复现缺陷。

后续两次真实 Opus 5.5 xhigh 静态复核指出回调异常、未消费响应、关闭回执和
旧页面凭证的问题，已按上文修正。最后一次报告确认 TLS 证明与固定证书链路
没有发现新的可操作问题；它仍是静态意见，不是运行验收，也未复核之后的全部
测试程序改动。20 分钟兜底上限仍由现有 15 分钟令牌续期提前覆盖；不改变此策略。

隔离 Rust 测试实际使用两张由同一测试 CA 签发的不同证书，覆盖普通信任和主机名
检查、真实 Hub 证明、另一有效证书的透明转发拒绝、证明后切换证书对 HTTP/WS 的
拒绝、合法轮换、8 MiB 上传、512 MiB 流式下载哈希和升级后空闲十秒的聊天连接。
不向系统安装测试 CA。测试进程及临时密钥有独立生命周期。

前端 IPC 测试覆盖不回退、配对前信任要求、分配期间取消、按需读取、迟到数据、
关闭前分配、发送顺序、迟到关闭回执以及健康探测预留。它使用接口替身，不能
称为真实 WebView 到 Rust 的端到端验收。浏览器回归另覆盖配对、撤销、双线路、
上传、续传、跨主机状态、停止和原有手机长按/文件操作。

真实原生验证另由 `client/scripts/native-transport-audit.mjs` 执行：显式启用
`native-transport-audit` feature 才编译独立测试程序，正常发布不包含该程序。
它复用生产传输源码和桌面后台策略，在隐藏、无痕 WebView 内执行真实 Channel、
HTTP 流和 WebSocket；冒用中转只收到无凭证证明探测，敏感请求计数为零。
8 MiB 上传回显和 512 MiB 下载均核对内容，单次 IPC 读取不超过 256 KiB。
这是本机合成数据正确性验证，耗时不能当作公网 VPS 网速，也没有完成峰值内存验收。

回归发现手机发送按钮会在另一设备停止 Bot 时从宽胶囊缩成圆形。现在手机统一
保持 44px 圆形命中区域；排队语义仍在文本及提示中，避免手指按住时按钮移动。
文件操作测试的桌面替身已加入新 IPC 网络接口，仍只连接真实隔离 loopback Hub；
没有为通过旧替身而恢复不安全的网络回退。

## 未关闭的边界

1. 已安装 macOS App、系统 CA、Windows WebView 和完整产品交互的攻击验收；
   Android 后续源码实现已有独立 JVM 验证，iOS 后续源码实现已有隔离 Foundation 验证，尚非 iPhone 验收。
   上述原生验证使用独立测试程序；后续 r26 开发包另有构建与完整性收据，
   仍未安装或替换用户的 App。
2. 原生配对、流式停止、双线路切换、大文件续传、峰值内存和窗口生命周期需要
   同一实际客户端串联验收。Rust 大文件正确性不等于原生 App 内存验收。
3. Hub TLS 私钥仍必须独占；共享同一 TLS 私钥的代理在此机制下无法区分。
   浏览器无法读取实际对端证书，且被替换的 SPA 本身也不可信；该边界仍存在，
   不以浏览器预览测试替代原生 App 安全验收，也不在本阶段扩展应用层加密。

不将局部测试通过当作整个计划完成，也不改变部署、签名或真机测试的待办状态。
