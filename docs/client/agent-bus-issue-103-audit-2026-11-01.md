# Agent Bus independent audit — Issue #103

The audit used main `bbcced125b65513de3a8ea54c31868e9e81ec52c` and covered the local Bus, shared workflows, Hub, Gateway, CLI and App. Kimi's subscription rejected the requested review; the owner explicitly selected Claude Opus 5.5 instead. Opus independently reported findings before implementation, then reviewed the root-authored fixes. Root independently reviewed and reproduced Opus's Crew fix. The findings were also posted to [Issue #103](https://github.com/cloveric/tarobot/issues/103) before the four separate fix PRs.

## Confirmed findings and repairs

| Finding | Reproduction and observed result | Expected result and repair | PR |
| --- | --- | --- | --- |
| F-01, low–medium: saved goals misclassified as queue barriers | Keep an ordinary message running, queue another message, then start a Bus with a `/review` or `/stop` goal. Claim dispatched the waiting messages early; moving another message across that goal was refused despite the queue snapshot allowing it. | Durable Bus metadata distinguishes task goals from control commands. Ordinary messages retain queue controls; real slash commands remain barriers. This was early dispatch, not evidence of concurrent or duplicate model execution. | [#106](https://github.com/cloveric/tarobot/pull/106) |
| F-02, low–medium: missing Crew member preflight | Start Agent Bus Crew without the required member grants, including through CLI or after grants change while work waits. Crew called the coordinator once to decompose the goal, then all delegation failed. | Reject invalid remote roles before an engine turn or Crew record. Local coordinator roles and ordinary saved Crew/custom delegates retain their existing behavior; no grants are added. | [#109](https://github.com/cloveric/tarobot/pull/109) |
| F-03, low–medium: goals enter native engine command paths | Send a slash-prefixed goal without a separate slot instruction. The member/coordinator prompt started with `/compact` or another slash command. Kimi and DeepSeek adapters interpret these as native commands. | Mark these saved goals as task text at the shared boundary while retaining the original text and ordinary user command behavior. Verified at adapter boundaries, not against paid Kimi/Claude services. | [#107](https://github.com/cloveric/tarobot/pull/107) |
| F-04, low: transient capacity refusal fails immediately | Hold eight requests at one member, then submit a ninth from another workflow. The server correctly refused admission but the client immediately failed with poor busy feedback. | Retry only the intended member's explicit HTTP 503, structured retryable `server_busy`, up to three times at 200/400/800 ms. Preserve the absolute deadline, cancellation and current permissions. Unknown results, HTTP 200 engine failures, disconnects and timeouts are never resent. This handles brief bursts, not sustained saturation. | [#108](https://github.com/cloveric/tarobot/pull/108) |

Each issue has its own regression and implementation note linked from its PR. Root verified the original failures before the fixes. Opus's final F-01, F-03 and F-04 diff reviews found no blockers; root's independent F-02 review and desired-behavior probe passed.

All four PRs are merged. The source/native/secret checks passed on #106, #108 and #109. The first #107 source run had one failure in an unchanged TLS network-recovery fixture; four local cases at the same SHA passed. Independent forced-port probes confirmed an existing fixture race mechanism, without identifying the original CI port occupant. Its failed job was retried; that retry is not claimed green. Test-only hardening now verifies a listener has actually bound before probing, with four bounded port attempts and explicit exhaustion. Opus and root separately passed the resulting eight network tests. The [broader audit](post-1.0.123-audit-2026-11-01.md) records this CI boundary separately from the Bus repairs.

## Verification

- The existing core baseline passed 395 distinct cases, including two real HTTP waits longer than five minutes. This total comprises 336 core, 57 workflow and two long-wait cases, with two unrelated skips recorded separately.
- Isolated real Hub/Gateway/local Bus and scripted engines covered normal completion, offline Stop followed by Host restart, replay without another execution, and matching App/CLI terminal states. Production Host and real Bot sessions were untouched.
- F-01 passed 235 focused cases and Opus's five queue probes; two desired-behavior probes fail on the original code. F-03 passed 67 instruction/Gateway cases, with three new regressions failing on the original code. F-04 passed 168 capacity/transport/display/delegation cases; its real HTTP overflow case executes exactly once after capacity is released. These counts overlap the baseline and are not added together.
- F-02 passed 11 Crew cases. Adjacent suites initially passed 212/213; the unchanged registry test hit its five-second timeout under load and passed alone. Production TypeScript and standalone build passed. Full test-tree TypeScript has 154 errors matching the untouched baseline; they are not presented as fixed.
- All four fixes together passed 139 integrated tests and the standalone build (481 modules).
- Chromium's initial 78-scenario run passed 65 and failed 13; WebKit's ten real-Hub scenarios initially passed nine. Failure traces were retained and reviewed. Three stale assertions contradicted the owner's current menu/motion choices, and test timing included initial loading and a short-transition race. After targeted test maintenance and reruns, all 78 Chromium and ten WebKit scenarios have passing evidence across the baseline and focused runs. This is not a claim that the initial full runs passed. See [UI test contracts](agent-bus-ui-test-contracts-2026-11-01.md).

The UI first-read hypothesis was rejected: Opus found one initial read whose result was applied. The measured delay included lazy loading, history synchronization and main-thread work during concurrent tests. No speculative production re-read loop was added.

## Observations and limits

“Cancelled” versus “stopped” wording remains a minor consistency observation. Incomplete stage display after a Hub event rejection remains an unconfirmed static concern, not a reproduced defect. Stop/claim races, replay duplication and cross-conversation context leaks were investigated without confirming a new bug. Existing uncertain-result and offline-stop boundaries remain intact.

Evidence lives under `taro-tmp.noindex/agent-bus-103-20261101`, including Opus's independent report, per-fix reviews, red/green probes, restart receipts, UI traces and `integrated-tests.log` / `integrated-build.log`. The work does not establish real paid-model, physical mobile-device or installed-App acceptance and does not publish a release.
