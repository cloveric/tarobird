# 手机远程连接：让 Agent 配置，或手动部署

[English](remote-access.en.md) · [手动部署命令](vps-relay-manual.zh-CN.md) · [返回首页](../../README.zh-CN.md)

手机在外面用流量连接家里的 Bot，需要先建立可达线路。只在 App 中填写
VPS 地址不会安装中转，也不会让手机自动获得使用权限。

## 先选择运行位置

| 需求 | 方式 | 需要保持在线 |
| --- | --- | --- |
| 使用电脑上已有的 Bot、文件、CLI 登录和聊天记录 | **电脑运行 Bot，VPS 做中转**；本文默认方案 | 电脑和 VPS |
| 不想维护 VPS，可以在电脑和手机使用 Tailscale | 启用 Tailscale 线路，并完成 TaroBot 配对 | 电脑和两端 Tailscale |
| 电脑关机后 Bot 也要继续工作 | [直接在 VPS 上运行完整 Hub 和 Bot](host-deployment.md) | VPS；引擎登录、文件、MCP 需在 VPS 配置 |

已有电脑主机时，添加中转应保留原 Hub 身份和数据库。重新在 VPS 创建一个
Hub 会得到另一台独立主机，不会自动出现电脑上的 Bot 或历史。

## 方式一：让有终端和 SSH 能力的 Agent 配置

适合能访问运行主机的 Codex、Claude Code 等 Agent。Agent 需要本地文件与
终端权限、仓库访问权限，以及你授权使用的 VPS SSH 登录；普通聊天窗口不能
仅凭一句话完成部署。以下说明可直接复制，再替换尖括号中的内容。

```text
请为 TaroBot 配置手机通过 VPS 连接现有电脑主机的线路，并实际验证连通。

仓库：https://github.com/cloveric/tarobird
运行 Bot 的电脑系统：<macOS / Linux / Windows>
TaroBot 安装位置或源码目录：<路径>
现有 Hub 状态目录：<路径；不确定时请先从正在运行的主机确认>
VPS SSH 别名：<例如 tarobot-relay>
SSH 私钥的本地路径：<只给路径，不粘贴私钥内容>
VPS 系统与公网地址：<系统、IPv4>
VPS 已有服务：<网站、游戏等；不确定时先检查>
入口选择：<已有域名，或公网 IPv4 + 受信任的 IP 证书>

先读 AGENTS.md、docs/entrypoint-map.md、docs/client/remote-access.md、
docs/client/vps-relay-manual.md 和 docs/client/relay-deployment.md。
我要保留电脑上原来的 Bot、文件、聊天和设备配对，VPS 只做中转。

在已授权范围内完成部署：
1. 确认现有 Hub 状态目录、身份、运行状态和备份；盘点 VPS 端口及已有服务。
   使用已核验的 SSH 主机密钥，不关闭主机密钥校验。
2. 选择空闲公网 HTTPS 与 mTLS 隧道端口。共享 VPS 不运行专用服务器防火墙
   安装器，不覆盖现有网站、证书或服务，不把本地管理接口暴露到公网。
3. 生成独立的隧道凭据，给原 Hub 增加 loopback TLS 监听与出站中转配置。
   业务 HTTPS 私钥、Hub 身份私钥、API 密钥、聊天数据库留在原主机。
4. 配置可信域名或 IP 证书、自动续期、主机接收新证书并安全加载的完整流程；
   配置中转开机自启与故障重启。不要把一次签发当成续期已经完成。
5. 验证公网 HTTPS、实际 TLS 证书绑定的 Hub 身份、已配对设备认证、历史同步、
   未授权访问拒绝，以及中转重启后的恢复；不要向真实 Bot 发测试任务。
6. 给我手机实际填写的 HTTPS 地址、准确的设置路径、必须保持在线的机器、
   已验证项和仍需我在真机验证的项目。不得只以 /health 成功宣称全部完成。

不要把密钥、真实服务器配置、API 凭据或聊天数据提交到 GitHub；只在需要时
向我询问缺少的信息。部署目标是 TaroBot 远程连接，不是部署其他应用。
```

如果 VPS 上已有服务，Agent 应按实际环境追加中转。仓库自带
`hub relay deploy` 管理专用服务器的防火墙，不能直接套用到共享服务器。

## 方式二：自己手动配置

[手动教程](vps-relay-manual.zh-CN.md)提供按执行机器标明的命令和配置，顺序是：

1. 核对 SSH、原主机状态目录和端口；在私有目录保存凭据。
2. 在原主机生成 mTLS CA、隧道客户端／服务端证书和业务 HTTPS 私钥。
3. 在 VPS 签发匹配域名或 IP 的业务证书；只传 CSR，不上传业务私钥。
4. 安装独立中转服务，放行选定端口；保留已有服务和防火墙策略。
5. 向原 Hub 配置追加监听与出站隧道，空闲时重启同一台主机。
6. 设置证书续期和加载，再在手机添加线路并完成验收。

命令中的 `192.0.2.10`、`/absolute/path/...` 等均是示例，不能直接作为连接地址。
手动教程当前面向 macOS/Linux 运行主机和 Debian/Ubuntu VPS；Windows 原生服务
生命周期与定时任务需要按 Windows 环境配置，不能直接粘贴 systemd/launchd 模板。

## 在运行 Bot 的电脑上设置中转入口

本机也可以管理自己的 VPS 地址，无需先换到手机或另一台电脑：

1. 打开 **连接 → 本机 VPS 中转 → 添加 VPS 中转**。
2. 填写已部署的公网 HTTPS 入口，点击 **验证并保存中转**。
3. 保存前会检查 HTTPS 和主机身份；入口属于别的主机或无法验证时不会保存。
4. 已保存的中转可继续编辑、排序和移除，也可生成供新设备配对的连接码。

本机仍通过原有本地线路连接，不绕行 VPS。这里保存的是主机对外公布的地址，
不会安装云端程序、配置隧道、签发证书或放行端口。尚未部署的入口需先完成
前文部署步骤。网络中自动管理的线路会在同步后更新；单独配对或手动修改过
线路的设备仍需按下一节添加地址。

以上本机入口为当前源码新增，尚未发布；1.0.94 及之前的本机界面仍只有
LAN/Tailscale 入口。[实现和验证边界](local-vps-settings-2026-10-19.md)。

## 手机怎么填

**已经与这台电脑配对：**

当前独立「连接」页按以下步骤操作；较早版本从「我的 → 设置 → 连接」进入。

1. 打开 **我的 → 连接 → 编辑线路**；「连接」位于「我的网络」上方。
2. 保留已有直连地址。只有中转线路时，直连地址可留空；不再选择部署方式。
3. 点 **添加中转**，填写部署后得到的 **中转地址**，例如
   `https://192.0.2.10:8443`，再点 **保存线路**。
4. 等待“已连接”，确认当前线路名称；关闭 Wi-Fi 后验证手机流量连接。

线路按设备保存，电脑添加线路不会自动改写已配对手机的线路。
添加中转无需删除主机或重新配对；手机也不需要 SSH 私钥或引擎 API 密钥。
多台主机可共用一台云服务器，但每台主机都需要独立的中转入口和隧道。不能把指向 example-mac 的入口直接用作另一台主机的备用线路。

**第一次连接：**先在原主机的 **设置 → 设备与安全 → 添加新设备**获取可信
Hub 身份／限时连接二维码（有效期 5 分钟）。新设备需升级到支持限时邀请的 App，扫描或粘贴完整连接信息。在手机配对界面使用已部署的公网 HTTPS 地址及同一个
Hub 身份和有效邀请，发起配对后，由主机或已授权设备确认八位配对码。二维码如果仍包含
局域网地址，应先在配对表单更新地址；不能从一个未经核验的公网 `/health`
响应直接把公钥当作可信身份。登录 Tailscale 不会自动完成 TaroBot 配对。

## 地址、安全与排障

- **入口地址不是密码。** 陌生人可能发现服务地址，但首次配对还需有效的限时邀请；获得授权仍需要
  你批准和设备签名。不要批准不认识的设备；保护 SSH 私钥和已配对设备。
- **8443 和 7443 不同。** 本文示例中 8443 是手机 HTTPS 入口；7443 仅供主机
  建立 mTLS 隧道；22 是 SSH。以你实际部署的端口为准。
- **`connected: false`：**中转已启动，但原主机隧道还没连上，检查主机在线状态、
  隧道端口、证书名称和客户端指纹。
- **证书错误：**检查入口 IP／域名、证书有效期、完整链和手机时间；不要用关闭
  TLS 校验代替修复。若已过期，检查 VPS 签发与主机加载两个环节。
- **主机身份不匹配：**线路连到了其他 Hub，纠正地址，不删除原身份来强行连接。
- **在家可用、流量不可用：**检查腾讯云／其他云厂商的入站规则和操作系统防火墙，
  以及 VPS 是否真正建立了到主机的隧道。不要把公网入口填写成 `127.0.0.1`。
- **电脑停机：**中转不能代替电脑运行 Bot，也不保存离线聊天或文件副本。

公网入口仍可能遭受流量攻击或软件漏洞利用。现有设备认证和限流不等于绝对安全。
部署记录需区分“服务启动”“公网认证与同步通过”“手机真机通过”，参见
[已完成的公网 IP 中转验证](ip-relay-2026-10-12.md)。
