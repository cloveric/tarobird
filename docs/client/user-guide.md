# TaroCub 客户端使用说明

当前为开发版本。已实现功能和仍待验收项目请看[验收记录](implementation-status.md)。正式发布、手机签名、生产外网配置和真实手机推送尚未验收。

Bot、群、session、长期记忆、workspace 和 system prompt 的准确关系见[会话与记忆说明](session-model.md)。电脑侧栏以 Bot 和群为主体；点 Bot 返回已有私聊，旁边加号才创建新对话。使用鼠标时，将指针移到 Bot 行上会显示加号；键盘聚焦和触屏也可以操作。新群沿用 Bot 设置和工作区，默认不带旧会话历史。对话设置新增“切断恢复的会话”，沿用 `/detach`，不会删除文件记忆。

发送 `/help` 可查看 App 使用说明和当前引擎对应的命令；`/config` 打开 Bot 配置。切换引擎会清理不兼容的会话绑定，之后到「运行状态」安排该 Bot 空闲后重启。命令菜单随保存的引擎配置更新，但运行中的进程仍需重启才切换引擎。

群组和话题中，可在 `/config` 的“群聊模式”选择“全量监听”或“仅 @”，也可发送 `/group all`、`/group at`、`/group status`。这只影响当前 Bot 在当前群组或话题的回复规则；其他 Bot、话题和飞书群不受影响。设备访问授权仍在「设置 → 设备与安全」中管理。

群回复模式控制普通消息；TaroCub 已识别的命令仍可直接使用。输入框“让谁回复”选中的 Bot 决定消息接收者，多 Bot 群中先选好要配置的 Bot。

“运行状态”的用量是实例累计记录，包括切换引擎前留下的数据。未上报的 token 或费用会显示未知，并提示数据缺口；未知不代表没有消耗。Kimi 当前不提供逐轮 token／费用，Codex、DeepSeek 和 Antigravity 不提供美元费用，美元预算不能据此约束它们的消耗。

需要备份整套聊天和 Bot 时，电脑端可执行 `hub backup --full`，恢复使用 `hub restore`，具体步骤见[备份与恢复说明](operations.md#backup-and-export)。完整备份要求 Hub 和它管理的 Bot 已停止，包含设备信任、附件、Bot 配置、session 和默认工作目录；普通每日备份仍只保存数据库。恢复到原来的 Hub 路径，且不会覆盖现有目录。外部项目、引擎登录和原生会话文件需另外保留，命令会列出能识别的外部依赖。

## 手机和电脑的入口

手机使用独立的 IM 布局，进入聊天后显示整屏消息，左上角返回首页。底部三个入口分别是：

- **消息**：最近私聊和群，支持“全部 / 未读 / 群组”筛选；群内话题归在所属群里。顶部搜索先匹配会话、群、话题和 Bot 名称，历史正文另点“搜索历史消息”。
- **Bot**：按主机查看助手。有过私聊时，点 Bot 回到其最近的私聊；没有私聊时点旁边“新对话”开始。旁边的加号创建独立新对话，沿用该 Bot 的模型、effort、工作区和长期记忆。
- **我的**：个人头像、主机切换、文件中心、Skills 与 MCP、运行状态、已归档、设置和主机管理。

“消息”和“Bot”右上角的加号可创建对话、群组或 Bot。聊天右上角“更多”提供对话设置、新对话及连接设置；正在处理时，停止和引导入口会显示在输入框附近。电脑保留侧栏和聊天顶栏，不需要按手机的路径操作。

手机的“更多”和新建等操作从底部展开，关闭后回到原来的页面。空输入框保持紧凑，点击输入或已有草稿时会展开。系统开启“减少动态效果”时，面板和切换动画会关闭；聊天正文不使用入场动画。

## 连接多台运行主机

一台电脑可以运行本地 Bot，同时作为客户端连接其他电脑；手机也可以分别配对 Mac mini、笔记本或 VPS。在「设备与网络」选择「此设备连接另一台主机」，分别完成可信设备配对。手机入口在「我的」所选主机下方，电脑入口在工作台菜单。要让另一台新设备加入，应点同页醒目的「添加设备」。

消息和 Bot 列表会显示所属主机。同名 Bot、同名对话仍分别保存会话、文件和草稿；一个群只能选择同一主机上的 Bot。手机在“我的”切换当前主机后，文件中心、Skills/MCP、运行状态，以及连接和设备授权设置针对该主机；语言和外观仍只影响当前客户端。创建页面也会标出运行位置，提交前先确认主机名称。每台运行主机可以再配置自己的多个 VPS 中转，主机和中转线路是两个不同层级。

## 首次连接与添加设备

1. **已有设备显示二维码**：手机打开「我的 → 设备与网络 → 添加设备」；电脑打开「设备与网络 → 添加设备」，欢迎页也有「添加设备 · 显示二维码」。已有可用线路时直接显示二维码，不会重新设置或重启主机。首次没有线路时，按说明选择同一 Wi-Fi 或 Tailscale，再点「生成…二维码」。
2. **新设备扫码或粘贴**：在新手机、平板或电脑打开 TaroBot，点「扫描连接二维码」；也可复制旧设备上的连接信息，在新设备选择「粘贴连接信息」。核对主机后，填写设备名称并点「配对此设备」。局域网连接要求在同一 Wi-Fi；Tailscale 要求两端已连入能互相访问的网络。
3. **已有设备确认**：新设备显示 8 位配对码。回到旧设备点「已扫码，输入配对码」，核对主机身份尾号后输入这 8 位数字并确认。也可直接从「设备与网络 → 输入配对码确认」进入。新设备「其他确认方式」中提供确认二维码，旧设备可扫描它代替手输数字。
4. **完成**：手机获准且连接成功后自动进入聊天。新电脑若要带着自己的 Bot 加入网络，连接后还要明确确认加入，不能把手机配对与主机组网混为一谈。

「连接状态与线路」查看在线状态、当前线路和备用线路；「设备与网络」用于添加设备、查看网络成员和主机组网；「设备与安全」用于设备名称及访问授权管理。二维码本身只传递连接信息，最终授权仍需核对配对码。

没有已有管理设备时，可在主机终端使用 `tarobot pair --lan` 显示连接二维码，用 `tarobot devices approve <8位配对码>` 确认，见[CLI 使用说明](../host-cli.md#手机配对与远程连接)。

## 主端运行在哪里

在配对页展开“连接选项与备用中转（可选）”，或进入“设置 → 连接 → 编辑线路”，可选择“主端部署方式”：

- **本地电脑运行 Bot**：手机／其他电脑经直连或中转访问主电脑，主电脑需在线。
- **VPS 运行 Bot，直接连接**：VPS 同时运行 Bot 和提供 HTTPS 入口，不需要另装中转或 Tailscale。
- **VPS 运行 Bot，通过其他 VPS 中转**：主机 VPS 运行 Bot，其他 VPS 只负责转发连接，可添加多个备用中转。

界面会显示连接路径与数据保存位置。选择仅设置已部署环境的连接，不会安装或迁移 Bot。
主机上的文件、CLI 登录、MCP、记忆和会话需要在主机配置；不会自动读取客户端电脑。
备用中转不等于备用运行主机。配置示例、首次 SSH 配对、安全边界见[主机与中转部署说明](host-deployment.md)。

## 电脑与手机接续使用

电脑和手机配对到同一个 Hub、属于同一个用户后，共用对话历史。电脑新建的群组、手机新建的话题都会出现在另一端；任一端发送的消息、附件、Bot 的生成过程和最终回复都同步到另一端。两端选择同一个话题即可接着聊，切换设备不会另开 session。

电脑发起的任务需要确认时，可以在手机卡片上提交；电脑上的卡片会同步为已处理状态。已读状态、会话改名、归档和绑定也由 Hub 共享。某端关闭或断线期间的记录会在重新连接后补齐，不必重新发送已经提交的消息。打开较长的会话会定位到最新消息；上翻查看历史时保持阅读位置，点“回到最新消息”可继续跟进。

运行 Bot 的主机和 Hub 需要保持在线；主机部署在 VPS 时，本地电脑可以关机。手机被系统挂起时，重新打开会补齐记录；后台通知仍需完成推送配置。未发送草稿、暂存分享、置顶列表、主题、字号和当前正在查看的会话目前保存在各自设备；不会因为另一端正在编辑或切换会话而覆盖本端。会话免打扰保存在 Hub，修改会同步更新其他已连接设备的管理面板；设备自身的通知偏好仍按设备分别设置。

电脑重新打开会恢复上次查看的会话；手机重新打开先显示“消息”列表，点入会话后恢复该设备的文字草稿。普通进入长对话会跟随最新消息；通知和搜索结果则跳到指定消息。移除主机会清除该主机在本机保存的位置与草稿。

Android 返回操作已接入分层导航：先关闭当前弹窗或附件预览，设置详情先回到设置分类；文件和运行详情先回到列表。未保存的线路、对话名称和文件标注沿用确认流程，保存中不会提前退出。聊天页返回会显示会话列表，再返回将应用放到后台，保留当前聊天草稿。录音中返回会结束录音并保留待发送音频，不会自动发送。这些流程已通过浏览器事件和桥接接口检查，实体返回键、系统手势及键盘收起顺序仍待 Android 真机验收。

“待发送分享”窗口关闭再打开时，当前编辑的说明文字和目标会话会保留，进行中的发送也会继续；主动停止请点“取消上传”。尚未提交发送的编辑只在本次运行中保留，关闭整个 App 后仍可能恢复为系统分享的原始内容。

## 对话与文件

Bot 是固定的助手实例，模型、effort 和工作区属于 Bot；对话、群组讨论和群内话题使用各自独立的 session。

调整思考强度时，点击聊天标题下方的模型 / effort 一行；群聊里先选要调整的 Bot。保存会同步到其他设备，并影响这个 Bot 的所有对话、群和话题，其他 Bot 不受影响。目前不提供单个对话的 effort 覆盖。修改不会创建消息或新 session，也不会中断正在进行的任务；引擎在下一次读取配置的安全时机应用。

各家引擎的档位不统一，选择器按当前引擎和模型显示兼容选项，保留原生档位名称。同名档位不代表相同的思考量或速度。“跟随默认”表示移除手工覆盖，不表示关闭思考。离线 Bot 不能从此入口修改；另一设备刚修改过配置时，界面会提示重新读取，避免覆盖新设置。具体范围见 [effort 设置说明](effort-settings.md)。

- **新建 Bot**：电脑侧栏点“新建 Bot”；手机在“消息”或“Bot”页点右上角“＋ → 新建 Bot”。填写名称、选择引擎、模型和 effort，然后点“创建 Bot”。Hub 所在主机（电脑或 VPS）应已安装并登录相应引擎。工作区可留空，自动创建独立文件夹。创建后点“开始对话”。这会创建实际的 TaroCub 实例和进程；无需创建飞书应用。
- **新对话**：电脑聊天顶部点“新对话”；手机点聊天右上角“更多 → 新对话”，或“Bot”列表中该 Bot 旁的加号。默认选中对应 Bot，名称可以留空，不用重新配置模型。原对话和历史仍可在消息列表中找到。
- **新建群组**：电脑侧栏点“新建群组”；手机点右上角“＋ → 新建群组”。选择已有 Bot 后创建；一个 Bot 也可以开群。名称可留空。每个 Bot 沿用自己的配置。
- **群内新话题**：进入群组后点“新建话题”，可填写名称或直接按 Enter。自动沿用该群的 Bot，另开独立 session。界面按照“群 → 话题 → 消息”组织，话题相当于群里的独立讨论空间。

电脑侧栏点击群名右侧的箭头，可以展开或收起话题；手机先点消息列表中的群，再点“全部话题”。群列表会汇总话题的最近消息和未读数量。顶部显示所属群和当前话题，点群名或“默认讨论”可回到群里的日常交流。电脑和手机都保留“新建话题”和“全部话题”入口。

话题较多时，点“全部话题”按名称查找；目录显示最近消息、未读提示，并区分“进行中”和“已归档”。顶部话题按钮保持稳定顺序，目录和侧栏按最近活动排列。不同话题的消息和草稿分别保存，切换不会把消息混到其他话题。

**话题改名与删除**：进入话题后点右上角“⋯”，或在“全部话题”中点该话题右侧的“⋯”，选择“重命名话题”或“删除话题”。手机和电脑都有这两个入口，需由话题创建者联网操作。改名同步到其他设备，保留原消息、上下文和草稿。删除前会再次确认，只将这个话题移入“已归档”，不影响群组和其他话题；删除正在查看的话题会回到群组，删除其他话题不会切走当前聊天。历史可在“全部话题 → 已归档”查阅，点“管理话题 → 恢复到会话列表”后可继续讨论。归档整个群期间，其下话题也不能发送消息。

群聊输入框上方的“让谁回复”可以直接点选 Bot，也可输入 `@` 打开选择列表。默认选中第一个 Bot，可同时选择多个。消息会携带明确的 Bot 选择；协议中未点名消息仍遵循实例原有响应设置。自己的消息和 Agent 回复使用不同底色，具体颜色随所选配色风格变化。

输入框旁的“发起 Bot 协作”可直接选择发起 Bot、委托对象和任务，也可选择并行、串联或回答后复核。在命令菜单点 `/ask`、`/fan`、`/chain`、`/verify` 也会打开这个入口；手工输入原命令仍然可用。一次由一个 Bot 发起流程，结果回到当前群组或话题，不用记内部实例编号。编辑中的任务文字保留在本机对话草稿；“编辑协作设置”可直接进入发起 Bot 的设置。当前入口发送文字任务，附件和引用从普通消息输入框发送。

同名 Bot 会带上 ID 的区分后缀。消息正文中的已知托管实例编号以名称显示，悬停可查看完整编号；代码、链接、文件路径保持原样，专用复制按钮及转发保存原始消息。名称目录会在本机缓存，离线重开仍可辨认引用，重新配对会清除该 Hub 的目录。无法识别的编号保持原文，不猜测身份。托管 Bot 的协作入口会检查配置、双向授权与对方服务状态；刷新后失去权限的旧选择不可发送。实际执行仍由原有 Bot 权限规则判断。

跨 Bot 委托沿用 TaroCub 的 Agent Bus：`/ask` 指定实例，`/fan` 并行处理，`/chain` 按顺序传递结果，`/verify` 交另一实例复核。Hub 创建的 Bot 可在“运行状态 → 协作设置”中启用并选择允许的成员、并行成员、串联顺序和复核 Bot。双方都需允许对方；界面显示对方权限和协作服务连接情况，可直接跳到对方设置。保存后点“空闲后重启并应用”，任务结束后重新读取检查连接。建群本身不会自动开放权限。外部接入的现有实例仍由其本机配置管理。发出协作命令时，在“让谁回复”里只选发起该流程的 Bot，避免重复启动。手机停止会取消发起方等待，并将取消信号传给接收方引擎；已执行的工具不会被撤销。断线或超时不会自动重新执行委托。

“研究团队与高级设置”提供 Crew 的协调者、研究员、分析员、撰写者、审阅者（五个不同 Bot），以及问题数、修订次数和委派层数。启用 Crew 会让协调者收到的普通文字消息自动进入研究报告流程；带附件消息保持普通处理。保存修改仅影响当前 Bot；各角色的对方权限也需要配置。

协作设置只有所有者的已配对设备可读写，密钥不会传到客户端。另一设备或本机修改后，旧页面保存会提示冲突并保留草稿；重新读取前会确认是否放弃未保存修改。服务“在线”只代表可连接，不能证明最近保存的配置已经全部应用。

所有创建操作都等待 Hub 确认后进入；断线导致结果未确认时，“重试创建”沿用同一次请求，避免重复创建。新 Bot 尚未上线时消息可以排队；持续离线可在“运行状态”查看服务详情、安排重启，手机从“我的”进入。既有飞书 Bot 的接入仍通过原 Gateway 配置完成，新建 Bot 不会重配或重启它们。已有实例 session 可在对话管理中绑定，绑定才会共享上下文。

输入 `/` 查看命令提示，`/config` 打开引擎设置。桌面按 Enter 发送；Mac 按 ⌘ Command + Enter 换行，Windows 按 Alt + Enter 换行，两者也支持 Shift + Enter。停止按钮停止当前轮次。表单和审批卡片通过卡片上的按钮提交，完成或取消后变为只读。

Codex 请求额外访问文件或网络时，会显示请求详情及“本轮允许／本会话允许／拒绝”。详情中的路径是 Bot 所在电脑上的路径；批准只授予这次展示的范围。“本会话允许”可能影响后续命令，请按实际需要选择。手机操作后电脑同步结果，停止当前轮次会取消仍在等待的申请。

Bot 正在处理时，输入框旁显示停止按钮；手机其他状态可从右上角“更多 → 停止当前轮次”进入。停止沿用 `/stop` 规则：中止当前任务或语音转写，也取消已经接收、仍在等待合并的附件消息；已经排队的下一项任务仍会继续。群内停止会请求当前讨论中的所有 Bot，其他话题不受影响。某个 Bot 离线或未回应不会阻止其余 Bot 接收停止请求，但界面会提示未能确认全部停止；可在运行状态中检查。中断卡片和取消提示会同步到电脑、手机。离线期间不能发送停止操作，重连也不会补发旧停止请求去影响新任务。

电脑和手机都支持把**文字、多张图片和其他文件放在同一条消息里发送**。先写文字再选附件，或先选附件再写说明都可以。通过“添加文件”、拖入文件或粘贴图片添加附件后，输入框内会显示缩略图、文件名和“一起发送”的提示；可以移除单个附件或点“继续添加”。同时粘贴图片和文字时，文字会插入当前光标位置。确认内容后只需点一次发送。上传中锁定本条内容；需要修改时先取消上传，文字和附件会保留。某个附件失败时不会提前发布文字或部分图片，重试仍一起发送。

桌面应用（macOS、Windows）的输入框附件按钮还提供“截屏”：临时收起 TaroBot 窗口，拖动框选屏幕区域，完成后以图片缩略图加入当前草稿。可补充文字、预览或移除，再自行发送；按 Esc 取消会保留已有草稿，也不会改动剪贴板。截屏期间如果切换了主机或对话，迟到的截图会丢弃，避免放进错误的聊天。macOS 首次使用需要在系统设置的“隐私与安全性 → 屏幕与系统音频录制”中允许 TaroBot，系统要求时重新打开应用。

每个附件最小 1 字节，默认上限 512 MiB，可由 Hub 的 `maxFileBytes` 设置调整；添加附件后会显示当前上限。超限会保留文字和附件草稿，不会发出消息。附件以 8 MiB 分块上传。断网或线路切换时会显示“连接中断，等待恢复…”，自动重连后查询 Hub 已保存的分块，只补传缺失部分。单次请求最多等待 5 分钟；无进展的恢复等待最多 5 分钟，超时后可重试。上传和校验完成前不会发送这条消息。

“取消上传”会停止当前传输，保留已上传的分块和当前已选文件；再次发送相同文件可继续。切换对话或关闭当前工作区会取消上传，避免继续向旧会话发送。关闭客户端后，普通附件可能需要重新选择原文件。下载会保留已完成的 8 MiB 分块，断线或切换线路后可继续；本机断点记录在刷新或重开后仍可使用，需要再次点击文件恢复。记录受容量与有效期限制，系统清理存储时也可能丢失，不等于后台下载服务。完整文件校验通过后才交给预览或保存，手机进程终止及后台行为仍待真机验收。详见[下载恢复](resumable-downloads.md)。

图片可点开查看。文件卡片支持文本、代码、PDF、Word 和 Excel 预览；HTML/SVG 显示原文。桌面“另存为”打开系统保存窗口。手机的下载按钮执行“保存到手机”：Android 10 及以上直接保存到“下载/TaroBot”，同名文件保留独立副本，并显示实际保存位置；较旧的 Android 和 iOS 使用系统文件保存窗口。只有保存完成才显示“已保存”。

消息里的表格会保留合理列宽，宽表可在表格内左右滑动，金额、日期和短标签尽量保持一行；长备注按段落换行，不再被压成竖排。宽表或较长表格上方有“展开表格”：手机进入全屏阅读，桌面打开大窗口，表头在上下滚动时保持可见。返回或关闭后保留聊天草稿与表格横向位置。短表不额外显示工具栏。引用缩略图保持只读，原表格内容不会被截短或改写。

音频和视频附件可点开内置播放，支持暂停和拖动进度；聊天中的语音也能直接播放。MP3、M4A（AAC）、WAV 以及 MP4（H.264 + AAC）已通过当前桌面/手机页面和 Android 模拟器的播放检查。其他编码取决于设备解码能力，同为 MP4 后缀不代表编码相同。预览需先下载并校验完整文件，大视频不会边下载边播放。手机不能播放的格式可用“其他应用”打开；桌面可另存为后使用播放器。详见[播放验证及范围](media-playback-2026-10-12.md)。

文件预览中另有“分享”和“其他应用”两个独立入口：分享打开系统分享面板，其他应用交给手机上的阅读应用。分享完成不代表已经保存到手机。原始附件和主机文件不会因这些操作被移动或删除。当前 Android 原生保存已在模拟器核验；iOS 文件保存窗口和各品牌手机仍需真机验收。

## 查看任务时间线和操作审计

电脑侧栏或手机“我的”进入“运行状态”，在 Bot 下点“运行记录”。“任务时间线”显示执行、重试、文件投递、协作等事件；切换“操作审计”可查看原 TaroCub 的操作记录。“查看 Hub 审计”单独显示配对、登录、吊销、审批、重启等管理记录。只有 Hub 所有者的可信设备能使用这些入口。

输入关键词后点“应用筛选”。“更多筛选”可按事件类型、执行结果、消息通道、会话和本机时区的时间范围查找；类型可直接输入完整事件名。“App”与“飞书”按原记录的会话归属区分。手机默认收起高级筛选和统计，展开后可查看重试、预算拦截、文件拒绝等计数。

列表先显示最近记录，点“加载更早记录”继续查看。“刷新记录”读取最新状态；电脑和手机查看同一套源记录，各自的筛选条件独立。点“查看记录详情”可展开执行者、记录标识和已脱敏的元数据。较长详情会提示显示截短，原日志不变。

统计覆盖当前日志及仍保留的轮转文件，不是从安装至今的全部历史。日志损坏、部分内容无法读取或尾部尚未写完时会显示提示；旧记录已被轮转清理导致翻页位置失效时，需要刷新再查。Hub 自建 Bot 停止后仍可查看它的日志；外接 Bot 需要在线才能从其 Gateway 读取。记录中未写明的结果不会被推断成成功。

## 查看任务、定时提醒和用量

在“运行状态”的 Bot 下点“详细概览”。电脑和手机读取同一个 Bot 的数据，点击“刷新概览”更新；页面标明读取和在线采样时间。四个分类分别是：

- **当前活动**：在线进程中的执行、排队、待审批、待选择和合并待处理会话，以及正在执行的会话标识和开始时间。已保存配置、绑定会话数单独展示，绑定过会话不等于正在运行。这里只统计该 Bot 的共享 App／飞书进程，不包括独立服务。
- **定时任务**：单次提醒、循环任务、是否启用、按任务时区显示的下次计划、最近执行与错误。展开可看会话复用、直接提醒／Agent 执行、通知设置、超时及最近 10 次执行。这里只查看；创建或修改继续使用原来的定时任务命令、卡片及工具。计划时间不保证离线期间执行。
- **协作流程**：最近保存的 crew 阶段、协调者、审阅结果和修订次数。“记录为运行中”不代表当前仍在执行；“查看任务时间线”可进一步查事件。
- **日/月用量**：选择按日、按月或累计，保留账本的 UTC 日期口径，可选择所有已记录期间。输入、输出、缓存、平均每轮及费用来自账本；没有记录显示未知，零费用也不能证明免费。

实时读取失败后，不再显示旧的活动计数。Hub 自建 Bot 离线时仍能查看保存数据；外接 Bot 需上线。损坏或过大的状态有读取提示，不会因为打开页面而修改原始记录；用量可回退到有效备份，但会提示数据可能较旧。

定时任务较多时，每页显示 25 条，可搜索名称、内容、任务 ID 或会话，并按启用状态筛选；页码可以直接跳转。搜索覆盖全部任务，展开一条任务后可查看其设置和最近执行历史。

## 文件中心

电脑侧栏点“文件中心”；手机返回首页后点“我的 → 文件中心”。它盘点已接入 Hub 的 Bot 工作区、收件附件和语音转写目录。多个 Bot 使用同一个实际工作区时只统计一次，并显示所有关联 Bot。尚未接入的本机实例不会自动加入；离线的外接 Bot、旧版本不支持盘点或读取失败时会显示提示，不能将未盘点部分理解为没有文件。

列表可按 Bot、分类、状态筛选，搜索名称、位置、备注，也可按占用、修改时间或名称排序。点一组文件查看实际磁盘占用、内容大小、来源、文件类型、较大文件和分类依据。电脑左右并列显示列表与详情；手机点“返回文件列表”继续筛选。“通常可重建”等状态是原文件中心的分类提示，不会自动清理文件。

在详情底部可标记重要、手动分类、填写备注，点“保存标注”后，同一个 Hub 的电脑和手机共享结果。保存中暂时锁定编辑；另一设备先保存了新版本时，本端草稿会保留并提示冲突。点“读取最新标注”会用最新值替换当前草稿，再编辑保存。关闭详情或切换文件组时，未保存的改动会提示确认。

首次盘点会导入原 Web Console 对这些文件组已有的标注；之后以 App 中保存的版本为准，不会双向修改原 Console 标注，清除后也不会被旧标注再次填回。文件本身不受标注影响。“复制位置”复制 Hub 上的路径；“在 Hub 电脑中显示”请求那台 Mac 打开 Finder，并不是在手机文件应用中打开。

“重新盘点”更新文件清单和占用，盘点中可取消；取消或失败会保留上次结果。清单是一次盘点的快照，文件变化后需要重新盘点。Hub 重启后需要重新盘点，但已保存标注仍在。此入口不提供删除或传输文件；聊天附件仍在对话中查看和保存。

## 查看 Skills 与 MCP

电脑侧栏或手机“我的”进入“Skills 与 MCP”，先确认页面标出的运行主机，再选择 Bot。可以切换 Skills / MCP、搜索名称或说明，并按配置范围筛选、展开来源。目录来自那台运行主机，不是当前手机或副机上的目录。

“已发现”只说明配置中找到了项目，不等于引擎已经加载或 MCP 服务在线。页面会区分部分清单、禁用和运行状态尚未确认，并说明读取限制。这个入口用于查看，不会自动安装技能、信任工作区或修改 MCP。配置仍由运行主机及对应引擎管理。

## 发语音和转写

点输入框下方的麦克风开始录音，界面会显示时长。点“完成录音”后可以试听、删除重录，也可以在同一条消息里添加文字说明或其他附件，再点发送。点“取消录音”会丢弃本次录音。切换对话会取消正在录制的内容，避免发错位置；切到后台时，在系统送达可见性事件的情况下会结束录音、保留本机草稿。未发送的录音不会同步到另一设备，关闭客户端可能丢失草稿。麦克风被拒绝时按提示到系统／浏览器设置允许，也可以上传已有录音。

收到后会显示转写进度与结果预览，然后 Bot 继续处理。短语音沿用本地 Qwen；达到 15 分钟的长音频，在电脑已配置听悟时走听悟，失败可回退本地。需要指定路线，可以把“强制本地转写”或“强制云端转写”放在同条消息的文字里；云端方式需要原有配置，会上传音频到该转写服务。停止按钮可取消当前转写。转写有缺段会明确标注，不会把不完整文字当完整结果。

电脑和手机都可以发送、播放、引用、转发语音；发送后的录音、转写卡片和 Bot 结果会同步。录音暂设 64 MiB 上限，到达后自动结束为待发送草稿；较长的已有录音可以从“添加文件”上传，仍遵循普通附件上限。各引擎的 MCP、插件和技能继续在电脑执行，不需要在手机重复配置。详细对应关系见[功能适配核对表](capability-map.md)。

Kimi 的项目 MCP 只在受信任工作区中加载。如果 App 中找不到项目工具，请先在电脑的原生 Kimi 中打开并信任该工作区；不要把“配置文件存在”当作工具已加载。已核验的 Kimi 2.1.1 尚不支持新版文档中的 `KIMI_CODE_TRUST_WORKSPACE` 环境变量。

审批时按按钮上的范围决定：**允许一次**只批准这次请求；**本轮允许**覆盖当前任务；**本会话允许**可能影响这个会话的后续消息；Kimi 的**允许后续调用**采用引擎的持续授权规则，不能当作仅当前轮次。不同引擎提供的按钮会不同；缺少“允许一次”时，App 不会代替你升级为持续授权。手机作出的决定及其范围也会显示在桌面端。

## 链接预览

在消息里输入或粘贴 `http://`、`https://` 网页链接，会在输入框上方预读取标题和可用的封面。原网址仍保留；发送后，网页标题、网站/域名、简介和封面显示在同一条消息气泡里。文字、图片或文件也可以一起发出。

一条消息有多个链接时，可以用“选择预览链接”决定展示哪一个（最多识别前 5 个不同链接）。点叉号关闭本条预览，或点“显示链接预览”恢复。代码块、行内代码和 Markdown 内嵌图片中的网址不自动生成卡片。

预览下方的“发送为”可以选择“标题”或“卡片”：标题视图只显示图标、网页标题和真实域名，更省空间；卡片还可显示简介和封面。选择随消息同步到电脑、手机，重开和转发后也保留。收到消息后可点“展开链接详情／收起链接详情”，这只改变本机当前阅读视图，不修改消息，也不会再次唤醒 Bot。旧消息默认继续显示卡片。

预览无需读取完成就能发送。Hub 会把读取结果和封面存入这条消息，电脑、手机随后收到相同结果；重开客户端或转发也保留已生成的卡片。点卡片打开原网页。封面读取失败时仍显示标题；网页需登录、禁止读取、超时或不支持时，保留可点击的网址，不影响文字和附件发送。

预读取会由 Hub 向公共网站发起请求，不携带浏览器登录状态。局域网、Tailscale 私网和本机管理地址不自动读取；仍可通过原网址自行打开。

显示层次参考[飞书官方链接预览指南](https://open.feishu.cn/document/development-link-preview/link-preview-development-guide)的标题与卡片形式。飞书等需要授权的私有文档，目前不会自动获取其正文或私人预览数据。

## 引用与转发

每条消息下方都有引用和转发入口；电脑显示文字与图标，手机使用图标按钮，并保留读屏名称“引用回复”“转发消息”。我的消息靠右，Bot 消息靠左；两者的底色随所选配色变化，不固定为浅蓝色。

- **引用回复**：点“引用”，输入框上方会显示作者、原文摘要和附件名称。输入自己的补充后发送。点预览右侧的叉号可取消引用；发出后点引用区域可回到原消息。引用消息和 Bot 读取引用内容、附件的能力沿用同一对话的上下文。
- **转发消息**：点“转发”，搜索并选择一个单聊、群组的默认讨论或群内话题，再点“确认转发”。选择页只显示搜索与目标，不重复展示被转发内容；单聊显示对应 Bot 头像，群组与话题显示群头像。话题会显示所属群组，归档的目标不会出现在列表中。也可以选回当前对话。正在生成的消息须等生成结束再转发。
- **保留什么**：转发保存当时的正文、卡片内容、图片、音频、文件和已生成的链接预览，并标出来源对话、作者和时间。卡片中的审批、表单等操作保持只读。原消息后来修改或删除，不会修改已转发的副本；转发附件可以在目标对话里预览和另存为。再次转发时记录这一次的直接来源，不自动附带整段聊天历史。
- **是否继续处理**：转到单聊时默认让该 Bot 接着处理；转到群组或话题时默认只保存内容。可以调整“让 Bot 回复这条转发”及回复 Bot，也可以转发后再引用它提问。

引用和转发结果都会同步到同一 Hub 下的电脑、手机。离线转发会先保存在本机，显示“等待发送”，重新打开仍保留，重连后发送且不会重复。引用或转发来源如果已经删除或不在自己的可访问对话中，会显示不可访问提示；目标中的转发副本仍可阅读。此处转发的目标是 TaroCub 内部对话，不是飞书、Telegram 或系统分享。

## 从其他手机应用分享

Android 系统分享菜单选择 TaroCub 后，会保存文字、网址或文件，并打开客户端。iOS 分享扩展先保存草稿，再手动打开 TaroCub。客户端显示“待发送分享”，点开后选择会话、检查或编辑文字，再点击“发送分享”。不会自动选择 bot 或发送。

首次尝试发送后，重试固定使用原会话、原文字和同一消息编号。这样，即使发送已被接受但本机清理回执丢失，也不会生成第二条消息。需要更改目标时，丢弃这条草稿并重新分享。普通聊天草稿不会被分享内容覆盖。

分享入口每批最多 64 个文件，合计大小使用最近一次连接 Hub 时收到的附件上限（默认 512 MiB）；本机队列最多 16 条、总文件预算为该上限的两倍（默认约 1 GiB）。调整 Hub 设置后，先打开客户端连接一次，系统分享入口才会记住新上限；最终上传仍以 Hub 的当前设置为准。副本在 24 小时后访问队列时清理，已进入发送队列或手动丢弃的副本立即清理。带附件的分享需恢复连接后发送。手机系统回调和大文件仍需真机验收。

## 离线、搜索和重新发送

离线时可以查看本机已有记录，并按顺序排队发送文字。顶部显示连接状态；恢复后客户端自动补齐消息。未发送队列出现错误时，查看错误原因再重试。切换会话保留文字草稿。

离线较久、缺少超过 1000 条事件时，客户端会下载会话的最新快照。下载期间仍能查看原有缓存，收齐后统一更新；中途断线或关闭程序不会把半份历史当成已同步。草稿和待发消息保留，恢复完成后按原顺序发送。

很长的 Bot 回答仍在原消息中显示，保留正文、表格和公式，不需要跳到外部文档阅读。长回答通过分块传输，只有收齐并校验后才更新本机历史；中断时保留上一版，重连后自动补齐。引用、转发和搜索使用完整内容。新旧客户端并用时，较旧版本可能需要更新才能接收超长回答。

如果 Bot 进程在处理期间异常重启，客户端会把本次运行标为“处理已中断”，保留已收到的内容，并关闭失效的确认按钮。展开“查看中断前的内容”可读旧卡片。为避免命令重复执行，这种情况不会自动重跑；先检查已有结果，需要继续时重新发送。普通断网或 Hub 重连仍会自动补齐原任务，不属于进程中断。

如果最终回复已进入待投递账本，重启后会尝试补发正文和通过检查的附件。投递结果不确定时会显示 ♻️ 并提示可能重复；不会重新执行模型或回复中的定时任务、建文档等操作。该账本沿用 TaroCub 的大小、次数和时效限制，详细边界见[全功能对齐审查](functional-parity-audit.md)。

已查看且不超过 16 MiB 的附件会按最近使用顺序缓存，总预算 128 MiB。未缓存或较大的附件需要联网。完整历史搜索需要 Hub 在线。

电脑从侧栏搜索历史消息。手机先在“消息”页搜索栏输入关键词，再点下方“搜索历史消息”；这个按钮查询当前主机，标题会标明范围。搜索面板内可继续修改关键词，并按 Bot、开始／结束日期、是否含附件筛选；日期包含当天。Bot 筛选也包含其所在对话中的用户消息。中文单字、词语，以及 `%`、下划线、反斜杠均按原文匹配。点结果回到对应群组、话题或对话，并定位原消息。

搜索期间会显示“正在搜索”，没有命中和日期顺序错误也会给出提示。每页最多显示 50 条摘要，用“上一页／下一页”继续查看更早的结果；点击结果查看完整原文。翻页失败时当前结果保留，可再次点击重试。修改关键词或筛选条件后，点击“应用筛选”才会更新结果并回到第一页；未应用的修改会明确提示。可以随时改查其他词或关闭搜索，迟到的旧结果不会覆盖新查询。新增或修改的消息可能出现在已翻过的位置，重新应用筛选可读取最新结果。分页搜索需要当前版本的 Hub。

消息菜单的“重新发送”会发起新消息和新一轮处理，适用于明确希望再执行一次的场景。它与断线后的自动恢复不同。

## 通知与应用锁

在设置中启用通知，并配置免打扰时间、会话静音。真实通知还需要 Hub 和平台推送配置。Android 支持 FCM，也可选择已经安装的 UnifiedPush 分发器；UnifiedPush 服务器地址必须在 Hub 允许列表中。切换推送方式会替换当前设备的注册。

手机可在“设置 → 设备与安全”中启用系统身份验证。离开应用后再次打开需要面容、指纹或设备密码；后台预览会遮挡，Android 开启时也会禁止截屏。应用锁保护本机界面，不替代丢失设备后的吊销操作。

## 设置、导出和本机重置

设置分为“通用”“通知”“连接”“设备与安全”。桌面左侧选分类，手机点分类进入全屏详情；顶部返回分类不会丢失正在编辑的线路。通用里可切换中文/English、明暗主题、字号，以及暖砂、松绿、海雾、暮紫四套配色；外观只影响当前设备。界面语言不会翻译 bot 已写出的内容。

电脑点击聊天顶部连接状态可直接进入“连接”；手机从聊天右上角“更多 → 打开连接设置”进入。先查看实际线路和已保存地址，再点“编辑线路”。改动会标记未保存，取消可恢复原值，关闭整个设置前会确认是否放弃。保存线路不等于连接成功，实际状态单独显示。

在「设置 → 连接 → 编辑线路」中，直连 / Tailscale 地址是可选项；VPS 支持一主多备，最多 8 台。每条 VPS 可以填写名称和地址，用上下箭头调整优先级、添加备用或移除，再点「保存线路」。界面显示当前线路和各节点最近的探测结果。直连可用时优先直连，其余按 VPS 列表从上到下尝试。主线路故障时自动切换，已发送消息按原 ID 和同步进度恢复；高优先级线路连续恢复稳定后，等 Bot 回复、待发消息和文件上传完成再回切。所有线路必须指向同一个 Hub，身份不符会被拒绝。

桌面 App 运行本机主机时，在「设置 → 设备与安全 → 添加新设备」可选择「同一 Wi-Fi」或「Tailscale 异地连接」。Tailscale 方式先在电脑和手机安装 Tailscale、登录同一账号并开启连接，再点击「生成 Tailscale 连接码」；App 会检测电脑当前的 Tailscale 地址、建立 HTTPS 监听，并把地址和此主机的公钥、公开证书放入二维码。无需手填地址、配置 Tailscale Serve 或购买 VPS。TaroBot 不会代替你登录 Tailscale，也不会更改其访问规则；这些规则需允许手机访问二维码中的主机端口。

新手机在 TaroBot 扫码后，会显示配对码，需要回到电脑确认。已经通过局域网配对的手机，在手机「设置 → 连接」中选择「扫描二维码更新连接」，扫描 Tailscale 连接码并确认即可；保留设备身份、聊天记录和备用 VPS，只替换这台手机的直连线路。Tailscale 登录不会自动完成 TaroBot 配对。电脑需保持开机联网，两端 Tailscale 需保持连接。

局域网和 Tailscale 监听可以同时开启，生成一种连接码不会关闭另一种监听。首次开启或地址变化可能短暂重启主机，操作前请等运行中的任务结束。若主机启动时 Tailscale 尚未连接，仍可在电脑本地使用；连接 Tailscale 后回到此入口刷新连接码，以恢复该监听。关闭此页面不会关闭已经开启的监听。当前自动检测要求 Tailscale 地址出现在系统网络接口中；未检测到时不会生成假连接码。用户态网络模式或自建远程 Hub 仍需使用已有的手动 HTTPS 线路配置。

线路偏好保存在当前设备，便于各设备使用不同的直连地址和优先级；「显示连接二维码」生成的二维码携带完整的主备列表，新设备扫码即可带入。原来已经配对的设备可分别在连接线路中补充备用地址。首次配对也能通过可用的备用线路发起；已有会话、文件和 Bot 仍同步同一个 Mac mini。

Mac Hub 的 `relays` 配置让主、备 VPS 保持独立出站 TLS 隧道；无需 Tailscale 也能使用多 VPS。各 VPS 的部署文件和凭据彼此独立，配置示例见 [主备中转部署](relay-deployment.md#multiple-primary-and-backup-vps-relays)。这保护 VPS 和到某一 VPS 的网络故障；Mac mini、家中网络或 Hub 本体停机时，全部中转都会失去执行端。

文件保存在运行 Hub 的主机上（本地电脑或 VPS）。Tailscale 成功建立设备直连时，文件数据不经过 VPS；无法直连时，Tailscale 自身也可能使用中继。选择 VPS 备用线路时，VPS 转发加密的文件数据，会占用 VPS 带宽，但不保存文件副本，也不解密文件内容。因此，线路显示“Tailscale”不代表已经确认点对点直连。

同一局域网可配置 HTTPS 直连，无需 Tailscale。默认私有监听只接受本机回环或 Tailscale 地址；普通局域网地址需要显式配置 HTTPS 监听并设置 exposure: public，再用防火墙限制访问范围。这不会自动开放路由器端口，连接设备仍须配对。具体配置见主机与中转部署说明。

消息的 Google Docs 导出需要事先在 Hub 完成 Google 授权。导出结果须有文档链接和写入校验回执；未配置时应按提示完成授权，不能把提示或排队状态视作导出成功。

“管理运行主机 → 移除此主机”会清除该主机的本机历史缓存、草稿、待发送消息、分享副本和设备密钥，Hub 中的历史保留，其他主机不受影响。这个操作不适合作为临时断网的解决方式。

桌面更新在“设置 → 通用”中显示版本和安装按钮；安装由你主动点击。开发构建尚未配置正式更新源。
