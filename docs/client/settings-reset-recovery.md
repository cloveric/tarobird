# 设置回归与断开恢复验收

日期：2026-10-02。接续 [Opus 5.5 两轮设置评审](settings-ui-review.md)，本轮落实其中的清理失败风险，并实际运行改版后的浏览器回归。没有再次调用 Opus，也没有部署或重启生产实例。

## 程序变化

- “断开并重新配对”先用一笔 IndexedDB 事务保存待清理记录和新的缓存版本，然后关闭连接并重新载入页面。清理阶段不启动工作区或旧身份连接。
- 清理共享文件、推送、设备密钥之后，最后一笔事务同时清除身份、消息、草稿、发件箱、附件和待清理记录；保留语言、主题等本机偏好。任一步失败都保留重试记录及原密钥引用，显示失败步骤，可点击重试或重开应用继续。
- 每次缓存写入在同一事务内检查版本和待清理标记。旧页面、延迟的附件转换不能在清理后重新写入旧内容。浏览器通过广播通知同源页面重新载入，并用 Web Locks 串行执行清理。
- 原生安全存储删除后再次检查密钥是否仍存在。Android UnifiedPush 注销检查本地保存结果；Firebase 清理在没有配置时直接返回，有配置时等待删除 token 完成。浏览器推送查询先检查支持能力和通知权限，修复 WebKit 未获权限时的卡住问题。
- 在打开设置或扫码弹窗前明确聚焦入口按钮，修复 Safari 点击按钮默认不聚焦、关闭后无法回到入口的问题。

清除本机数据不会删除 Hub 历史，也不会自动撤销主机上的设备授权记录。丢失设备仍应由另一可信设备撤销授权。

浏览器覆盖：桌面和 390 px 手机分类导航、跨分类保留线路草稿、非法地址、取消恢复、关闭确认、连续 Esc、扫码焦点返回、配对二维码、主备 VPS 故障切换、群与话题、真实断网后三条消息按序恢复、大快照事务、增量流式消息、离线 Markdown worker 和冷启动。

故障测试在真实 IndexedDB 中中止最终清理事务：身份、草稿与重试记录均保留；刷新后没有新增旧身份 WebSocket；重试后本机数据清除，深色主题保留，主机历史与授权记录仍在。另一个页面和延迟附件写入均被旧缓存版本拦截。

早期 WebKit 离线模拟保留了既有 WebSocket，测试改用真正断开 TCP 的本地代理；代理起初遗漏允许的来源，已补入仅本测试的回环来源。这些中间失败未计为通过。最终完整浏览器组合重新运行，通过数如上。
