# Bot deletion and mobile interaction cleanup — 2026-10-14

## Behavior

Phone: Bot tab → a Bot's settings gear → Delete Bot. Desktop: right-click a
Bot → Bot settings → Delete Bot. Both use the same confirmation, identifying
the Bot and host and explaining the consequences before any request is sent.

Deletion is owner-only and applies to App-managed workers, regardless of engine.
Externally managed workers show an explanation instead of pretending the App can
stop their external supervisor. Offline hosts cannot accept deletions; an offline
Bot can be deleted while its host is connected. Older hosts show an upgrade hint.

The host atomically records `bots.deleted_at` (schema 14), settles active replies
as interrupted, closes pending card actions and cancels pending deliveries. The
manager stops the worker through its existing IPC shutdown path, with bounded
process-tree escalation, and suppresses all automatic restart attempts. A failed
shutdown confirmation is reported for retry rather than claimed successful.
Replayed creation requests, restarts, old Gateway credentials, late Bot writes,
and attempts to restore a retired direct chat cannot reactivate the Bot.

Direct conversations are archived. Group and topic membership loses only the
removed Bot; empty groups/topics are archived. History, attachments, avatar
metadata and workspace files remain, including external workspaces. Historical
Bot names are retained in an isolated read-only directory and offline name cache;
they do not appear as selectable Bots. Archived history explains why it cannot
be restored. Other Bots and devices remain connected.

No workspace cleanup or credential export is part of deletion. Backups preserve
tombstones as well as retained files; restoring such a backup does not restart
a deleted Bot. Existing pre-deletion backups, like other full-state restores,
represent the earlier state. Schema 14 requires an updated host and is rejected
by older binaries rather than silently erasing the deletion marker.

## Mobile presentation

- A single native question no longer repeats a card title, a `1 / 1` counter,
  and the generated `Question 1` heading. It has one heading, the actual prompt,
  choices/free text and Submit. There is no disabled Previous button. Multiple
  questions retain progress, navigation, validation and focus handling. Existing
  saved cards receive the same presentation without rewriting their content.
- The attachment plus is inside the composer, immediately left of the microphone.
  It keeps a 44 px touch target without a separate outlined circle. The attachment
  sheet, draft preservation, recorder gestures and send/stop slot are unchanged.

## Verification

Disposable Hub/worker fixtures only; no user Bot was deleted or restarted.

- Root tests cover deletion admission, role and fresh-session checks, stale-name
  confirmations, duplicate requests, create/restart races, worker shutdown,
  archive/group/topic behavior, active run interruption and file retention.
- Authenticated HTTP tests cover deletion receipts and live Bot updates, denial
  of the previous worker credential, and repeated confirmation.
- Backup tests cover retained workspace/attachment data and durable tombstones.
- Browser journeys exercise both phone-initiated and desktop-initiated deletion,
  cancellation, live cross-device updates, reload, read-only history and retained
  message authors. Question journeys cover single/multiple forms, free text,
  validation, focus, drafts, offline queuing and cross-device settlement.
- Attachment/composer/hold-to-talk regression covers 320/390 px layouts, activity
  transitions, file picking, captions, cancellation and voice gestures.

Source changes only: these checks do not constitute physical phone keyboard,
macOS/Windows native installer, or real-engine shutdown acceptance. No new
installer is generated by this change.
