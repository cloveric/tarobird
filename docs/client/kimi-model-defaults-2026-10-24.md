# Kimi 模型列表与原生默认档位

## 行为

App 的新建 Bot、Bot 设置、输入框快捷选择，以及 CLI `catalog` / `bots model`
共用主机读取的 Kimi 模型列表。模型 ID 来自本地 `config.toml`，不硬编码套餐
或猜测模型别名。`引擎默认模型 · K3.1 Pro` 表示跟随本机默认；单独选择
`K3.1 Pro` 则固定保存它的真实 ID `kimi-code/k3.1-pro`。

思考档位按每个模型的 `support_efforts` 提供。未指定 Bot effort 时，ACP
适配器使用选定模型的 `default_effort`。本机 Kimi Code 2.3.1 实际提供 K3
默认 high、K3.1 Pro 默认 max。固定思考的 K2.7 Code Highspeed 只显示跟随默认，
执行时使用原生 `on`，不提供无效的 low/high/max 按钮。

已有 Bot 的显式 effort（包括以前版本写入的 high、用户保存的 max）全部保留，
不能猜测它是否属于用户偏好。新建 Bot 或切换到 Kimi 不再自动写入 high。
想恢复原生默认，可在设置中选择「跟随默认」。明确固定 K3 的 Bot 仍需切换模型，
本次不会把所有 Bot 自动迁移成 3.1。

模型设置是 Bot 级，影响其已有和新建对话。现有适配器在下一安全边界重读设置、
恢复同一个原生 session 并应用模型/档位；正在执行的任务和后台子代理不被打断。
原生 ACP 在换模型后可能保留旧 effort，所以重置时必须明确应用新模型的默认档位。
不清空上下文；官方仍建议换模型后新建会话，以减少混合上下文和缓存影响。

## 兼容与限制

- 沿用现有严格协议的 `id`、可选 `label`、`efforts`，不增加 wire 字段。
  旧客户端能读取同一响应，已有历史卡片和会话格式不变。旧客户端可能只显示默认
  项的模型名称；新版会保留「引擎默认模型」前缀，明确区分跟随和固定选择。
- 元数据读取限制为普通文件、最多 1 MiB / 512 个模型，允许普通配置符号链接。
  仅输出模型白名单字段，解析失败不输出可能包含密钥的 TOML 错误。
- 缺失、损坏或旧配置没有默认档位元数据时，不编造 high，也不修改原生配置；
  ACP 自己保留/决定该会话设置。这种旧版情况下，无法保证取消覆盖后重置已保存的
  档位，仍可明确选一个原生支持的档位。没有宣称所有旧 CLI 均具备新版元数据。
- 列表代表主机配置，不证明服务端套餐授权；执行前仍由现有 ACP advertised-value
  校验确认。自定义模型 ID 入口保留。
- 其他引擎的默认值和平台字号、布局不改变。

## 验证

本机原生 Kimi Code **2.3.1**：独立工作区、独立测试 Bot 配置，未修改生产 KK1、
主机配置或 Kimi 默认配置。真实适配器连续四轮使用同一原生 session：

| 轮次 | 模型 | 实际 ACP 档位 | 结果 |
| --- | --- | --- | --- |
| 1 | K3.1 Pro | 显式 low | 精确标记应答 |
| 2 | K3.1 Pro | 取消覆盖后 max | 回忆第 1 轮口令 |
| 3 | K3 | 原生 high | 精确标记应答 |
| 4 | K3.1 Pro | 原生 max | 再次回忆第 1 轮口令 |

原生探测还确认新建 session 默认 3.1 Pro/max，以及仅切换模型不会自动重置旧档位。
本机全部 6 个配置模型的 ID/名称与原生 ACP 一致；固定思考模型接受 `on` 后，
ACP 的思考选项仅剩 `on`，没有可调整的档位。
验收文件保存在 `/Volumes/gdrive/taro-tmp/kimi-model-defaults-20261024/`：
`acp-config-probe.json`、`live-adapter.json`、`live-adapter.log`。
单元/集成覆盖模型分档、新 Bot 默认、显式偏好保留、旧会话恢复、旧格式回退、
损坏配置、严格旧协议、共享 App/CLI 保存与历史保留。
浏览器覆盖桌面 1360 和手机宽度 390，浅/深色模型设置、桌面快捷模型选择，
无横向溢出；这些截图不构成 iPhone/Android 真机验收。

验证结果：477 个测试文件、6528 项通过，5 项按原有条件跳过；Host/CLI 与
App 构建通过；9 项浏览器回归通过（Kimi 模型设置 1 项，跨引擎快捷设置 8 项）；
77 项桌面 Rust 单元/集成测试通过。原生检查先因新工作目录缺少 `host` 打包资源
停止，补上已有验证资源后重跑通过；没有生成或安装新版 App。

本次是源码修订，不自动发版、重启或更新已安装 App/CLI。
