# Per-message queue pause — issue #104

## Behavior

Each editable, undispatched prompt has Pause / Start in the queue, on desktop,
phone and ADHD. Pause keeps its position and displays an explicit Paused badge;
the Host skips it and continues later eligible messages. Start restores
eligibility at the retained position, without preempting an active input.
Editing, reordering, source navigation and cancellation remain available while
paused. The trigger previews the first eligible message, or says all are paused.
Desktop right-click / keyboard context menu and phone long-press expose the same
action. Phone Up/Down retain icon buttons with accessible labels and 44px
minimum widths, keeping normal phone actions on one row; narrow screens can wrap.
The English queue ordinal is shortened to #N so it fits alongside the four header
controls at 320px, while the full row/button accessible labels remain.
Touch movement, scrolling, cancellation and navigation cancel a pending
hold; releasing the hold does not activate the menu underneath it.

CLI: `tarobot queue pause|resume CONVERSATION --bot BOT --message ID --revision REV`.
The CLI uses the same authenticated endpoint, revision check and request receipt
as App clients; lost responses retain the original request ID/body for reconciliation.

## Ownership and compatibility

- `deliveries.queue_paused` is durable Host state. Claim/take and mutations share
  one write transaction. Pausing after claim is rejected; a successful pause
  cannot be claimed. Resume does not clear an active dispatch fence.
- Push, pull, replay and legacy-worker paths respect pause before decoding input
  or flushing commands. Slash commands and Agent Bus inputs keep their existing
  controls and cannot be paused through this feature.
- The wire state remains `queued` with optional `paused`, `canPause`, `canResume`
  fields. `capabilities.pause` gates the new UI on older Hosts. Existing App
  parsers can still read a newer snapshot without a new enum value.
- Existing membership, author, supported-engine, group and revocation guards are
  unchanged. No authorization is added, and no model-specific queue is introduced.
- Hub schema 25 adds the pause column with false as the migration default.
  Runtime metadata, backup/restore validation and downgrade fences advance
  together: an older runtime must not silently dispatch paused inputs.

  still visible. It now waits for loading and fonts before measuring; the same

- The English ordinal really clipped at 320px. Shortening the queue-only label
  to `#N` fixed it; the complete heading geometry / original-message navigation
  case passed on the final client build (`english-final.log`).
- The existing dispatched-item assertion expected the old move/cancel-only
  error text. The broader message also covers pause, and the updated assertion
  passed the complete cross-device / uncertain-receipt scenario
  (`receipts-readback.log`). The earlier failing receipt run is retained.

New browser cases also verify two paired Apps, retained edit/composer drafts,
all-paused previews, 320px overflow, 390px action alignment and 44px targets.
Chromium long-press uses trusted CDP touch input, including release without
accidental activation and movement cancellation. WebKit uses synthetic hold
pointer events followed by a real menu tap; it does not establish physical iOS
long-press behavior. Five-engine checks exercise shared Host dispatch semantics,
not real model invocations.

This is source / isolated Host and browser acceptance. No production Host state,
installed App, device pairing or model configuration was changed. Physical iOS /
Android acceptance and an installed-App upgrade are not claimed. No release.
