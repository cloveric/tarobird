# Mobile IM navigation

The phone uses a dedicated full-page inbox and three bottom destinations: Messages,
Bots and Me. The desktop retains its Bot / group tree and simultaneous conversation
pane. This changes navigation, not the Bot / session / workspace model.

## State boundaries

- Conversation IDs still identify sessions. Separate direct conversations with the
  same Bot remain separate rows and keep their own drafts.
- A group is an inbox row. Its active topics contribute to recency, previews and
  unread totals, while their messages remain in distinct conversations. Topics
  open from inside the group. Archived parents and topics are excluded.
- Multiple runtime hosts appear in the same inbox. Row keys and actions carry both
  host and conversation ID. Avatars use the owning host's provider.
- Opening Me changes no active transport. Its tools and settings explicitly identify
  the selected runtime host. Switching hosts retains each mounted workspace.
- On a fresh phone launch, the inbox is the root. A notification / explicit deep
  link can open its conversation directly. Choosing a row does not automatically
  focus the composer or raise the keyboard.
- A phone inbox does not send read marks for the internally selected conversation.
  Android Back closes the top dialog first, returns a chat to the inbox, returns
  Me / Bots to Messages, and only then allows the root to background.
- Returning to the inbox finishes an active recording and preserves the audio draft.
  Uploads and typed drafts retain their original ownership.
- Conversation-name search is local to the displayed inbox. Full message search
  explicitly names its runtime host; it does not silently search a different host.
