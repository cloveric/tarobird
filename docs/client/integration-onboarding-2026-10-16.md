# 首次本机 Bot：可选语音与搜索建议

首次在桌面本机主机创建 Bot 成功后，推荐 Qwen3-ASR 0.6B 和 Tavily + Brave，可分别选择，也可直接跳过。后续从「Skills 与 MCP」重新进入，针对当前主机和选中的 Bot。

本机身份来自原生 Host 公钥，不以 localhost 地址或窗口宽度推断。已有现存或已删除 Bot 的主机不再插入首次建议；远程、网页和手机的新建流程维持原样。

选择配置会打开现有的可编辑消息预览，随后创建独立对话并保存草稿。用户发送后才由 Bot 协助检查和配置。页面不自动下载、安装、提交密钥或宣称接入已验证。配置消息要求复用现有环境、默认优先内置硬盘，空间不足或用户指定时再使用外置磁盘、私有保存密钥、避免重复 MCP 注册，并实际检查结果。

## 2026-10-19：首次配置草稿为空

首次创建配置对话时，目录同步可能先把它选为当前对话，此时输入框读取的是
尚未写入配置文字的空草稿。稍后 `CapabilityHelpDialog` 保存草稿，列表订阅收到
更新，但再次选择同一个对话 ID 不会触发输入框重新读取，因此出现“左侧有草稿，
输入框却为空”。隔离首次启动测试通过控制保存和读取的完成顺序复现了该问题。

配置窗口现在把已经成功保存的文字随创建回执交给工作区。如果目标已经是当前
对话，立即更新输入框，并使之前尚未完成的空草稿读取失效；其他对话仍从各自
缓存加载。消息仍由用户编辑并手动发送，不会自动执行安装。已有草稿没有被删除。
同时补齐配置窗口关闭后的桌面输入框聚焦，避免当前对话 ID 未变时丢失焦点请求。

回归覆盖延迟保存、旧空读取晚到、组合语音与搜索配置、手动修改后仅发送一次，
以及已有对话的文字/附件草稿保留、丢回执重试与切换主机时的隔离。
本轮 Chromium、WebKit 各 23 项相关流程通过，另各 3 项 ADHD 草稿隔离、窗口
创建与焦点回归通过，共 52 项浏览器检查；客户端翻译检查、类型检查和构建通过。
首次草稿为空与关闭后未聚焦均先在旧实现中复现，再验证修复。没有运行全库回归，
也没有发布安装包或替换用户已安装的 App。
CLI 不受影响：本次只修正 App 内配置消息预览到输入框的交接，不改变主机 API、
安装工具、模型运行和 CLI 命令。原生 Windows 的实际安装配置不属于本次浏览器验证。

## 边界与 CLI

原生 IPC 和系统凭据存储由测试替身提供；浏览器通过不代表 macOS/Windows 安装器或真机验收通过。本次没有实际下载 ASR 模型、调用付费搜索 API、重启用户主机或更新已安装 App。

本次为客户端引导，Host API、协议和配置规则未变，CLI 继续使用同一套随包私有配置、安装/检查脚本和 MCP 入口。没有新增原生 Windows Qwen 一键安装器；该平台必须先检查兼容环境，不能直接执行 macOS/Linux 的 Bash 安装步骤。
