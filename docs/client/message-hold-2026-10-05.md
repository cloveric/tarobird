# 手机长按消息与文件直点 · 2026-10-05

本轮实现用户给出的 Grok Bot 手机操作方式，沿用现有引用/转发和文件权限链路。
代码、浏览器交互和手机资源副本已验证；不代表手机原生容器或整个产品计划完成。

## 行为

- 手机触摸消息正文、图片或文件主区域约 500ms，打开消息操作面板。可引用回复、
  复制、选择文本、转发和导出；保留原有“…”入口供键盘与读屏访问。
- 手机文件的图标和名称组成直接预览按钮，视觉上不再显示“打开”字样。
  保存图标保持独立。辅助技术仍能读到“打开 + 文件名”，大小通过描述关联。
  桌面保留原来的打开和保存控件。
- 手指移动超过 10px、取消触摸、多指、离开页面或切换对话/主机，取消尚未完成的长按。
  松开长按的同一次触摸不会意外打开文件或点击面板按钮。
- 流式更新期间暂缓自动贴底；不移动所按消息的虚拟列表滚动补偿不会误取消长按。
  代码、链接和表单维持原生交互；菜单里的“选择文本”提供可选取的完整消息文本。
- 引用仍发送原消息 ID，由 Gateway 获取原文及同对话附件，并传给真实 CLI。
  UI 摘要不作为给 Bot 的全部上下文，也不会把其他会话的附件权限扩大。

实际 `claude-opus-5-5`、请求 effort `xhigh` 完成一次静态复核，约 509 秒。
没有向它发送用户截图里的出行或订票资料，只提供本次需求描述和相关源文件。
原始最终报告及模型收据（本地材料：`evidence/message-hold-2026-10-05/opus-review.json`）。

采用的修正包括：避免无关/不位移的滚动取消长按、暂缓贴底、实时查找列表节点、
手势开关与选择样式对齐、部分文字选择、行内代码例外、迟到的系统菜单抑制、
文件大小读屏描述、稳定的媒体查询订阅、触屏按压样式、长标签换行。

复核中关于导出重复提交、旧节点焦点和引用快照的担忧，经读取完整实现后已有
保护：导出共享状态同步去重，App 的 focus getter 按消息/会话重新定位并回退，
引用按 ID 回源。仍补了导出按钮的显式 busy 防卫。没有将推测项记录为已复现缺陷，
也没有声称 Opus 对修正后版本做了无条件签字。

## 边界与早期失败

- 固定 500ms 阈值及触觉反馈尚未覆盖 iOS/Android 真机和辅助功能延迟设置。
  WebKit 浏览器通过不等于 iOS WebView / 系统选区 / 键盘与触觉通过。
- 初轮测试仍找旧的“打开”可见按钮，中文/英文选择器已更新到文件主按钮语义。
- 初轮 Claude/DeepSeek 测试在图片和虚拟布局仍变化时发出长按，触发取消；
  测试改为等待图片与布局稳定再触摸，两家复测通过。其后按 Opus 建议修正
  不位移滚动误取消，并增加流式/无位移滚动回归。
- 首次从错误工作目录启动测试未发现用例，不计为运行通过。
