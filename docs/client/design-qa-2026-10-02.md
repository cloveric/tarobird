# Grok Bot alignment — TaroCub client

final result: passed

Date: 2026-10-02. This result applies to the bounded refinement below. It is
not a claim of complete parity with the native Grok Bot app or a release gate
for all TaroCub features.

## Design standard

The user's explicit acceptance reference is **Grok Bot**. Future client work
must preserve its level of readable conversation hierarchy, restrained surfaces,
consistent typography, clear selection and purposeful interaction feedback.
The reference is the application UI in the [official interactive demo](https://x.ai/bot),
linked from the [launch article](https://x.ai/news/introducing-grok-bot).
The marketing hero is not the application design target.

TaroCub retains its Bot → independent chat and group → independent topic model,
custom avatars, accent and native engine controls. These are intentional product
differences. Decorative mascot scenes, novelty motion and repeated framed panels
are not the direction for routine work surfaces.

## Required design surfaces

- **Typography:** system UI/CJK fallbacks retained; Bot names, child conversations,
  metadata and content have distinct weights and sizes. No display font introduced.
- **Spacing:** consistent rounded conversation surfaces, softer references and
  shorter composer. Virtual message transforms remain owned by the virtualizer.
- **Colors:** neutral canvas, one restrained accent, clear sender contrast. Measured
  user-body contrast 13.27:1 light / 10.06:1 dark; links 8.87:1 / 7.03:1.
- **Assets:** existing custom avatar still renders; defaults remain identifiers.
  No Grok logo/art copied and no new decorative assets or dependencies.
- **Copy:** group subtitles reflect actual group/topic semantics. No new fake
  progress label. Navigation cleanup affects excerpts only, not source/copy/export.

## Flow acceptance

1. **Chat and sidebar — passed.** Sender separation, readable excerpts and real
   demo reply via the isolated Hub/Gateway verified.
2. **Groups/topics and questions — passed.** Selected topic and parent group visible;
   question selection, Next, multi-select and Submit produced the expected receipt:
   “直接打磨细节”, “手机操作, 阅读与动效”.
3. **Rich messages — passed for sampled formats.** A fixture file, caption, fenced JS
   and link were sent together. Code colors, file action, link preview and quote
   navigation verified. File download and voice recording were not rerun this turn.
4. **Phone/settings — passed.** No horizontal document overflow at 390×844;
   settings measured exactly 390×844. Theme controls and returning to chat work.
5. **Motion — passed for sampled controls.** Reduced motion gives dialog animation
   `none` and button transitions `0s`. Virtual rows have no animation or transition;
   no message entry effects or decorative loops were added.

Console inspection returned no errors. Browser facts are in
grok-ui-browser.json（本地材料：`../../docs/client/evidence/grok-ui-browser.json`）.

## Checks, limits and follow-up

- Focused tests: 2 files, 5 passed. Frontend translation check, TypeScript and Vite passed.
- Required full gate: **222 files passed; 3469 tests passed, 1 skipped**. Root build passed.
- Design implementation used actual Claude Opus 5.5 with xhigh; parent performed
  rendered QA and the final excerpt/contrast fixes. Model receipt（本地材料：`../../docs/client/evidence/grok-ui-opus55.json`）.
- Public Grok demo was inspected; its private/native settings and every animation
  were not audited. Mobile native packages and real-engine matrix were not rebuilt
  or rerun. No production services or VPS deployment changed.
- P3: TaroCub retains more composer tools and a taller two-line input than Grok's
  one-line demo. This supports existing file/voice/collaboration workflows.
- P3: Sender action rows reserve space to prevent virtual-list jumps; short exchanges
  have more vertical spacing than the reference. Revisit only with measured scrolling
  and keyboard/mobile interaction checks.
- Sidebar cleanup intentionally handles paired bold prose only; full code snippets
  and complex Markdown excerpts remain literal rather than loading a parser on startup.
