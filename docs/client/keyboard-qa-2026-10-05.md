# 手机输入与短视口验收

日期：2026-10-05。沿用当前 Atelier 视觉体系，聚焦输入时的空间分配与操作可达性。
实际 Opus 5.5 xhigh 负责布局分析和 `viewport.css`，父代理负责键盘接入、控制器、集成与验证。
本报告的浏览器键盘信号是受控模拟；不能代替实体 iOS／Android 的键盘、手势或安全区验收。

## 已复现的问题

原配置声明 `Keyboard.resize: body`，但没有安装或注册 `@capacitor/keyboard`。
页面使用 `100dvh`；Chrome 中把 body 的可用高度设为 500px，窗口仍为 844px 时，
输入区下边缘仍在 844px，落在可见范围之外。这个实验用于解释布局缺口，
不宣称真实系统必然以同样方式缩放。三条独立浏览器回归在修改样式前均失败。

## 接入边界

- 安装并注册 `@capacitor/keyboard@8.0.6`。iOS 采用 Native resize，Android 使用
  `adjustResize` 和 `resizeOnFullScreen`。两套生成的原生工程已包含该插件。
- 单一控制器合并窗口、visual viewport 和原生键盘事件，在动画帧更新尺寸变量，
  不为每一帧触发 React 重绘。原生窗口已经缩小时不会再次扣除键盘高度。
- 浏览器双指缩放不作为键盘信号；控制器卸载时清理事件并恢复原有页面变量。
- 接入参考 [Capacitor v8 Keyboard 官方文档](https://capacitorjs.com/docs/apis/keyboard)。
  插件注册成功不等于原生编译或真机验证成功。

## 验证流程

1. 手机群聊引用长消息，输入文字并附带两个文件；缩小可见区域，检查标题、输入、发送和消息滚动。
   恢复、缩放再还原后，草稿与附件仍保留；最终发送产生一条含文字、引用和两个附件的消息。
2. 短视口下创建群组：名称保留、Bot 可选、创建按钮可滚动到达；随后检查设置标题和内容滚动。
3. 配对表单输入主机名，短视口下可到达连接按钮；还原并旋转到宽屏后保持正常布局。
4. 在当前 Chrome 预览页实际打开流程，保存并检查截图；受控修改在结束后还原。

## 验证记录

Chromium 和 WebKit 最终各 **30 项通过**，其中每个浏览器包含 4 项新增键盘／短视口流程。
覆盖手机 IM、多主机草稿、附件、引用、语音、提问、语言切换、返回、创建和启动故障恢复。
根检查为 **236 个文件、3,792 通过、1 跳过**，构建通过；客户端构建及翻译检查通过。
详细数据、源码和日志指纹见 验收回执（本地材料：`evidence/keyboard-2026-10-05.json`）。

父代理根据失败和截图补充了三处修正：

- 配对页只设 min-height 仍不足，改为在可见区域中独立滚动；两浏览器首次失败、修正后通过。
- 桌面创建焦点出现两次失败。仅把弹窗清理改为布局阶段仍不足；最终将聚焦请求保留到新会话提交后执行，最终两套完整浏览器用例通过。手机仍不自动唤起键盘。
- 新建群组头像被通用 span 的 flex:1 横向拉伸，实测 86×32。文字与状态采用明确的样式范围后，实际截图和回归均确认头像为 32×32。

根检查还保留了两类失败记录：160 次持久写入的缓存压力测试在 5 秒时限内超时，
单独约 3.2 秒；为该测试增加时限至 20 秒，未减少流量或修改断言。另一次与浏览器
同时运行时，128 MiB 解压测试超过 5 秒；归档代码和断言未改，独立运行完整根检查后通过。
