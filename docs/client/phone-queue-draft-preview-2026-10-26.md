# 手机待执行底色与未发送图片预览

## 问题与修改

“待执行”入口没有按任务状态切换底色。手机打开队列再系统返回时，WebView
保留了按钮的 `:hover`，全局按钮规则把背景留成灰色。用户随后明确更喜欢
灰底：现在仅在无悬停能力的设备上，入口空闲和悬停均使用现有 `--hover`
主题底色，浅色时为浅灰、深色时为对应深灰。桌面悬停、键盘焦点、队列内容
与排序不变。

未发送图片走 `AttachmentDraft → DraftAttachmentPreview → LocalImagePreview →
ImageViewer`，读取本地 File，不经过 Host 下载。文件名、自然尺寸和缩放比例
正常，不等于图片已经绘制到屏幕。Android 隔离 WebView 中观察到图片已解码、
可读到像素但屏幕仍黑；去掉画布常驻的零位移 `translate3d` 后，同一实例立即
显示。只去掉这个变换仍在重复打开问题样本时见过局部未绘制，因此没有把那版
当作完成。

最终修改为：

- 静止画布使用 `transform: none`；只在横向滑动反馈期间设置二维位移。
  松手、取消、多指接管、切图和关闭沿用原来的清理入口，清除整个变换。
- 全尺寸查看器使用 `decoding="sync"` 请求图片与该帧一起呈现；缩略图继续
  异步加载。没有添加解码 Promise、重试定时器或重复创建图片的补丁。
- 不修改 File、图片格式、清晰度、上传内容或保存的原始字节。不修改单击
  显隐工具栏、双击缩放、拖动、惯性、长按、原生全屏租约和返回规则。

这些是 App 的触摸样式与图片绘制修订。Host、CLI、消息、附件存储和协议不变，
不需要新增 CLI 命令。

## 验证与边界

基线中的队列系统返回用例因灰色悬停残留失败；查看器静止画布用例因残留恒等
变换失败。修订后验证触摸窗口、窄／宽桌面、拖动及取消、图库边界、焦点恢复、
队列排序与草稿保持。新增原生断言直接采样截图中的图片像素，不只检查 DOM
可见性、`onload` 和自然尺寸。

可重复的原生用例：使用 `client/scripts/image-viewer-phone-build.mjs <外部目录>`
构建隔离 fixture，以 `-PtarobotApplicationId=com.tarocub.client.appearancetest`
构建 App 与测试 APK，运行：

- `AppearanceTest#draftPhotoPaintsAfterOpeningAndReopening`：生成 JPEG 后通过
  正式未发送附件组件打开，连续重开三次、检查实际绘制像素与附件仍在草稿中。
- `AppearanceTest#imageToolbarDoesNotResizeNativeCanvas`：原有原生触摸显隐、
  每帧几何和系统安全边距回归。

另外使用用户提供的问题图片，在 Android API 36 隔离模拟器中进行了最终
三组各三次打开／关闭，共九次，九张截图一致且图片完整显示。问题样本未放进
仓库。一个收到的 JPEG 缺少结束标记；这只是样本特征，不能证明用户原文件损坏，
也没有据此修补或重新编码图片。正常 JPEG 也单独检查过。

早期显式调用 `decode()` 的实验未能稳定修复，已经撤销；不能把那个阶段的
通过用例计作最终实现的验证。复现具有时序性，旧变换在部分重复实验中也会
正常显示。当前证据支持本次绘制兼容修订，但没有物理 ColorOS 手机验收，
不能保证覆盖该设备全部 WebView／GPU 条件。浏览器 WebKit 也不等于 iPhone
真机验收。

证据目录：`/Volumes/gdrive/taro-tmp/phone-queue-draft-preview-20261026`。
本轮不发版、不更新已安装 App、不重启生产 Host。
