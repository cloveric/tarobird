# Agent Bus 返回 ADHD 后的整页滚动条

## 原因与修复

在 Mac 安装版实际点击「打开 Agent Bus → 收起 Agent Bus」，窗口右侧和底部立即出现粗滚动条；使用当前源码的独立 Cocoa/WKWebView 窗口也能复现。

配置页的协作方式使用 `fieldset`，其中供读屏使用的隐藏 `legend` 是绝对定位。宽窗口的 Bus 停靠栏没有为它提供定位容器：即使面板已隐藏且宽度归零，原生 WebKit 仍将标签相对页面的位置算入整页溢出。横向滚动条占用高度后，又产生纵向滚动条。窄窗口的浮动停靠栏原本有定位，不能只测这一种布局。

现在由 `.agent-bus-mode-picker` 建立定位容器，隐藏标签随其父级一起被停靠栏裁切。保留读屏分组名称、面板收起动效和内部滚动；没有给整页增加 `overflow:hidden`，也不卸载 Bus 编辑器、清除草稿或改动消息队列。

这是桌面客户端的 CSS 定位修复；手机布局、Hub 协议和 CLI 能力不变，CLI 无新增命令需求。

## 验证

- 安装版复现与源码验证分开进行。源码使用隔离 Hub、临时对话和独立原生 WebView，没有替换已安装 App，也没有向真实对话发送测试任务。
- 原生基线：1500×850 内容窗口，收起后整页横向溢出 25 px、纵向溢出 17 px，并出现两个原生滚动条。
- 最终 CSS 修复：宽窗口连续三次打开、收起，横纵溢出均为 0 px，`html` 的 overflow 仍为 visible；缩到 1100×610，再打开、收起及返回普通聊天，也没有外层滚动条。实际输入草稿、向上滚动消息和返回聊天后，草稿仍在、消息区仍可滚动。
- 新增浏览器路径覆盖 1600、1100、1360、1359 四种宽度，每种两次打开配置页并收起；检查隐藏标签的定位容器在停靠栏内、整页无溢出、面板草稿保留。另核对多列网格的横纵滚动、最后一行发送按钮、手机尺寸下的隐藏面板和返回普通聊天。
- Playwright WebKit 的原始几何测试没有复现原生缺陷，因此增加定位容器检查，并以实际 Mac WebView 的前后对照确认修复。
- 既有 Bus 列表折叠测试在冷启动后等待 5 秒，但列表的下一次刷新周期为 6 秒；移除本次 CSS 的基线也失败。该断言改为等待 10 秒，保留原有折叠状态和草稿断言，没有调整产品轮询频率。

最终相关浏览器回归：Chromium 10 项、WebKit 10 项全部通过，涵盖本次切换路径及既有拖动、阅读、工作台、列表折叠、成员定位与草稿导航。客户端翻译、类型检查和生产构建通过。本次仅改客户端定位样式，未重复运行无关的主机全量单元测试。首次回归中有一项既有 WebKit 流式阅读检查出现 1 px 的段落位置误差，单独复查通过；没有改动阅读实现或放宽它的断言。验证日志及原生几何记录保留于外置盘的本次临时测试目录。
