# 设备加入与配对体验修订（2026-10-23）

由 Codex 实现，CC1 的 Claude Opus 5.5（1M，xhigh）独立审查并编写二维码回归。基线为 d6bc91e。对象是新设备加入流程，以及已有设备上二维码和确认入口的可发现性。

## 用户旅程

1. 已连接手机：我的 → 设备与网络 → 添加设备。电脑：工作台菜单 → 设备与网络 → 添加设备；空工作台另有「添加设备 · 显示二维码」。按钮注明手机、平板或电脑，已有线路立即显示连接二维码。
2. 新设备：扫描连接二维码或粘贴连接信息。页面明确告诉用户从哪里找到它。输入设备名称并请求连接后显示 8 位配对码。
3. 已连接设备：点「已扫码，输入配对码」，核对主机和 8 位数字后确认。已在新设备取得配对码的人可直接点「输入配对码确认」，省去分享步骤。
4. 新手机连接成功后自动进入聊天。新电脑若携带自己的 Bot 加入网络，仍需在新电脑明确确认主机成员加入。

「连接状态与线路」用于查看和修改访问线路；「设备与网络」用于添加设备和主机组网；「设备与安全」管理名称和访问授权。网络本身的名称及已有成员关系不因导航改名而变更。

## 本轮问题与处置

| 问题 | 处置 |
| --- | --- |
| 添加主机不包含手机，二维码藏在确认按钮及设置页后 | 明确为添加设备；直接进入独立邀请向导 |
| 已有局域网地址仍需点击开启配对 | 新组件只读 host-routes；已有地址直接出码，不调用监听器配置或网络写入 |
| 第一次还没有地址 | 保留显式生成局域网/Tailscale二维码，说明网络条件；准备期间不能关闭或离开向导 |
| 两种二维码的说明混用 | 连接二维码用于连接；新设备的确认二维码用于填入 8 位配对码，扫码说明分别对应两端 |
| localhost/未指定地址不适合分享 | 过滤回环、未指定和非 HTTPS 地址；为空时给出下一步，不构造非法 payload |
| 读取失败、身份不符或迟到响应可能误导 | 可重试，严格检查 host key，卸载/换主机后忽略旧响应 |
| 离线或旧监听地址仍看起来可用 | 显示保存信息及主机监听异常提示；明确恢复或重新生成，而非自动重配 |
| 手机独有的中转地址丢失、默认线路失效 | 合并手机保存的 VPS；去重并遵守 8 条中转上限，优先保留当前使用的中转；默认跳过主机报告未监听的线路，本机优先局域网 |
| 未组网的多主机邀请目标不清楚 | 显式选择可管理主机，页头显示名称与公钥尾号；不自动跨网络切换 |
| 时间偏差导致过早显示配对码过期 | 取得 HTTP Date 时保存服务端时差；旧数据和无 Date 响应保持兼容；待确认列表使用 ready 的服务端时差 |
| 无管理权限还提示重试确认 | 不请求 owner 待确认列表，显示权限原因并禁用确认入口 |
| 旧说明与按钮不一致 | 同步中英文、用户指南、CLI help 和相关测试 |

打开二维码不会批准设备。真正授权仍由现有签名设备操作执行，未知响应不自动重发。手机保持独立授权；主机的 Bot、文件及成员协议未改。

## CLI 与后续边界

这是客户端流程和文案修订，无新增 Host 能力、协议或 JSON 格式；CLI 沿用 `pair`、`devices approve` 和 `network` 共享实现。CLI help 更新为新手机或电脑，用户文档同步入口。本轮不发布独立 CLI 包或外部软件仓库版本。

`pair` 的输出保留纯 CLI 首次设置路径：没有已授权手机时，可在主机终端运行 `tarobot devices approve <配对码>`。浏览器跨源响应未暴露 Date 时，配对时钟校正回退到原有本地时钟行为；本轮不修改 Host CORS 策略。

显式在 App 准备新线路时，既有签名线路发布行为保持不变；本轮只让「显示已有二维码」成为只读。CLI `pair` 本身不修改组网共享线路，该既有产品差异仍在 CLI 文档明确说明。

协调主机离线时保留明确原因；同网其他 owner 主机作为显式备选的流程尚未新增。不能把跨主机同步未验收说成全网任意设备都已验收。
