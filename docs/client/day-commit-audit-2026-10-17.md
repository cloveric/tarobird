## 审阅方法

主审检查提交历史、入口映射、调用链和现有测试，并对候选问题先补回归、
观察旧实现失败，再做窄范围修复。另以实际 `claude-opus-5-5`、`xhigh`
运行三组独立只读审阅：

| 分组 | 覆盖 |
| --- | --- |
| Host / CLI | `src`、`tests`、根脚本、协议、权限和队列，以及 CLI 使用说明 |
| 原生 / 发布 | Rust、Android、构建与更新脚本、CI、更新界面、下载凭据 |
| 客户端 / 展示 | React、样式、浏览器测试、首页与桌面/手机展示素材 |

审阅进程仅允许 Read、Glob、Grep，不修改代码或操作正在运行的主机。
候选发现必须由主审核对；静态意见和历史验证记录均不代替当前测试结果。
修复后再由同一实际模型独立复核补丁、边界和回归用例。第四轮提出的
会话有效期问题已复现并修复；另外两处竞态/慢传疑点按下述方法验证。

## 已复现并修复

### 批量跨主机传文件触发自身限流

每次逻辑操作要先取挑战，再发签名请求。上传一个小文件需创建、写块和
完成三次操作，即至少六个 HTTP 请求。旧实现连续上传 20 个小文件会耗尽
目标现有的 64 请求突发额度，挑战阶段报对端不可用，正常批量发送无法完成。

发送端现按目标公钥在传输前分配间隔 300 ms 的操作时隙，给共享入口的
8 请求/秒限制保留余量。本地等待队列有界，且短于通行证有效期；不改变
接收端安全限流，不在超时或丢回执后自动重发。真实 TLS 套接字回归上传
20 个文件并检查目标消息的 20 个附件；旧实现失败，修复后通过。

### Bot 拒绝日志绕过既有采样和保留分区

新增的 `bot-message.rejected` 未注册为低信任日志。40 次无效通行证请求
会产生 40 条详细数据库记录；大量同类记录还会被当作可信操作，挤掉授权
等重要收据。现接入既有拒绝采样和保留策略：每窗口保留样本，剩余次数
汇总记账；维护时使用低信任分区，不挤占重要操作的额度。正常 wait 轮询
仍逐次记账，但也进入有界的常规流量分区，避免长时间等待挤掉授权收据。

真实 HTTP 请求和 100,005 条记录的保留测试均在旧实现失败、修复后通过。
正文、文件字节及凭证不会加入审计日志。

### CLI 回复文件名丢扩展名及跨文件系统长度问题

旧实现直接截取文件名的前 120 个字符，长 ASCII 名会丢掉 `.txt` 等
扩展名；多字节名称加附件 ID 后可超过常见文件系统的 255 字节限制。
Mac APFS 上的中文样例能够写入，因此这里的字节长度问题是可移植性缺陷，
不冒充已经复现了 Mac 写入失败或 Linux 真机失败。

现保留短扩展名，按 UTF-8 字节及字符边界截断主文件名，整个叶名称不超过
240 字节，并验证附件 ID 不含路径成分。测试覆盖长中文、长 ASCII、原始
文件字节、再次 wait 复用相同路径，以及不安全 ID 在请求文件内容前被拒绝。

### 已签名回复仍可能包含不安全文件元数据

远端签名证明消息来自哪个 Hub，并不证明它返回的文件路径安全。旧 CLI
直接将远端 `file.id` 拼进输出路径，未限制路径分隔符。现下载前整批校验
ID、文件名、正整数大小、MIME 和 SHA-256，并保持输出文件独占创建、
已存在文件按哈希复用的规则。恶意 ID、负数/过大尺寸和错误哈希均在读取
文件内容前拒绝。测试使用受控恶意响应，不访问真实用户目录。
同一边界还包括默认输出目录使用的目标 ID 和消息 ID：解析结果须符合
共享 schema，主机 ID 必须对应正在通信的公钥；CLI 再次校验解析结果和
messageId。受控对端返回路径成分或另一台主机 ID 的五项反例在旧实现失败、
修复后拒绝，避免将签名当作任意目标或路径的授权。

### 五秒总超时截断正常文件传输

原来挑战探测和有内容的请求共用 5 秒总时限。真实 TLS 测试发送 8 MiB
并延迟 6 秒返回，稳定触发超时。现探测与连接保持 5 秒限制，已签名传输
使用按请求体大小计算的 15–60 秒总时限和 15 秒空闲超时；两种本机 CLI
认证路径都给外层调用 120 秒预算。通行证有效期、身份校验和不重发规则
不变。极慢或停止进展的线路仍会明确超时，并不承诺任意带宽均可完成。

补丁复核发现，Owner 会话仍按旧的 60 秒余量刷新，可能在 120 秒调用中途
过期。已改为提前保留完整调用预算及 30 秒余量，仅在发请求前刷新，不在
请求已发出后重试；剩余 90 秒的会话用例在旧阈值失败、修复后通过。

另用真实 TLS 接收端将 8 MiB 上传限速到约 400 KiB/s：21 秒内持续读取，
超过 15 秒空闲区间仍成功，且只收到一次请求。当前 Node 24.14.0 会检查
底层写队列的进展，未复现“单次写入必定在 15 秒被截断”的静态疑点；
保留此回归，不据此声称所有系统、带宽或 Node 版本均已验收。

### Bot 来源没有传到接收模型

原来来源只进入协议、队列和 App 标签，接收引擎拿到的正文与用户输入相同。
现通过每条消息的异步上下文传入本轮附加提示，包含来源主机/Bot/请求 ID
及层数，明确它是委托任务，不能据此新增授权、批准操作或披露无关资料。
提示使用稳定 ID，不把远端显示名称当作权限依据。

带问题卡的真实 Hub/Gateway 排队测试确认：任务仍等待原轮次结束、不误答
卡片，接收引擎看到对应来源，普通用户轮次不带这段来源提示。
第四轮另检查了“用户附件进入批处理等待后，Bot 任务立即到达”的情形。
通过真实 Hub/Gateway 投递，持久化调度仍按顺序处理；两次引擎调用各自
保留正确的 context-message，用户轮次没有 Bot 来源标记。该候选竞态未
在支持的入口复现，增加回归保护，不为绕过 Hub 的假设路径改动 Core。

### App 重发和转发丢失协作来源

普通“重新发送”会把跨 Bot 输入转成用户消息，失去原请求的回复关联和
Bot 专用队列规则。桌面工具条、手机消息菜单以及实际重发函数现在都拒绝
该输入及其错误回复走普通重发路径；来源 Bot 应核对原请求结果后决定新任务。
用户主动转发仍是引用行为，并保留原 Bot 与主机署名，不再误标成 Owner。

桌面/手机浏览器回归检查原任务和失败回复均不提供普通重发，数据库仍只有
一条原始输入；Host 转发回归检查署名和原消息 ID，同时不伪造新的签名来源。

### Mac 退出更新等待时遗留完整 App 副本

只有 Rust Drop 清理临时备份不足以覆盖进程退出。现准备阶段写专用标记，
下一次更新仅清理同一 App、结构合法、且系统确认原进程已退出的准备目录。
存活/复用 PID、其他 App、旧版无标记目录和开始替换后的恢复备份均保留。
进入替换前删除准备标记并同步目录，确保崩溃后不会把恢复副本当作垃圾。

真实 Mac Rust 回归以已退出的子进程模拟遗留准备目录，检查新尝试清理它，
同时保留活跃及恢复副本，原 App 和用户数据不变。另对齐普通 Host 启动的
`NODE_OPTIONS`/`NODE_PATH` 清理，并给原生等待增加锁等待与停止阶段的预算；
后两项是调用链加固，不声称复现了用户机器上的事故。

  造成失败，也会让“慢请求”场景未经模拟就通过。仅在这组依赖 HTTP
  拦截的测试中禁用 Service Worker，并断言请求确已被捕获；不修改产品
  的离线能力。离线页面和附件由原有专门套件覆盖。
- **已核对未改动**：ADHD 对话/主机隔离、草稿归属、问题卡隔离、上传时
  导航保护、图片手势、已有文件凭据恢复、撤销只读边界及线路切换没有
  得到新的确定缺陷。保留测试结论，不能据此保证以后没有任何问题。
- **保留产品行为**：未连接 Bot 默认隐藏及提示符合当前约定；不擅自增加
  宽限期或改成未读例外。归档的协作对话仍受归档保护，调用方需明确恢复
  对话或选择新对话，不自动取消用户归档。
- **待特定环境验收**：外置盘安装 App 与系统临时目录不同卷时的上游
  Tauri 替换限制；不同所有者的 App 权限；旧 Claude/Kimi 版本参数兼容；
  沙箱权限下的 CLI 凭据/loopback 访问。这里只确认调用链和测试缺口，
  不声称这些环境已经真机通过。
- **暂不扩展设计**：断点下载、回复分页、memo 清理、更多发布记录的分页、
  损坏 ADHD 布局的显式重置、下载取消后的缓存复用及 GitHub 登录类型兼容，
  仍为后续专项工作；没有把未经验证的猜测写成已修复 bug。
- **明确兼容边界**：CLI 继续使用共享的 512 MiB 文件上限；对端单独提高
  上传上限不代表 CLI 已支持更大回复。新增响应字段也须按协议版本协调，
  当前严格 schema 不接受未知字段。共享中转/NAT 下的多来源争用仍可能
  被接收端限流，发送端节流不等于取消入口保护。
