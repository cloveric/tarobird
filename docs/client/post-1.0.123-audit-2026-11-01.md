# 1.0.123 发布后的整体复审 · 2026-11-01

## 范围与协作

审查从 macOS 1.0.123 的源码 `8ca8f06ade38e9e8e6d524b8f812247a520c56c6` 到本轮开始时的 `origin/main` `bbcced125b65513de3a8ea54c31868e9e81ec52c`：15 个提交、108 个文件。包含浏览器扩展与页面操作、Design 自动打开与原生输入归属、工作台文件管理、屏幕授权设置、头像完成态、宽屏输入栏及相关 CI 改动。

主实现与实际 Claude Opus 5.5 分工审查、先形成发现报告，再隔离复现和修复，互相复核差异。Issue #103 原指定 Kimi，因订阅拒绝已由 owner 明确改为 Opus。该项继续覆盖完整 Agent Bus 链路，不把早已存在的问题称为这次发布之后的新回归。所有模型响应替身、浏览器测试和原生 Electron 验证分别标记；没有重启生产 Host、改实际权限、发布新版或替换安装版。

## 确认问题

## 未作为确认 bug 修改的项目

- 扩展移除后菜单“重装又复活”的假设被探针否定：重装前现有 unload 已清理；单独 clearStorageData 也未清掉原生策略规则。
- Design opener 的不可见目标、错误设备、跨对话、过期输入与尚未采纳的 steer 均保持拒绝；ADHD 仍只手动打开，普通单对话按明确请求自动打开。
- Agent Bus Stop/claim 竞争、ACK 顺序、重放重复执行与跨对话上下文污染假设未被证实。失去结果时不自动重发、离线停止等待确认等既有安全边界保留。
- “已取消/已停止”文案差异及 Hub 拒收阶段事件后的信息呈现属于观察项；后者未独立复现，不把它说成已修故障。
- Google 内置登录仍受站点兼容性限制；已有系统浏览器入口不等于内置登录已修复。扩展能力也不等于完整 Chrome 扩展 API 兼容。

## 收尾记录与限制

Opus 的三份 Electron 文件按 `opus/fix/frozen-files.sha256` 独立核对一致；主实现补上新取消原因的界面提示并验证重试。任务证据保存在 `taro-tmp.noindex/post-1.0.123-audit-20261101` 和 `agent-bus-103-20261101`，原始失败与成功运行均保留，未合并不同运行的指标。一次将新版回调测试用于旧实现的负向对照因等待不存在的回调被终止，不计为全套红证据；C1 以真实 Electron 对照为准。两项最终界面测试第一次因工作目录错误中止，改用 client 目录后 2/2 通过。

实际 Windows、手机系统层通知/权限/后台生命周期，以及真实付费 Kimi 引擎不在本次隔离环境验收结论内。全测试树 TypeScript 的 154 项既有错误由 Opus 对照未修改基线确认一致；生产编译单独验证。原生确认框等待期间，同一扩展队列的重置仍需等待回答，回答后的代次校验会阻止旧许可生效。未修改同一个无 key 文件夹并发首次安装可能生成不同随机 ID 的既有行为。

GitHub CI 本次已能运行。PR #106、#108、#109 的全量源码、原生及密钥检查通过；#106 的 Linux 全量逻辑测试为 7664 通过、12 跳过。#107 初次仅未修改的网络恢复测试出现 TLS `wrong version number`，其余 7661 通过、12 跳过；同一测试在其他三个 CI 通过，本地同 SHA 的四项网络恢复测试也通过。失败作业已单独重试，未将首次失败写成全绿。最终 main 的新 CI 与 PR 的检查属于不同运行。

进一步隔离确认，网络恢复测试释放“空闲端口”后，若明文 HTTP 服务抢先占用该端口，TLS 可选监听只记录绑定失败，随后健康检查会把 HTTPS 发到 HTTP 服务而得到 EPROTO。Opus 的五项强制场景复现了这一机制；原 CI 没有端口占用记录，且本机 OpenSSL 的具体错误串不同，不能把它说成原 CI 根因已确定。只加固测试：最多四次选择端口，确认实际 TLS 监听后才检查，耗尽明确失败，保留 CA、续约、Host 身份与本机存活断言。原四项加上强制碰撞与耗尽共八项，由 Opus 和主实现分别跑过。没有修改生产网络行为。

四个 Agent Bus 修复 PR 均已合并；#107 合并依据是已完成的独立差异复审、针对性及集成验证，单列记录其 CI 重试仍未完成，未宣称所有远端检查已通过。本轮源码与测试修订不发版、不更新已安装 App。
