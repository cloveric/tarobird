# 线路与 Agent Bus 后台读取优化（2026-10-19）

本轮接续 Fable 报告的 CW-02、AB-02。范围是客户端线路选择与 Bus 状态读取，
不改变主机排队、授权、幂等请求编号或任务投递协议。没有重启生产主机、更新已安装
App 或发布安装包。纯客户端读取策略无需新增 headless CLI 命令。

## 线路探测

原实现在线后每 1.5 秒探测全部配置线路，即使当前已是首选线路或文档已隐藏。
复现实验中，持续不可达的首选线路在 120 秒内被探测 80 次；隐藏文档也继续发请求。

修订后，活动连接的 WebSocket 心跳仍负责失联判断和故障切换；可选的线路健康扫描
按以下策略运行：

- 文档隐藏时跳过扫描，不因隐藏主动断开现有连接。
- 已在首选线路时，扫描完成后等待约 30 秒再刷新健康情况。
- 备用线路上的首选恢复检查从 3 秒开始逐级退避，扫描完成后的等待最长 30 秒。
- 一旦发现更优线路恢复，仍需三次连续的身份匹配样本，并等待无运行中任务、
  无待发送消息、无文件传输的空闲边界，才进行回切。
- 原生恢复、浏览器重新可见/获得焦点和网络恢复会立即发起检查；重复唤醒信号合并，
  不替换健康连接、不取消 HTTP 传输、不重新发送任务。暂停超过 30 秒的旧成功样本
  不参与新的三次确认。
- 线路编辑、连接代次变化、关闭或隐藏期间返回的旧结果不能触发回切；旧线路扫描
  也不能把编辑前的健康状态重新写回当前列表。

确定性计时测试中，不可达首选线路的 120 秒扫描数不超过 8 次；已在首选线路时
60 秒内为 2 次；隐藏时可选扫描为 0。该数字是请求数量验证，不是实机耗电测量。
没有操作系统网络事件时，备用线路上的恢复发现可能等待下一次扫描，再加该次请求
本身的网络耗时，随后还需连续确认和空闲边界；失联处理仍走原心跳预算。

扩展浏览器操作还复现了一处真实故障：两条 VPS 的 HTTP `/health` 都正常、
但 WebSocket 均断流时，第一条线路的短冷却已在第二条心跳等待期间到期，
重连又选回第一条，延迟使用第三条可用线路。现在重连优先选择尚未发生连接失败的
可达备选线路；恢复到高优先级线路仍保留原来的连续验证与空闲回切规则。
只有健康检查成功不足以清掉连接失败记录，须完成真实认证。

## Agent Bus 面板

原来收起的空闲 Bus 仍每 3.5 秒读取完整详情。实际浏览器复现收起后 7.5 秒发生
两次详情请求。现在收起且空闲时为 15 秒一次；面板展开或任务仍活动时保留
3.5 秒刷新，使 ADHD 成员状态继续更新。重新展开或从后台返回时立即刷新。
文档隐藏期间不轮询，重新可见后仍能收取已完成状态。

已有请求互斥、组件代次栅栏和草稿守卫保留；轮询不会提交保存、启动协作或覆盖
本地未保存配置/目标。切换主机或 Bus 后的旧读取仍不能覆盖新编辑器。

## 通知去重的保留边界

本轮没有给 IndexedDB 的 `notification:<messageId>` 任意设置 TTL。消息历史同步
可以替换本地消息集合，旧消息也可能稍后收到内容更新；仅删除超时收据或把标记
简单放在会被替换的消息字段上，会再次通知已经提示过的回复。

当前收据按主机缓存隔离，并随用户清理该主机缓存/重置而清理；每条消息保留一项
小型去重记录。它仍随历史消息数增长，不能称为已实现有界长期归档。若后续需要
硬上限，应先定义消息保留与历史通知资格，再迁移旧收据，并覆盖快照、跨窗口、
旧消息编辑和重连重放，不能以“性能优化”破坏不重复提示。

## 验证

- focused 连接回归：4 文件、45 项通过，包含原有文件传输、活跃任务、队列、身份
  不匹配、过期 handoff，以及新增退避、隐藏、唤醒、旧结果和多备用线路选择。
- 客户端翻译检查、TypeScript 和生产构建通过。
- Chromium 11 项、WebKit 11 项通过：覆盖线路断流时不重复执行、三 VPS 逐级
  故障切换、身份不匹配、恢复后实际消息往返；Bus 覆盖收起/展开/隐藏/活动状态
  和原有草稿、失效确认、读取恢复。不将之前失败和重复运行累计为额外通过。
- 浏览器 Chromium/WebKit 验证不能替代真实 Android/iOS 的后台电量、移动网络恢复
  或平台省电策略验收。本轮没有宣称这些物理设备项目完成。
