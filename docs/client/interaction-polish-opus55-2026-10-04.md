## 二、设计决策

1. **聊天操作菜单分为三组，按“对象”而不是“功能”排列。**
   - 本对话：对话设置、新对话。
   - 去往别处（行尾带当前值 + chevron，与“我的”页 cell 的导航语言一致）：连接、已归档对话。
   - 运行控制（仅在未检测到回复时出现，放在最后）：引导当前任务、停止当前轮次，各带一行说明。
   飞书和 Grok 的成熟做法都是把“导航/状态”和“对当前运行的控制”分开，罕用且有副作用的操作放在底部。
2. **不隐藏、不吞结果。** 引导/停止保留在原位置和原条件下，不禁用：客户端的 `replying`
   只看最后 8 条消息，可能漏掉附件批次、目标运行等，禁用会让用户失去唯一入口。改为照实说明：
   - 停止：“未检测到进行中的回复。仍会向 Bot 发送停止请求，结果显示在对话中。”（与 Gateway 的实际回执一致：已停止 / 当前没有正在运行的任务 / 批次取消通知；失败仍走现有错误横幅“未能确认所有 Bot 已停止…”）
   - 引导：复用桌面已有说明“补充到当前任务；不支持时会说明，不会改成排队”。不支持的引擎仍会在点击后看到现有原因文案（如“当前 Bot 的 CLI 接入暂不支持引导…”），不预先隐藏能力。
3. **“已归档”→“已归档对话”**（菜单行、列表标题、“我的”页 cell 统一），菜单行显示数量（>0 时），减少空跳转。沿用已有的“关闭已归档对话”“暂无已归档对话”用词。
4. **“打开连接设置”行改为状态行**：可见标签“连接”，行尾显示与桌面胶囊相同格式的状态（`主机直连 · 23ms` / 连接中 / 离线），图标随在线状态切换 Wifi / WifiOff。手机聊天页因此第一次能看到连接状态，而不增加头部元素。
5. **手机回复中，用输入框占位符说明两个按钮**：“引导当前任务，或排队到下一轮…”。动词与按钮标签（引导 / 排队）一一对应；只在输入框为空时出现，正是用户决定怎么发的时刻。选择占位符而不是额外提示行，是因为提示行会在回复开始/结束时改变输入区高度，与跟随最新消息的滚动逻辑冲突（Atelier 文档已有同样的约束）。桌面不变（已有 hint 和 tooltip，且占位符承担“/ 查看命令”提示）。
6. **头部摘要只拼接已知部分**：`[engine, model]` 过滤空值后再加强度；两者都未知时以“思考强度”作名词：“思考强度 · 跟随默认”。桌面连接胶囊用同一个过滤拼接。只用已有翻译键。

## 四、动效说明

本轮**没有新增任何动画、过渡或关键帧**。
- 菜单仍使用既有的手机底部弹层 `tc-sheet-up`（300ms，`cubic-bezier(.32,.72,0,1)`）。
- 行的按下/悬停背景沿用既有规则；chevron、数值、说明文字都是静态的。
- 占位符切换是即时的，不做淡入；避免回复开始时输入区出现“动态”干扰。
- `prefers-reduced-motion` 的现有全局规则不受影响。

## 五、未验证项与风险

1. **未构建、未跑类型检查**：新增派生值的类型按源码推断（`filter(Boolean)` 后 `join`），需 `tsc` 确认。
2. **翻译校验会失败**，直到补上 3 个 `en.json` 条目（见下）。`MobileHome.tsx` 使用单引号 `t('…')`，不在校验正则内，所以“我的”页即使漏补也不会报错，但英文界面会显示中文——补条目时一并覆盖。
3. **未渲染**：320 / 390px 下三组菜单的高度（底部弹层可滚动）、带说明行的换行、连接值的省略效果、深色模式，均需父代理实际查看。
4. 英文占位符 “Steer this task, or queue…” 约 26 字符；在 320px、单行折叠态下的截断情况未验证。中文 14 字符按 16px 估算约 230px，内宽约 268px，未实测。
5. `useId()` 生成的 id 含冒号等字符，作为 `aria-describedby` 引用合法，未在 WebKit 读屏中实测。
6. 占位符说明“引导”对不支持引导的引擎（Claude / Kimi / Antigravity）同样出现；这是有意的：按钮本来就显示，点击后给出现有的不支持原因。若父代理认为应按能力预判，需要额外请求 `/steer` 状态，属于新的网络行为，本轮不做。
7. 空闲时的“停止”说明写的是“结果显示在对话中”，依据是 Gateway `stop` 的回执逻辑；对非 Gateway 的 Bot 路径未核实。
