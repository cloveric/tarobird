# Bot 消息授权：现有命令的图形入口

## 本次范围

经 Owner 澄清和简化，本次只为现有 `messages send/wait/allow/revoke`
直接消息通道增加授权界面。由 Codex 独立实施；Owner 随后要求 Opus 5.5（xhigh）
独立审阅 UI 并进行实际操作，复审记录见文末。

**Agent Bus 的权限、成员、流程、配置、UI 和执行逻辑不在修改范围内。**
没有新增主机默认互通策略、三态例外、双向快捷授权，也没有更改任务队列或
撤权后的任务生命周期。不因为默认互通或兼容迁移隐式增加任何授权。

## 入口与行为

- 桌面/浏览器：设置 → Bot 消息授权；手机：我的 → 设置 → Bot 消息授权。
- 2026-10-27 补齐 Bot 设置页的「Bot 消息授权」入口，手机 Bot 列表、聊天详情和
  桌面均可使用。打开时默认选中当前 Bot，复用相同授权列表、签名保存和回读核对；
  Bot 离线不隐藏入口，是否可读写取决于主机连接和 owner 权限。返回时保留未保存
  修改的确认与保存期间关闭保护，并恢复入口焦点。仅打开入口不会增加任何授权。
  此入口是客户端展示补充，Host/CLI 能力和现有全局设置入口不变。
- 选发起方，在“它可以请求谁”勾选接收方，保存；“谁可以请求它”只读展示反向关系。
- `A → B` 与 `B → A` 独立。B 可以通过原任务回复机制返回结果，A 用原消息 ID
  查询，不需要 B 的反向发起权限。授权本身不会发消息或启动任务。
- 后续补齐 `A → A` 的显示、保存和撤销：当前 Bot 位于接收方首项，标注“自身其他对话”。
  授权仍由 owner 操作；旧主机提示更新。见[自身消息授权补充](bot-self-message-grants-2026-10-21.md)。
- 初次读取直接使用主机现有授权记录，包括通过 CLI 设置的关系，不创建新授权表，
  不覆盖或重新初始化旧配置。只显示同一主机当前有效 Bot 的直接消息授权。
- 离线状态与授权状态分开；离线 Bot 可以配置。稳定 ID 关联授权；改名无影响，
  删除的 Bot 不再列出，后来创建的同名 Bot 不获得旧 ID 的权限。
- 打开页面、回到前台/聚焦和页面可见时每 5 秒刷新。离开页面停止轮询；无并发轮询。
  在线状态和名称可在编辑时刷新，其他位置改过授权或增删 Bot 时保留草稿并要求重新核对。
- 保存只提交用户改变的方向，SQLite 单一事务内全部生效或全部回滚。服务端确认后再 GET
  回读核对；超时/断网不自动重发，不显示成功。重新载入可以核对已经生效但响应丢失的写入。
- 编辑未保存时切换发起方暂时禁用；可保存或放弃修改。离开设置使用既有放弃草稿确认，
  “继续编辑”返回本页。保存期间禁用关闭/导航与重复提交。
- 超过 6 个接收方显示搜索框，最多渲染 100 个匹配结果并提示缩小范围；单次最多改 256 个。
- 旧主机返回 404 时显示更新主机提示，不提供虚假的可编辑授权列表。

### 取消授权的现有边界

**本次沿用现有命令语义**：撤权会阻止后续发送和结果查询；已经提交的排队/运行任务
不会因此停止或取消。因此 UI 在取消勾选时提示先取回结果，再取消授权。
原始大方案中“撤销排队任务、运行中仍可取回结果”的协议升级已从本次范围移除，不能
把本次交付描述为已实现该规则。停止任务继续使用既有独立操作。

## 实现与权限

- `src/client-protocol/bot-message-grants.ts`：快照和命令 schema。
- `BotMessages.readGrants/updateGrants`：复用 `meta` 中现有 `bot-messages:grant:*`。
  快照只输出 ID、名称、在线状态和有效有向关系，不输出公钥/凭据/其他主机授权。
- `GET /api/bot-messages/grants`：已认证的 owner 读取。
- `POST /api/bot-messages/grants`：`{command, proof}`，command 为
  `{operation:'local-message-grants', sourceBot, revision, changes:[{targetBot,allowed}]}`。
  同时要求当前 owner 会话、一次性设备签名，签名绑定规范化完整 command 的 SHA-256。
  Bot 实例凭据不能调用这个 owner 接口，不提供自授权工具。
- revision 包含活动 Bot ID、现有本机记录和持久随机变更标识。旧 CLI 的本机 allow/revoke
  同样更新标识，避免其他客户端的旧草稿或允许→撤销→允许 ABA 覆盖新状态。
- 审计与授权写入位于同一事务，记录设备操作者、时间、方向及之前/之后的状态。
  现有单条 CLI 授权审计也纳入事务并使用真实设备操作者。
- 默认策略、Bus 配置、跨主机授权和消息投递/回执/文件上传路径保持原样。
- 桌面 Rust、Android Java、iOS Swift 签名器增加对已有 `bot-message-grant` 操作的严格
  64 位十六进制摘要支持，使用既有签名域；没有导出私钥或降级为不签名写入。

## CLI

`tarobot messages grants --json` 读取与 App 相同的主机快照。
写操作仍使用已有 `messages allow --from "HOST/SOURCE_BOT_ID" --bot TARGET` 和
`messages revoke --from "HOST/SOURCE_BOT_ID" --bot TARGET`，不启动第二个 Hub。
Bot 进程调用 owner 清单命令被拒绝；正常 Bot 仍使用原来的 send/wait 窄协议。
后续 UI 复审修订只涉及呈现、焦点和客户端读取调度，不改变主机能力或 CLI 命令。

### Opus 审阅发现及处理

独立审阅使用 Opus 5.5 `claude-opus-5-5[1m]`、effort `xhigh`，先查看首次交付版本，
再对修订构建进行收尾复核。测试使用独立合成 Hub 和独立浏览器会话，实际执行桌面、
390px/320px 窄屏、双标签页冲突、断网、慢请求、保存拒绝、键盘和中英文操作；
未操作用户真实授权。原始报告、最终报告、截图及命令回执保存在外置盘本任务目录。

| 发现 | 处理 |
| --- | --- |
| B1 保存/失败反馈位于视口外 | 放到保存按钮旁，首次读取失败仍在页面顶部显示。 |
| B2 自动轮询抹掉保存拒绝 | 后台 GET 不清除写入失败；显式“重新核对”保留草稿；未知结果仍需重新载入，不自动重发。 |
| B3 首次勾选使列表移动 | 未保存标记放在固定高度的发起方标签行。 |
| B4 保存/放弃后键盘焦点丢失 | 焦点丢失时移到反馈区域；用户已移到其他控件时不抢焦点。 |
| B5 标题样式/焦点和手机重复标题 | 复用设置分类直接子级标题及已有聚焦、窄屏规则。 |
| B6 搜索 Escape 直接关闭设置 | 有搜索文字时先清空搜索；空搜索仍沿用设置退出规则。 |
| B7 慢轮询阻塞放弃修改 | 显式操作中止后台 GET，以请求代数屏蔽旧响应；刷新图标显示进度并尊重减少动画偏好。 |
| U1/U2/U3 操作与方向文案 | 主按钮使用统一 primary 样式；去掉反向标记中的“也”；撤权说明使用用户语言和警示样式。 |
| U10/U11/U13 主机范围、状态与无障碍 | “本机”改“当前主机”；在线色与产品一致；复选框关联在线/反向描述，列表关联标题。 |
| U5 冲突后重放旧草稿的建议 | 保留严格全局 revision 和显式重新核对，不自动重放；文案明确重新载入放弃整份未保存修改。这是保守产品选择，不属于数据丢失修复。 |
| U4/U6/U7/U8/U9/U12/U14 扩展建议 | 逐行变更摘要、排序、额外 ID 信息、可点入站标签、大列表新交互、折叠说明及通用确认框重构暂不加入，保持本次简化范围。 |

Opus 第二轮实际复核确认 B1–B7 已修复，并补充发现：冲突说明仍可能在按钮上方视口外、
鼠标保存也出现键盘焦点环、慢速手动读取缺少就近状态。继续修订为：冲突提示统一进入
按钮旁反馈区；只在 `:focus-visible` 显示焦点环；手动读取显示“正在载入…”并冻结本次
选择、防止重复读取；后台轮询不旋转图标或阻塞放弃；顶部刷新不把焦点移到旧反馈。
专项测试验证长手机列表的冲突说明可见、鼠标无焦点环而键盘有环，以及慢载入期间的
按钮/选择保护。未追加 N5 的长提示，避免增加窄屏信息量。

Opus 第三轮实际复查确认 N1–N4 修复，补充一项低等级 C1：顶部刷新时禁用按钮仍使
键盘焦点落到 body。最终保持刷新按钮可聚焦，用 `aria-busy` 显示状态，已有手动请求锁
继续阻止重复 GET；Codex 在 Chromium 与 WebKit 补测通过。此最后一项由 Codex 验证，
不将其描述为 Opus 已再次实测。双方对保留严格冲突检查、其余非必要扩展留后续的取舍一致。

组合 emoji 头像、真实读屏器、原生手机的操作仍未验收；浏览器窄屏不能代替手机真机。
原任务范围内的单向请求、反向拒绝与开放反向后的结果回传由 Codex 的生产 UI/Hub/Gateway
测试验证，模型输出为脚本替身，不能描述为两个真实模型实测。
