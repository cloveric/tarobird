# Android 原生传输：读取上限与取消

2026-10-05。继续 TLS 身份绑定工作；没有增加应用层端到端加密，没有替换已安装 App、发布 APK 或改动 VPS。

## 本次改动

Android HTTP 继续使用 OkHttp 5.5.0；WebSocket 改用固定版本的
[Java-WebSocket 1.6.0](https://github.com/TooTallNate/Java-WebSocket/releases/tag/v1.6.0)，
由 `HubSocket.java` 封装。HTTP 与 WS 使用同一已绑定 Hub 身份的 TLS 工厂，保留
系统 CA、主机名和证书叶子绑定检查，只允许 TLS 1.2/1.3。连接直接到已验证的
Hub 地址；不协商压缩／其他扩展，不跟随跳转，不使用系统代理，不自动重连或重发认证。

旧 OkHttp 接收路径会先组装完整消息，再执行 App 的 1 MiB 检查。隔离比较中，
服务端只发一个声称有 1 GiB 数据的帧头，旧路径继续等待正文；新路径立即拒绝。
实际有限制的解码器在分配该帧正文前拒绝超限长度。分片另做累计大小及数量限制，
包括没有终止帧的分片和大量空分片。正常 1 MiB 分片及跨帧拆开的中文 UTF-8 均有覆盖。

| 范围 | 限制 |
|---|---|
| WS HTTP Upgrade 头 | 16 KiB，解析前检查；首帧与头同批到达不误判 |
| 入站帧／完整消息 | 1 MiB |
| 一个消息的分片 | 4096 个且累计不超过 1 MiB |
| 已交给前端但未确认的事件 | 每条连接最多 8 条且合计最多 1 MiB；等待确认最多 10 秒 |
| WS 连接名额 | 每个 WebView 最多 8 个 |
| 出站队列 | 每条连接最多 64 帧、2 MiB；自动 Pong 同受限制，关闭帧可能额外占一个控制帧 |
| 上传 | 每次 8 MiB，全部正在执行的原生上传合计 32 MiB |
| HTTP 读取 | 复用 256 KiB 缓冲，每个 IPC 块不超过 256 KiB |

这些数字描述消息、队列或请求预算，**不是整个 App 的内存峰值**。出站可能还有一个
正在写出的帧，入站可能还有一个等待前端额度的消息；TLS、解码器和 JavaScript 的
临时复制仍占内存，实体手机测量没有完成。

关闭只在收到合法的对端 Close 帧、并确认本地 Close 帧已写入和 flush 后才报告确认；EOF、超限和仅本地取消均不报
正常关闭。主动关闭发出 Close 后继续读取，并设置五秒等待期限，不把本地意图当回执。
已经验证的 SSLSocket 通过流适配器交给协议库；适配器只观察完整关闭帧的写入及
flush，所有字节仍走同一 TLS 连接。对端先关闭但停止读取、导致本地回复堵塞时，
也不会提前报告正常关闭。

慢接收测试复现了直接关闭 SSLSocket 会等待被阻塞的 TLS 写入，导致取消操作卡住。
现先关闭其底层 TCP Socket 解开阻塞，再由 IO 回调处理 TLS 资源释放；原始线程栈
保留在本轮证据中。上传预算直到原生执行退出才归还，返回响应后清除请求体引用；
未知结果的上传不自动重放。旧连接错误只能作废其自己的证书绑定代际。

## 验证范围

`client/scripts/android-transport-audit.mjs` 以 Java 8 目标编译生产 `HubTls`、
`HubSocket`、`HubTransport` 源码，在 JVM 上运行真实临时 Hub、TLS 证书和异常端点。
依赖的版本及 SHA-256 记录在 `client/android/audit/dependencies.json`；没有安装
系统 CA 或接受 Android SDK 许可。

包含真实配对与设备认证、HTTP/WS、冒用代理拒绝、证书轮换、8 MiB 上传、512 MiB
下载哈希，以及握手超限、非法扩展／跳转、超大帧头、分片、UTF-8、取消、名额和预算
恢复。512 MiB 的耗时来自本地回环，不能代表手机／VPS速度。

本轮 JVM 核心检查 71 项通过，Chromium／WebKit 桥接合同各 11 项通过；共享测试端点

通过、1 项已有跳过，构建通过。移动端 303 个前端资源与本次构建相同。

最终结果、Opus 5.5 xhigh 复审记录及源码哈希见

## Opus 5.5 xhigh 复核处理

实际 `claude-opus-5-5 --effort xhigh` 对初稿完成静态复核，耗时 1014.356 秒；
原报告见 Opus 报告（本地材料：`evidence/android-socket-bounds-2026-10-05/opus-review.md`）。
报告明确说明部分库行为来自旧版记忆；下面结合固定的 1.6.0 源码和测试逐项处理，
不把推测全部算作已复现缺陷。这是初稿复核后的修正与验证，**不是最终版本的 Opus 再次批准**。

- **H1：阻塞写入时 TLS close 卡住。** 已有 JVM 线程栈复现；改为底层 TCP 先取消，
  TLS 释放留给 IO 回调。取消延迟测试通过；Conscrypt／真机 ANR 仍待验收。
- **M1、L3：重复 Close 和未写出回复却报告正常关闭。** 本地主动 Close 只发一次；
  对端回复走完成分支，不再次回声。只有本地关闭帧 flush 与对端关闭帧两项均满足才报正常。
  协议端统计只收到一个主动关闭帧；另保留旧逻辑在堵塞写入时误报正常的失败收据。
- **M2、L2：迟到异常／打开超时漏终态。** 失败通知只发一次；取消后的 TLS 异常不再
  报错或作废绑定。只有信任校验失败才作废对应绑定；DNS 未返回时也能先报告打开超时，
  迟到连接不能复活。相应用例通过。
- **M3：并发关闭 HTTP 读取缓冲。** 取消只直接中断 Call；响应体清理交给独立、有界
  执行器，并与读锁串行。正在清理的名额仍计入 HTTP 上限；拒收响应在全局锁外关闭。
  阻塞读取、重载取消及后续文件哈希通过；没有声称复现过 SegmentPool 内存破坏。
- **M4、L4：存活及寿命。** 已核实共享 `connection.ts` 有前台心跳和 1100 ms 无回复
  检查；15 分钟令牌在到期前 30 秒续连，早于原生 20 分钟兜底期限。生产下载按
  `CHUNK_BYTES` 发 Range 请求，五分钟约束的是每次请求；512 MiB 单请求只是隔离压力样本。
  锁屏、Doze 和真实网络切换的检测耗时仍未验收。
- **M5：256 KiB 聚合。** 当前 HTTP 用于有限响应／文件，聊天和过程事件走 WS。
  未来若加 SSE／NDJSON，必须另外实现按到达交付；本轮未宣称支持这种 HTTP 流。
- **M6：接收窗口。** 核对 1.6.0 后删除显式 `setReceiveBufferSize(8192)`，保留库的
  有界读取数组，不人为限制系统接收窗口。
- **L1、L5、L6、L7。** 忽略对端 Close 后的数据；复用 HTTP DNS 解析器，在总时限内
  尝试其他地址（仍使用同一 TLS 绑定）；取消步骤容忍已关闭资源；增加上传累计预算并
  明确队列限制之外还有当前帧、编码和桥接复制。多个地址回退、预算释放和写入取消通过。
- **V1：入站掩码。** 1.6.0 解码时确实不保留 mask 标记，检查 `Framedata` 不可靠。
  改为在连续的原始帧头上验证掩码及长度，不分配正文；完整／分段非法帧均被拒绝。
- **V2：UTF-8 分片。** 实测固定版本可以接收跨帧拆开的“你好”；没有为了测试取消分片支持。

本轮源码级与隔离验证不替代 Android API 24+ 的系统信任策略、SNI、原生桥接、
后台生命周期和真实手机内存测试。Android SDK 许可／安装及应用发布仍未执行。
