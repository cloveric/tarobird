## 修复的实际问题

真实 Codex MCP 表单中，点「下一题」后立即填字，输入可能丢失。旧逻辑在下一帧把焦点移到标题，抢走已经进入的输入框。真实失败截图、原生等待状态与延迟 RAF 的确定性回归共同确认了原因。

第一次改为 layout effect 加 ref 后，Opus 指出同题动作仍可能不触发 React 提交，留下焦点标记。配对 Hub 用例未暴露这个问题；静默连接与延迟草稿存储的真实组件 fixture 则稳定复现。最终改为每次导航递增的状态计数：切题/校验的提交阶段完成聚焦，普通输入和草稿恢复不触发聚焦。

回归验证了正常切题、上一题、重复当前题、重复空答案校验后的标题焦点，以及随后的连续文字输入。原有草稿恢复、多选限制、断网待发送和双端确认断言保留。Opus 最终代码复核未发现阻断问题。
