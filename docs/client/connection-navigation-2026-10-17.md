# 独立连接页面与线路表单（2026-10-17）

> 后续入口调整见 [2026-10-19 网络与连接](network-settings-2026-10-19.md)：设置新增网络分类，本文保留当时的改动记录。

## 问题与结果

原来的四项「主端部署方式」把 Bot 的运行位置与设备的连接方式混在一起。
用户只是给已有主机增加一个中转地址，却需要先判断电脑、VPS、直连或中转的部署组合。
新的表单直接表达设备要使用的地址，不再要求选择部署方式。

- 手机：在「我的」中，将「连接」放在「我的网络」正上方，并显示当前主机名称。
- 桌面：在「工作台」菜单中，将「连接」放在「我的网络」正上方。
- 「设置」只保留通用、通知、设备与安全；聊天里的连接状态入口仍能直接打开连接页面。
- 「连接」首先显示当前线路、已保存线路及其可用状态；点击「编辑线路」后修改。
- 表单包含可选的直连地址和可选的中转线路，可直连、只中转或同时保留两者。
  至少保留一条有效线路。直连优先，中转依顺序备用，恢复稳定后在空闲时回切。
- 「直连和中转怎么选？」收起较长说明。说明明确：地址必须通向同一主机，
  多台主机共用一台云服务器仍需独立入口；填入地址不会自动建立中转或迁移 Bot。

## 兼容与边界

`ConnectionPanel` 使用现有线路编辑器、本机身份判断及返回导航。
退出时保留未保存确认、保存中退出保护和焦点恢复；手机页面使用独立滚动区域。
本机直连地址仍由桌面端管理，本机对外连接通过原有 `DesktopHostInvite` 配置。

`connectionConfiguration` 根据实际地址构造线路，而不是根据旧的部署选项隐藏或丢弃输入。
旧二维码和已保存身份中的 `deployment` 信息在与线路兼容时保留；例如旧的只中转二维码
添加直连后会清除不再适用的 `vps-relay` 标记。未修改的 Tailscale 名称、自定义标签及证书信任信息保留。
主机公钥、配对授权、错误主机拒绝、HTTPS 要求和线路切换规则均使用原有实现。

这是设备本地连接管理的界面调整，没有新增主机能力、协议或数据库版本。
CLI 不需要新增命令；既有主机、中转、配对和组网能力保持可用。

  多中转故障切换、错误主机拒绝、120 MiB 上传/下载恢复以及 513 MiB 上传内容校验。

回归过程中更新了仍引用旧部署下拉框、旧菜单角色或默认 VPS 文案的测试定位。
另修复了新连接页同时关闭确认框与页面时的焦点问题：先卸载确认框，再关闭页面，
避免原入口仍处于模态遮挡状态时无法恢复焦点。最终浏览器整轮运行均无失败。

测试使用临时 Hub、真实网络接口及隔离的浏览器设备身份；涉及引擎回复的测试使用测试 Gateway。
浏览器手机视口与 WebKit 覆盖不等同于 Android 真机或 macOS 原生应用验收。
测试输出放在外置盘，未修改正式主机的线路或配对关系。

## 共用云服务器提示补充

「连接」概览和「中转线路」填写区现在直接显示「多台主机共用云服务器」说明，
不再要求用户展开帮助才能发现这条规则。首次配对的中转表单复用同一提示。

- 多台主机可共用腾讯云等云服务器，但每台主机都需要独立入口（不同端口或域名）
  和通向自己的隧道；不能把已指向另一主机的地址直接拿来使用。
- 先完成中转部署，再填写当前主机的入口。App 保存线路不会自动部署中转。
- 中英文同步，提示使用现有主题颜色；概览与编辑状态各显示一次，不重复堆叠。

这是说明与展示调整，不改变线路保存、身份校验或隧道部署逻辑，没有新增 CLI 能力，
因此无需新增 CLI 命令。本次仍只提交源码，安装包需后续发布。
