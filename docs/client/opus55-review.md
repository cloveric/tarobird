# Opus 5.5 xhigh 审查与优化记录

日期：2026-10-02。范围为本地客户端的 Bot／群／原生会话衔接、双端恢复操作、附件与发件箱可靠性。按用户要求先完善程序，部署仍延期。

使用本机 Claude CLI，显式指定 `--model claude-opus-5-5 --effort xhigh`，仅开放 Read／Glob／Grep，并禁用其他 MCP 和浏览器能力。每轮流式返回中的 assistant model 都是 `claude-opus-5-5`。审查模型只读代码；主 agent 复现、讨论方案、修改并执行测试。没有用其他模型代替。

## 讨论后落地的修复

| 问题与触发条件 | 修复及验证 |
|---|---|
| 所选会话消失、收据损坏或写入中断时，整个对话连 `/reset` 都被挡住 | 仍阻止消息进入不确定的上下文，给出具体错误；增加“清除会话选择”。owner 与对话所有者鉴权、版本比较、审计和双端同步；离线 Bot 不影响清除。四种错误的真实 Gateway 回归、Hub WebSocket 回归和手机→桌面浏览器测试通过 |
| Claude 在从未建立 session 的新对话中恢复旧会话后，`/detach` 没有作用 | 明确保存空的前态；切断解除绑定。先以回归测试复现 Claude 失败、Codex 正常，再修复；真实 Claude 双端验收通过 |
| “新会话”按钮发送不存在的 `/new` 命令 | 改为打开“新建独立对话”表单，预选当前 Bot；创建前不增加会话或给模型发消息 |
| 绑定下拉框看似未选择，实际上保留旧 session，按钮仍可点击 | 默认空值，只有当前已读取列表中的真实选择才启用；另一设备改变 bindingId 时清空本地选择 |
| 附件缺失／截断被当成服务器临时故障，发件箱不断重连重发 | 下载及转发统一返回不可重试的 410，转发回滚文件与记录。其他临时请求错误保持连接，单条持久退避；有限次数后显示重试／移除。同对话后续项暂停，其他对话可继续 |
| 运行中补发文字可绕过尚未应用的恢复选择，直接注入旧会话 | Gateway 在 steer 前检查最新选择的已应用收据；不确定或失败时先排队，再由相同恢复校验处理 |
| 按对话暂停发件箱后，失败的卡片点击原本不可见，会卡住后续消息 | 主 agent 与第三轮审查均发现；卡片操作现在也显示为待处理项，可重试或移除。真实 Hub 拒绝卡片操作后，检查暂停、可见入口与移除后恢复发送；Chromium／WebKit 均通过 |

额外优化：多 Bot 群面板可明确选择操作对象，原生命令只提及该 Bot，并同步输入框接收者；新建对话沿用所选 Bot。Bot 上下线原位更新，不改变侧栏顺序；群在线标记反映任一成员在线。发件箱用 IndexedDB 事务内单调顺序键，手动重试保留原 ID 和发送位置。临时存储错误与损坏收据区分提示；ENOSPC 注入验证写失败时不切换上下文。

## 讨论中的取舍

没有采纳“恢复失败后直接放行普通消息”或“当前 session ID 相同就把不确定收据视为成功”的方案。这可能把消息交给错误上下文。最终采用默认阻止、用户明确清除、保留原始收据的流程。

清除只取消 Hub 中的恢复选择，**不撤销已经发生的原生 session 切换**。中断后先切断或重置，再发普通消息；确认框和错误提示均明确说明。损坏收据清除后可使用原生 `/resume`，修复记录前列表绑定仍会拒绝。没有实现自动修复或猜测式重放。

失败操作不自动丢弃，也不让同对话的下一条消息越过它；用户可重试原操作或明确移除。包括旧版遗留的卡片操作，均有可见入口，不需要重新配对或清空数据。

第四轮定点复核确认：失败卡片操作的显示和阻塞条件一致，重试保留 ID，移除仅影响本地失败项；没有发现本轮改动新增的明确 P1／P2。审查回执记录实际返回模型和四轮成功结果：回执（本地材料：`evidence/opus55-review.json`）。

尚未认定为阻断 bug 的边界：如果非常旧的客户端曾把 `topic.create` 放进发件箱，旧失败项的 `groupId` 与现界面的 `conversationId` 展示存在潜在差异，当前客户端创建话题走 HTTP，未复现此路径；高于当前支持版本的收据会安全拒绝，但错误提示仍偏向存储问题。失败项需要进入对应对话才能看到。性能猜想未被当作确认缺陷或完成优化。
