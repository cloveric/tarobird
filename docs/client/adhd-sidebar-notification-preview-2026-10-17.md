# ADHD 侧栏与消息通知摘要

## 用户可见行为

- ADHD 左侧仍复用“按对话”的列表。现在显示 Bot 名称，拖动与右侧面板之间的分隔线
  即可调整宽度；默认 272 px，大窗口默认 288 px。宽度只属于当前窗口，重新打开恢复
  默认；模式切换保留当前宽度，勾选的对话和草稿不受影响。
- 去掉左侧列表的可见滚动条，鼠标滚轮、触控板及键盘仍能滚动。
- Android 通知标题示例：`「发布准备」 · CC1`；正文示例：
  `回复完成：已修复侧栏宽度，保留全部草稿。` 文件通知展示文件名，待确认和未完成任务
  使用相应提示，不把中断、部分完成或失败说成成功。

## 实现与兼容

`sidebar-resize.css` 让 `.adhd-shell` 复用现有 `Sidebar` 拖动、边界及重置逻辑。
`adhd-board.css` 删除额外隐藏 Bot 名称的规则；沿用普通列表在极窄宽度时的紧凑布局。

Hub 的 `push/preview.ts` 从已完成消息的可见正文生成摘要，整理 Markdown、控制字符
和双向控制符，跳过思考、工具日志、操作值与过程折叠区。遍历深度和元素数有上限。
目标及后台任务提示不会挤掉最终结果；技术比较符和泛型中的尖括号保留。
消息体总长仍不超过 v1 的 200 个 UTF-16 单元，截断不拆开 emoji 代理对。
对话名称来自目标对话，Bot 名称来自消息作者；定位仍使用主机、对话、消息 ID。

没有扩展严格的 v1 推送字段或枚举。历史 `title: TaroCub` 仅作为协议兼容字段保留，
新的两行 `body` 同时可供旧 Web/桌面/iOS 阅读。新 Android 校验该格式后分别显示标题
与正文，旧 Hub 继续使用通用提示；旧 APK 不识别新预览时也保留通用提示。
因此手机完整效果需要主机与 APK 都更新。
具体来说，新 Hub 搭配旧 APK 时，回复与文件会退回“收到新消息”，中断/部分完成可能
被旧 APK 显示为“任务遇到错误”；点击定位不受影响。下次发版必须提示同时更新主机
和安卓 APK。新 APK 的隐藏内容版本统一称“任务未完成”，不将用户停止说成错误。
`TaroCubUnifiedPushService` 同时传递事件种类和摘要，不再把两者丢弃；注册所绑定的
主机校验与撤销拦截仍先于通知展示执行。

此次按用户要求启用内容摘要，**配置的 FCM、APNs 或其他推送服务可以看到对话标题、
Bot 名及有限摘要或文件名**。不再声称内容完全不进入推送服务。Android 通知设置为
PRIVATE，提供不含标题和摘要的 publicVersion；系统设置决定锁屏是否显示私密内容。
原有前台抑制、免打扰、静默时段、去重、撤销检查及声音振动渠道保持原规则。

## CLI 影响

ADHD 是桌面呈现，没有新增 CLI 操作。摘要由共用 Hub 生成，因此无界面 CLI 主机
自动使用同一逻辑，不增加第二套实现或启动桌面依赖。下次发版须同步 App 内置主机
和独立 CLI 包；本变更不自行增加版本或发布安装包。

## 独立审查处理

Claude Opus 5.5（xhigh）在 CC1 独立只读审查，使用真实回复卡片、Java 格式校验、
旧 APK 兼容脚本和浏览器测量，报告 `opus-audit/review.md`。首轮未发现高严重度问题。
审查中已修复备用通道字段丢失、尖括号误删、目标/后台说明抢占摘要，并补齐精简
降级卡片的目标标识；新增原生测试覆盖备用通道、主机不匹配和撤销路径。

低优先级问题中，中断/超时/交付失败的重复状态、斜体/删除线/表格残留、桌面设置
误导文案已修正。最小降级卡片没有答案时保留“完整回复见下方消息”的真实提示。
旧 APK 兼容降级已在上文明确，不能通过改变严格 v1 字段强行绕过旧解析器。

极窄侧栏仍采用普通列表的省略策略：ADHD 的勾选框会占一部分标题宽度。这里保留
用户要求的 Bot 名称与共享列表规则，不另外提前隐藏 Bot；可拖宽查看标题。
“重新打开恢复默认宽度”按用户明确要求实现，不改成永久记忆宽度。

闭环复核进一步查出 Markdown 清理误改通配符/乘法/代码变量，以及分段清理导致
代码后的连接符、表格分隔消失。已用不与原文冲突的代码占位符、整段清理后恢复
实现，并补齐 9 个技术文字例子。Opus 在 `opus-audit/closure.md` 最终确认这些问题
全部修复，本轮审查没有遗留缺陷或阻断问题；极窄列表和旧 APK 行为按上述明确边界
处理。独立复核不替代实体手机送达与锁屏验收。
