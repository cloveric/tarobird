# 公网 VPS 中转调试验收 — 2026-10-02

在用户提供的 example-relay（Ubuntu 26.04 LTS，x86_64）完成了公网中转协议验收，
并修复了真实网络测试发现的两处连接生命周期问题。

## 部署与当前状态

- 公网端口：8443 用于客户端 TLS 透传，7443 用于主机主动建立的 mTLS 隧道。
- 健康接口只监听 `127.0.0.1:19877`。
- 独立服务：`tarocub-relay-debug`，配置位于 VPS 的
  `/opt/tarocub-relay-debug/relay.json`，单元位于
  `/etc/systemd/system/tarocub-relay-debug.service`。
- 使用独立、无登录权限的服务用户及 systemd 限制；运行时为官方 Node.js
  24.21.0，下载归档经过 SHA-256 校验。
- 腾讯云防火墙新增 TCP 7443、8443 两条规则，保留原有 22、80、ICMP 规则。
  没有修改现有 Nginx、网站、操作系统防火墙或生产 Bot。
- **验收结束后调试服务已停止，未开启开机自启。** 配置与程序保留，临时 Hub
  已关闭。现有 Nginx 仍为 active，网站的本机 HTTPS 检查返回 200。

这是与现有网站共存的手工隔离部署。没有执行会限制其他入站端口的专用 VPS
完整安装器，不能据此宣称该安装器已通过新机安装验收。

## 实际链路与结果

两个独立配对的 Node 协议客户端，经公网 `203.0.113.10:8443` 到 VPS，
再通过 `7443` 上的主动 mTLS 隧道到 Mac 上的隔离 Hub。
系统路由使用普通网络接口 `en1`，没有使用 SSH 转发或 Tailscale 数据路径。
SSH 仅用于部署、服务重启和状态读取。

1. 校验了客户端收到的 Hub TLS 证书及 Hub 身份签名。测试 CA 被明确作为受信 CA
   提供，证书验证始终开启，没有绕过浏览器证书警告。
2. 缺少客户端证书、同一 CA 下错误指纹、未知 SNI、未配对设备、未授权 HTTP
   请求和公开入口访问 worker API 均被拒绝。公网不发送 TLS 握手数据的连接在
  约 15.03 秒关闭。
3. 群组、话题内的消息在两个客户端间双向同步，合成 Bot 消息到达两端。
4. 上传 120 MiB 文件，分成 15 个 8 MiB 分块。前 4 块收到回执后，中断第 5 块；
   未完整的分块没有入账。重启 VPS 服务后，隧道约 0.82 秒重连，原 4 块、上传 ID
   和中断期间的消息都被保留，继续上传剩余分块成功。
5. 文件与随附文字组成同一条消息；重试相同消息 ID 不产生重复消息。
6. 修复下载收尾问题并重启 Hub、VPS 中转后，两个重新配对的客户端从同一持久化
   附件分别完整下载 **125,829,120 字节**。两端 SHA-256 都为：

   ```text
   33be979457d1e6e87f22f2ec79408602c958c555fb670fb300900124acdfa95f
   ```

   并行下载耗时分别约 424 秒、453 秒。这是本次有明显 TCP 重传的网络上的实测值，
   不是吞吐量承诺。最终版本还重新验证了新的 1 MiB 文件上传、文字附件合发、
   双向消息和设备撤销；撤销后附件请求返回 401。

上传中断恢复阶段使用的是先修复空闲超时的版本；下载及最后一轮鉴权、上传、
消息检查使用的是两处问题均修复后的版本。两个版本的精确 bundle SHA-256
均保存在机器可读回执，未把早期失败运行标为成功。

## 修复与回归

- **已认证连接空闲 15 秒被误关：** TCP 原始 socket 的握手超时在 TLS 握手后
  仍生效。改用 TLS 层的
  [`handshakeTimeout`](https://nodejs.org/api/tls.html#tlscreateserveroptions-secureconnectionlistener)，
  并在 TLS 客户端错误时关闭连接。回归同时检查未握手连接被清理、已建立连接
  空闲超过该期限仍能传输。
- **大文件下载尾部丢失：** 公网重复测试在 125,779,968 字节处断开，少了最后
  48 KiB。原先任一端 `close` 就销毁另一端，会丢弃慢速链路上排队的数据。
  `coupleSockets` 让正常 EOF 由 `pipe()` 排空并结束输出，异常中断仍销毁对端。
  主机隧道、VPS 数据通道和同机 TLS 转发采用相同行为。
- 增加慢速 16 MiB 响应测试，以及关闭发生时对端仍有待发送数据、双向异常中断的
  确定性回归。最终完整门禁：**219 个测试文件通过，3421 项通过，1 项跳过，
  构建成功，`git diff --check` 通过**。

## 验收边界

这是实际公网 VPS 与本机 Hub 的协议、传输和权限验收。两个客户端都在同一台 Mac
上运行，没有冒充 iOS/Android 真机、蜂窝网络或原生安装包验收。测试 Bot 为隔离的
合成 Bot，本次未运行生产模型、生产工作区或现有飞书/Telegram 实例。

目前是 TLS 透传：附件与会话持久化在主机，VPS 不保存附件缓存，主机需要在线。
上传支持断点续传；下载仍为整文件下载。测试使用短期私有 CA 证书，正式手机接入
还需要可信域名/证书及真机验收。第二台物理 VPS、完整新机安装器与 VPS 附件缓存
未在本轮验证。
