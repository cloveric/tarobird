# 设置 UI：Opus 5.5 两轮评审与实现

日期：2026-10-02。范围为设置、首次连接和配对入口；本轮没有部署服务器，也没有原生安装包验收。

## 评审来源与结论

实际调用 `claude-opus-5-5`，两轮均请求 `xhigh`，返回模型均为 `claude-opus-5-5`。评审使用本轮新截图和限定范围的源码，工具只允许 Read / Glob / Grep。

- [第一轮原文](settings-opus55-round1.md)：建议四类设置、移动端分类详情页、减少首次连接的拓扑负担、分离危险操作。
- [第二轮原文](settings-opus55-round2.md)：认可草稿保留方案；提出原生 dialog 强制关闭边界，以及需核实的本地清理和中转安全文案。
- 模型与验收记录（本地材料：`evidence/settings-opus55-review.json`）。评审是外部建议，不等于测试结论；具体处理见下表。

## 已落地

| 部分 | 结果 |
| --- | --- |
| 设置组织 | 通用、通知、连接、设备与安全。桌面双栏；390 px 手机为全屏分类列表进入详情，固定返回和关闭按钮。 |
| 通用 | 个人头像、语言、主题、字号；桌面端自启、快捷键和更新放在这里。头像同步、外观仅本设备的边界明确。 |
| 连接 | 聊天顶部连接状态可直接进入。当前实际线路和已保存配置单独显示；点击编辑后才能修改。 |
| 草稿 | 未保存标记；分类切换和返回列表保留草稿；取消恢复已保存值；关闭设置前应用内确认。保存期间禁止关闭和分类切换。 |
| 弹窗 | 原生 dialog 焦点约束，嵌套扫码/确认关闭返回原位置；onClose 处理强制关闭后 React 状态不同步。连续 Esc 已通过预览检查。 |
| 设备授权 | 本设备无撤销按钮；其他设备撤销前显示名称、平台和后果。空配对码不能提交，粘贴数字会规范化，批准后清空并反馈。 |
| 危险操作 | 单独放在设备与安全底部，使用应用内确认。清除本地数据与主机授权记录的区别明确。 |
| 首次连接 | 扫码或填写地址为主；连接选项和备用 VPS 折叠，默认不产生空白中转行。扫码显示摘要并可改为手填；主机身份校验保留。 |
| 说明 | 拓扑只显示一份摘要，长解释按需展开。纯中转保存前提示移除直连。内置中转透传 HTTPS 的边界经过源码核实；未声称中转缓存离线文件。 |
| 手机与通知 | 修复首次连接卡片网格横向溢出；通知独立页，修改任一勿扰时间或提交时更新时区。 |

没有采纳每次切分类都弹放弃确认：组件保持挂载，草稿不会因分类切换丢失。Opus 第二轮认可这一取舍。也没有按评审猜测修改中转行协议：受控输入未复现数据错位。

## 实际验证与边界

- 客户端翻译检查、TypeScript 和生产构建通过。
- 仓库完整测试/构建最终结果见机器记录；根测试不包含 `client/e2e`。
- 本轮在 Codex 内嵌浏览器实际执行：打开连接快捷入口、分类切换、390 px 布局、中英文切换、非法地址错误、取消恢复、保存反馈、草稿跨分类保留、关闭确认继续编辑、连续 Esc、嵌套扫码关闭和焦点返回。
- 既有浏览器回归脚本已适配分类和首次连接入口，并完成语法检查；本轮没有执行 Chromium/WebKit 自动化套件，不把前一轮结果冒充本轮结果。
- 不宣称完整无障碍合规或真机通过。iOS/Android 相机、Android 实体返回键和原生安全存储清理失败仍需原生验收。
- Opus 提醒的“断开重配多步清理可能中途失败”从现有代码可见失败边界，但本轮没有注入原生插件故障，也没有采用“忽略所有错误、一定删除身份”的建议，以免掩盖未清理的数据/凭据。应在后续原生可靠性验收中单独处理。
- 内置中转经 `src/relay/server.ts` 核实为 TLS 透传，不在中转解密 Hub 业务内容；第三方终止 TLS 的反向代理不属于这项保证。没有新增离线附件缓存、主机迁移或主机容灾功能。

## 后续可靠性验证

同日继续实现了可恢复的本地清理、缓存写入隔离和 Safari 弹窗焦点修复，补跑 Chromium 与 WebKit 各 17 项回归，全部通过。完整测试更新为 3,414 项通过、1 项跳过；详见 [设置回归与断开恢复验收](settings-reset-recovery.md)。此前“未执行浏览器套件”的说明仅描述初次 UI 评审阶段。原生插件真机验证仍未完成。
