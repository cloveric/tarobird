# Fox brand replacement — 2026-10-25

The owner selected the existing `pastel-fox` (橙尾狐) for TaroBot's product logo
and asked for a coordinated App/desktop/menu-bar/GitHub refresh with Opus 5.5
xhigh. The main sidebar should retain only the product name, so it no longer
needs a mascot change when the launcher artwork changes.

## Coverage

- A single recorded fox artwork produces desktop ICNS/ICO/window PNGs, iOS
  AppIcon, Android legacy/adaptive/themed launchers, favicon and touch icon.
- macOS menu-bar template and Android notification/themed glyphs use separate
  flat vector masks. The Mac status item uses the rounded cat follow-up below;
  Android retains the original full fox. Neither is a colour image painted black.
- Native iOS launch (2×/3×) and App welcome/pairing/loading/recovery use the fox.
  Android's actual launch theme references the verified adaptive launcher;
  unused legacy splash bitmaps are removed.
- `BrandName` replaces `BrandMark` only in the ordinary and ADHD sidebars; the
  latter also owns Agent Bus navigation. Independent brand scenes keep the fox.
  Themes, typography, responsive layout and personal Bot avatars are retained.
- English/Chinese README covers, product captures and demonstrations use the
  current text-only sidebar. Capture data is synthetic and isolated; historical
  design/audit evidence is not rewritten. The old TaroCub/Lark banner is replaced
  by the current TaroBot social image.

Pure visual change: no new CLI command, Host capability, schema, identity,
permissions or model/Agent Bus routing changes. The prior full-library default
avatar assignment remains separate and untouched. No versions are bumped and
no installed App or production Host is changed by this task.

## Review corrections

Opus independently inventoried the surfaces, implemented the sidebar separation
and refreshed README captures, then reviewed the icon pipeline and small sizes.
Root owns icon sources/generation/verification, native assets and social artwork.
The review corrected:

1. The first monochrome chin cutout read as a broad grin. The initial review
   narrowed it to a V-shaped separation. The owner's subsequent Mac-specific
   revision removes that cutout entirely, as recorded below.
2. Adaptive artwork was too close to the safety boundary. The final foreground
   fits the 66dp safe circle at all five densities; a pixel-based source check
   enforces this. Android themed glyphs also have a separate safe inset.
3. Isolated low-alpha pixels existed at raw image canvas edges. The raw edit is
   preserved as provenance; a reproducible SVG gutter excludes those pixels
   without rescaling or repainting the fox. Canvas edges are now fully clear.
4. The prior Windows transparency threshold encoded the slimmer taro shape.
   The wider fox uses a shape-appropriate minimum plus per-frame silhouette
   matching against the approved transparent master. Negative controls reject
   both padded macOS tiles and opaque iOS artwork. Alpha range, transparent
   corners, all six sizes and exact packaged EXE resource checks remain.
5. The old generator omitted the iOS launch mark and default desktop window
   PNGs. These and Android notification/themed variants are now covered by the
   manifest. The final review removed two unused Android splash resources and
   replaced their misleading parity check with actual activity/theme/launcher
   wiring checks. iOS now also has a 3× launch mark; Android notifications have
   a small internal margin without changing the system icon size.
6. The social banner's separator crossed the fox's chin; it now ends before
   the illustration. The selected identity, menu-bar mask and launcher safe
   areas were independently checked by Opus.
7. Old documentation capture scripts assumed obsolete pairing labels and
   could display the owner's machine name. Only disposable fixture/capture
   logic was corrected; the production flow was not modified to suit captures.

Opus completed the V3 review with no blocking findings. The final source check
passed all 83 resources. The remaining native/device acceptance boundaries are
listed below; optional non-Retina 16px ICNS detail tuning is not part of this change.
