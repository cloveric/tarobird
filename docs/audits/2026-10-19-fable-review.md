## 用户报告的拖文件问题

确认桌面原生拖放接管了事件，但前端没有接收该原生事件；原 HTML 接收区域也只限输入框。
现在关闭主窗口的原生拖放拦截，使用浏览器实际提供的 File 对象，将接收区域扩展至
当前对话主体。ADHD 按落点加入对应小窗口，不串入其他对话。拖入后显示草稿附件，
按“发送”才上传并提交任务；不会意外自动给 Bot 发消息。

Opus 提醒的旁路也一并修复：启动时安装全窗口文件防导航，覆盖欢迎/锁屏/侧栏；
不拦截事件传播，合法对话可接收。隐藏或 inert 对话框不挡住活动对话；目录按真实
entry 类型拒绝，零字节文件不会误判为目录（现有上传合同仍拒绝空文件）。
不增加任意本地路径读取 IPC。禁用状态使用现有提示区域说明原因。
另在 Tauri 原生导航回调拒绝 `file:`，防止仅携带文件 URL 的拖动把 App 主文档替换为本地文件。

原生验收边界：已搭建隔离的 macOS Cocoa/WKWebView 和本机测试 Hub，不接触生产状态。
测试源的系统 pasteboard 确认含真实文件 URL 与 NSFilenames 路径，但原生自动拖动在
独立简单控制页同样没有稳定产生 DOM 文件事件，结束位置还出现停在起点的情况。
最初 NSURL 夹具触发文件导航并不能证明 Finder 文件拖放失败；目前也不能据此宣称
Finder → 打包 App 的上传已经验收。产品 HTML 文件上传、ADHD 落点隔离已由 Chromium
及 WebKit 验证，完整原生路径仍待新打包 App 的专项验收。

## 为什么还看得到 Lark / Telegram

当前 App/CLI 的运行入口是 `index → host/hub → gateway → core`。standalone 构建
依赖图已检查 373 个模块，不导入 Lark/Telegram 实现或 Feishu SDK。

本轮清理了共享指令、技能索引、错误命令、陈旧项目状态和面向 App 的传输描述；
没有把产品流程继续指向旧车队。保留的名称分两类：真实可选适配器（独立构建、
独立测试）；已有身份/路由/回调/URL scheme/签名域的兼容值。后者直接替换会让
历史会话、配对或签名校验失效，不能按字符串批量删除。原报告也审到了可选适配器，
因此那些发现不代表 App 仍通过 Telegram 或 Lark 运行。

可选适配器实际修订还包括：上传重试接取消信号；超过一分钟的 Telegram retry_after
明确失败而不提前重试、不保留无限计时器；attachGateway 错误保留脱敏原因。
SDK 的旧消息过期窗口暂不扩大，以免恢复时执行很久以前的控制命令。

## 其他仓库修订与未盲改项

- 一次性 cron 在真正开始执行前原子持久化执行凭据并停用该次计划；崩溃恢复只对确认死亡的 owner 标记“结果未确认”，不自动重做副作用，保留显式重新启用。排队取消、写入失败与并发 scheduler 均有回归；不宣称外部副作用 exactly-once。
- Hub 操作日志增加 10 MiB 阈值、3 份尾部归档、30 秒检查的 copy-truncate 轮转，子进程继续写原 inode，CLI 可读归档尾部，备份不复制操作日志。检查间隔可能暂超阈值，拷贝到截断的短窗口可丢少量日志；它不是数据库审计账本。
- Windows APPDATA 必须是完整绝对路径，拒绝相对/盘符相对/仅根相对值，避免从工作目录生成另一份主机身份。实际 Windows Known Folder/UNC 权限仍需原生验收。
- CLI 帮助补 workspace、permission、pair wait；手动安装示例校验 SHA256SUMS，并明确普通 checksum 不等于发布者签名。版本与 schema 文档对齐现有 1.0.94 / 0.1.442 / 19，功能最小版本另行标注。
- 四处测试中的真实历史用户名改为合成示例；修正文档死链；已跟踪的脱敏 evidence 并非被 .gitignore 自动删除，不批量破坏引用。
- Scrapling 新安装使用产品目录并复用存在的旧安装；听悟文档区分 App 共享配置与可选旧实例，不迁移已有密钥文件或破坏旧会话身份。
- 根开发依赖更新 singlefile/picomatch 链；客户端 mammoth 仍有三条中等级传递告警，当前预览不调用该 CLI 参数解析路径，上游没有可用的修复版本。未接受扫描器建议的大幅降级，未称全仓依赖零告警。
- 可变 Actions tag、跨平台 pre-complete 门禁完善仍是供应链/工程待办；本轮独立执行真实本地检查，不把付费阻塞掩盖成测试成功。
- 用量账本长期 daily/monthly 保留和高频路线探测、通知去重记录、长期幂等收据、审计统计读取优化仍需带数据保留/通知/安全契约的设计，未按猜测删历史或拉长撤销窗口。
- 默认语言、全局快捷键、私有仓库 OAuth 范围、服务端 Bus 历史语言属于产品策略；当前行为与限制记录在分域表内，没有以“审计”名义改变用户已选择的能力。
- AGY goal argv 已在恢复审阅后通过真实原生对照及更新后的 adapter 验证，改用原生 text stdin；细节与持久化/跨版本边界见引擎审阅。浏览器预览的首次信任边界、同实例多活回合的更强能力隔离、跨引擎费用/缓存统计、真实 Windows/Android/iOS 验收仍未凭脚本测试宣称解决。
