## 表增长问题的具体边界

修复的是可丢弃缓存泄漏、运输正文保留和热路径扫描。不是把所有持久化记录设 TTL：

- 推送运输终态正文七天清理；紧凑回执仍随有效消息/设备增长，避免旧消息再次更新时重复提醒。
- IndexedDB 通知去重跟随主机缓存清理，不任意过期；历史快照替换后仍要识别已经通知的消息。
- Bot 请求编号、操作幂等收据保留，否则久后重试可能再次产生副作用。
- 新上传许可仅在从未使用且附件物理消失时清理；已使用及缺乏使用来源的旧许可不盲删。
- daily/monthly 用量是用户历史账本，不以优化名义删除；本轮释放的是已完成的内存写队尾。

这些数据不能称为“固定上限、不再增长”。长期硬上限需要同时定义历史保留、通知资格及
过期请求的拒绝协议。详情见 [后台读取合同](../client/adaptive-background-reads-2026-10-19.md)
和 [Hub 分域报告](2026-10-19-hub-review.md)。

## 真实进程与原生验收

- Node 子进程真实完成一次本地副作用后 SIGKILL；重启生产 CronScheduler 实现不重复执行，
  标记结果未确认，failureCount 不增加。活 owner 不被另一 scheduler 抢占，重复恢复不重复记账。
- 真实跨进程会话锁等待可取消，取消不杀活 owner；只有原 owner 被强杀后才回收锁。
  这不等于断电或外部副作用 exactly-once，也不替代 Windows 句柄/进程身份验收。
- 独立 10 万行审计查询实测约 1.05 秒，返回 50 行而统计总数完整；并发 30 次审计写入
  p50 2.63ms、p95 3.00ms、最大 3.23ms。采样 RSS 增量约 23.05MiB，非严格内存峰值。
  这是一次本机隔离实验，不是所有设备的性能承诺。
- 30 个合成设备完成真实签名握手和 600 次本机 WebSocket 心跳往返，同时运行十万行诊断读取；往返 p50 6.47ms、p95 17.22ms、最大 20.69ms。撤销一个设备后约 4.43ms 收到 4001 关闭，另一设备继续回应。这验证本机并发与即时撤销，不等于 30 台物理手机或公网移动网络。
- Mac 使用独立 bundle identifier 的真实 Tauri App、隔离 Hub 和合成文件完成：系统文件选择器
  → 草稿附件 → 发送 → 文件消息 → 原生 WebView 预览。49 字节文件与 Hub 落库内容逐字节一致。
  测试 App 的内置盘状态及两个系统钥匙串测试身份已清理，测试服务关闭，Finder 布局恢复。
  前端/原生基线包含此前拖放修复，搭配现有已安装的 host；未替换生产 App。
- Finder 跨窗口拖动在自动化输入阶段报 `windowNotFoundAtPosition`，未形成可判定的产品拖入
  结果。浏览器拖放及 ADHD 落点隔离不能替代它，**Finder → 打包 App 尚未验收通过**。
- macOS launchd 真实 writer 验证：外置 plist bootstrap 被系统拒绝，改用临时 16KiB 内置盘合成日志、4KiB 轮转阈值验证相同实现；轮转后文件只含 15 字节新标记、无 NUL、inode 未变，证明本机 launchd 标准输出在截断后继续追加。临时 job 已 bootout，临时目录已清理，结果留外置盘。此项不替代 Windows 被占用文件测试，也不抹去 copy-truncate 的极短丢日志窗口。
- AGY 原生 goal 输入验证另见 [引擎报告](2026-10-19-engines-review.md)。

## 复审与验证

本轮真实调用现有 Opus 5.5 / xhigh Bot，在单独协作对话中只读独立复核；其他分域代理
不冒称 Opus。独立初审、终审和最终增量复审均已返回；模型回执为
`claude-opus-5-5[1m]`，xhigh 来自调用配置。最终源码快照的结论为“无阻塞发现”，
不扩大为全项目无 bug。Opus 未运行仓库测试全集；它独立运行了 admission 失败、claim
写盘失败及 Gitleaks baseline 绕过复现，其余测试和原生收据由主审核对。

复审处理：admission 前重复触发、扫码 dropEffect、七天清理后推送去重、未使用上传许可
增长均已落实修订；最后又补 claim 写失败栅栏与旧 writer 的 SQL 消费触发器。
Gitleaks 绕过经主审再次复现并修复。`data:` 文档导航已拒绝。直接修改旧推送品牌常量、
无条件过期幂等记录等建议未采用，以免破坏现有客户端与请求重试合同。

最终源码的整合门禁通过：350 个默认测试文件、4,862 项通过、3 项跳过；
主机 standalone 374 模块不含可选旧传输/Feishu SDK；客户端生产构建通过；
Cargo 74 项通过，含两个 integration target 与真实 512MiB TLS 传输、证书轮换和 WebSocket
测试。先前完整执行 pre-complete 也已通过；后续增量分别重跑相关门禁，未把旧测试数字
当成最终源码结果。隐私脚本 3 项回归、身份检查与完整历史扫描通过。

最终增量的分域检查：Hub 许可及邻接 6 文件 114 项；引擎/调度/状态 11 文件 192 项；
可选适配器 legacy 57 文件 1,231 项。客户端 focused 45 项、预览单测 6 项、生产构建；
首轮 Chromium/WebKit 各 11 项，增量 Chromium 19 项、WebKit 18 项通过（1 个 Chromium
专用摄像头用例跳过），附件/ADHD 落点两浏览器各 1 项通过。Rust 完整 74 项通过，
随后仅 `data:` 拒绝增量重跑导航 3 项通过。隐私回归 3 项通过，包含 baseline 先红后绿。
数字有重复覆盖，不累加作总数。

## 仍受条件或协议约束的项目

- Finder 实际拖入、真实 Windows/Android/iOS 设备与移动网络/省电策略验收，没有冒称完成。
- 既有空闲回切仍依赖 HTTP 健康探测；HTTP 健康但 WebSocket 持续失败时，可能周期性尝试首选再返回备用。本轮未引入或消除该体验边界，不能将多 VPS 失败切换回归扩大为长期无抖动保证。
- 无 provider/schema 的旧跨引擎 cache 口径不能无损改写；未上报美元费用的引擎不能伪造账单预算。
- 用户历史归档、过期请求协议、默认语言/快捷键/OAuth 范围等产品策略，没有借审计改变。
- 首轮已确认的 optional transport/兼容身份边界继续保留；standalone 依赖图仍须验证不含旧传输。
- 线上 GitHub Actions 受费用条件限制，不计为通过；本轮本地检查单独记录。
